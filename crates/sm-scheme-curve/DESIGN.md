# sm-scheme-curve: design

Five curve schemes for the `sm-scheme-api` contract: `equal`, `bias`, `dualbias`, `stretch`, `curvature`.

## Positioning

Similar to **Cubit's curve schemes** (equal, bias, dualbias, stretch, curvature) and to **Gmsh's transfinite progressions** (`Progression`, `Bump`), it places edge nodes by a one-dimensional spacing law along arc length. It differs in where the law lives: the schemes work in **normalized arc length** and convert to **curve-parameter fractions** with an adaptive Gauss-Legendre arc-length map and a monotone safeguarded-Newton inverse, so every law is exact on lines, circles, ellipses and NURBS alike, and node keys, positions and parameters stay with the driver (`GenCtx::curve_patch`). That gives analytic closure (consecutive-edge ratio, first size, mirror symmetry) to 1e-12 on analytic curves (1e-9 on NURBS, up to the parameter-ulp limit noted below), bit-identical output for any thread count, and typed errors (never a silent relaxation) when sizes cannot be honoured.

## Layers

| Module | Role |
|---|---|
| `spacing` | Pure math in arc-length fractions: geometric series, ratio/first-size solving, count derivation, dual series, stretch profile. No geometry. |
| `arc` (private) | `ArcMap`: arc length as a function of the edge fraction. |
| `engine` | `Spec` + `node_params(curve, carrier, n, spec)`: arc fractions to parameter fractions; curvature density. |
| `params` | Typed serde structs carried in `SchemeChoice::params`. |
| `schemes` | `CurveScheme` (one `Scheme` implementation parametrized by `CurveKind`), `register`. |

## Arc-length map

`g(tau) = |C'(t(tau))| * |hi - lo|` with `t(tau)` from `geom::edge_param`, so edge sense is handled once. The initial panels are the 64-panel uniform grid merged with the curve's `ParametricCurve::breakpoints()` (interior knots, polyline vertices; repeated per period for an edge spanning a periodic seam), so every smooth piece is integrated on its own, however short. Panels are integrated with 5-point Gauss-Legendre and refined locally. A panel is accepted only if (1) its estimate matches the sum over its two halves within 1e-14 times the initial length, (2) it matches a 5-point Gauss-Lobatto estimate (which samples both panel endpoints, so a kink in the outer ~5% of a panel that no Gauss-Legendre node sees is caught) within 1e-13 times that length, and (3) the chord `|C(b) - C(a)|` does not exceed the panel's arc length (a geometric lower bound that exposes a hidden short span with real displacement). Refinement is depth-first in a fixed order. The Lobatto endpoint nodes are shifted inward by 8 parameter ulps, so a speed jump exactly at a panel end (a seeded breakpoint) is not read as unresolved, and the chord test allows for the rounding of the endpoint parameters (parameter ulp times local speed). **Known limitation:** a non-smooth point that the curve does not report as a breakpoint is found only by the adaptive refinement (a kink that is hidden from all nodes and adds negligible displacement can be missed), and a node cannot be placed finer than one ulp of the curve parameter, which is `eps * max speed` of arc length (about 3e-9 absolute for a 1e-7 knot span with O(1) displacement). Accuracy on NURBS is tested against a per-knot-span reference (tests/nurbs.rs: non-dyadic double knots, a degree-1 polyline, spans of width 0.002, an end span at 0.002, spans of 1e-6 near 20/64 and near the far end, double and triple knots at a short span, and seeded 200-curve and 300-curve (shifted ranges) probes with spans down to 1e-7). A panel `[a, b]` with `b - a <= 4 eps max(|a|, |b|, 1)` is accepted as it is. Evaluator noise: spline basis evaluation divides parameter differences that carry an absolute error `eps * max(|lo|, |hi|)`, so inside a smooth piece of parameter width `w` the speed has relative noise about `eps * max(|lo|, |hi|) / w` (1e-7 for a 1.6e-7 span at t ~ 100). Each panel knows the width of its smooth piece (between breakpoints) and the whole-vs-halves, Lobatto and chord tests get a floor of 16 times that relative noise (times the panel integral, or the endpoint positions for the chord), so a valid curve whose parameter range is far from 0 is never refused for noise it cannot remove. The panel budget is 2^16 plus four per seed panel (a dense knot vector is fine); exceeding it is a `Geometry` error, as is a curve with more than 2^20 seeds (an edge spanning an absurd number of periods). For a periodic curve the seam is seeded too. A seeded 300-curve probe (offsets 0, 3, 100, -7.5; scales 0.5-10; some rational; some sub-range edges; both senses) and an explicit quadratic repro at offsets 0, 100, -7.5, 1000 cover this. Equality is tested to 1e-9 relative plus the parameter-ulp allowance above (see W2_REPORT). Cumulative lengths and the (non-uniform) breakpoints give the inverse: binary search for the panel, then bracketed Newton on `integral(lo, tau) = target` inside it (derivative `g`, bisection fallback). If the speed spread over all quadrature nodes is below 1e-13 relative the parametrization is arc-length proportional (line, circle) and the map is the identity, which makes equal spacing on a line exact to rounding. Node inversions run under rayon above a fixed size threshold; each element is independent and the panel refinement is sequential, so output is bit-identical for any thread count.

## Spacing laws (binding decisions from `docs/research/cubit-meshing-semantics.md`)

- **Bias** (`e_{k+1} = r e_k`). Nodes `s_k = (r^k - 1)/(r^n - 1)`, evaluated with `exp_m1` and scaled exponentials (no cancellation near `r = 1`, no overflow). First size to ratio: monotone root of `ln(s_1(lambda)) = ln(a/L)` in `lambda = ln r` by bracketed Newton (finite-difference slope, bisection when the step leaves the bracket). Count from `(L, a, r)`: real count rounded half-to-even, minimum 1. Count from fine and coarse sizes: the series sum grows with the count, so a doubling search then bisection finds the integer minimizing `|sum - L|` (the Ours text iterates `n -> r -> n`, which is a fixed point at every `n`).
- **Dualbias.** Even `n = 2m`: `m` edges per half. Odd `n = 2m+1`: middle edge `a r^m`. Nodes are built from the half-series cumulative sum and mirrored (`1 - s`), so symmetry is exact. `first_size` solved the same way as bias.
- **Stretch.** First size only: bias with that first size. First and last: end edges pinned, interior linear between them and scaled to close the length (n >= 3). The ratio of consecutive edges is checked against `max_ratio` (default 2); a spacing that needs more is a typed `RatioLimit` error. The count is derived softly as `round(2L/(first+last))`.
- **Curvature.** Density `rho = (1 + |c| L k)^sign(c)`; `max(64 n, 512)` samples at equal **arc-length** fractions (positions from the arc map), trapezoid cumulative integral of `rho` over arc length, linear inversion to arc fractions, then the arc map. Constant curvature gives equal spacing on any parametrization (to rounding). Zero speed or non-finite curvature at a sample is a `Geometry` error. `|c| L kmax > 1e6` is an error. Closed (periodic) edges are refused for stretch and curvature.

## Interval counts

Schemes that imply a count (bias with `{first_size, last_size}` or `{ratio, first_size}`, stretch with `last_size`) emit a **soft** `Fixed` constraint from `interval_constraints`. A hard count on the edge wins; otherwise the solver sees it as a preference. All other modes take the plan's count.

## Failures

`applicability` rejects bad parameters with a reason (`NotApplicable`). `generate` maps `SpacingError` to `FailureKind`: parameter problems `NotApplicable`, unreachable sizes or ratio limits `Constraint`, geometry problems `Geometry`; none is `Internal`, so the driver may fall back. Nothing panics on user input.

## Determinism

All functions are pure. Parallel loops are per-element maps collected in index order followed by sequential sums. Tests compare bit patterns at 1 and N threads and across concurrent calls (`sm_testkit::determinism::check_f64_bits`).
