# sm-py design (W3b-PY, Q7)

Package `smartmesh` (distribution `smartmesh`, native module `smartmesh._native`), Python >= 3.10
abi3, numpy >= 1.23 and < 3 as the only run-time dependency, not published on PyPI.

## Layers

| Layer | Where | What |
|---|---|---|
| `core` | `src/core.rs` | `Host` = `Mutex<Server>` driven through JSON-RPC text; `MeshTables` snapshot. No PyO3 types, tested by `cargo test`. |
| `errors` | `src/errors.rs` | JSON-RPC code (and `script-error` kind) to Python class name; the code constants are `sm-protocol`'s. |
| `py` | `src/py.rs` (feature `python`) | The `smartmesh._native` module: `Host`, id parsing, `error_class`, `protocol_codes`. |
| typed API | `python/smartmesh/*.py` | `Session` over a `Transport` (`request(method, params)`), results, ids, `Mesh`, `smsh`. Pure Python. |
| stubs | `python/smartmesh/ops.pyi` | Generated by `tools/gen_stubs.py` from the live catalog. |

The native in-process transport is one `Transport`; a WebSocket client (`smesh serve --ws`) would
be a second one with no change to the typed layer.

## Rulings

1. **Sync, thread-safe.** `Host::call` takes the mutex; every native entry point releases the GIL
   (`Python::detach`) before waiting on it, so concurrent callers serialize on the lock and do not
   block other Python threads. There is no async API: use `asyncio.to_thread`. Every entry runs
   through `run()`, which wraps `catch_unwind`: a panic becomes `InternalError`, never PyO3's
   `PanicException` (a `BaseException`). A panic while the lock is held poisons it; later calls on
   that session raise `InternalError("... poisoned ...")` (the session state is no longer
   trusted); other sessions are unaffected. A panic outside the lock leaves the session usable.
2. **Thin typed layer over the JSON protocol.** Ops go through `Request::Apply`, so Python, the CLI
   and MCP share one code path and one state hash. `Host::call` builds the same JSON-RPC text as
   `InProcess` and goes through `Endpoint::handle_text`, so errors and hashes match remote clients.
3. **Cubit parity plus typed ops.** `Session.cmd(text)` runs command-language text (`script.run`);
   typed ops are `s.apply("model.create_brick", x=...)` and the generated
   `s.model.create_brick(x=...)`, `s.ops.<family>.<op>(...)`. Queries: `s.query(name, ...)` and
   `s.q.<family>.<query>(...)`. Positional-argument ops are keyword-only in Python.
4. **No zero-copy views of the live store.** `Session.mesh()` copies each table once (a `Vec` that
   numpy adopts: `OWNDATA`), marks it read-only, and never aliases the store, so later ops cannot
   change an earlier `Mesh` (snapshot semantics). The zero-copy path is the file:
   `smartmesh.smsh.open(path)` maps a `.smsh` and returns read-only `numpy.frombuffer` views.
   Borrowing the store's memory would need hand-written `unsafe` and is not done.

## `unsafe`

The crate has `#![deny(unsafe_code)]` and no hand-written `unsafe`. The PyO3 macros expand to FFI
glue that the lint rejects, so `src/py.rs` has one declarative `#[pymodule] mod _native` with one
`#[allow(unsafe_code)]` on it (CLAUDE.md, ddc2122). `tests/host.rs` scans the source for any
`unsafe` token (block, fn, impl, trait, extern) and for the one-allow rule.

## Tables

`MeshTables` holds the always-present arrays of `SMSH_FORMAT.md` 3.1 under the file's names and
dtypes (`x,y,z`, `*_ids`, `face_*`, `cell_*`, `class_entities`, `*_class`). Edges, sets, tags,
high-order and parametric tables are Stretch. A table equals the same-named `.smsh` array byte for
byte (little-endian host); `tests/host.rs` compares them with `sm-meshio`'s writer output for every
testkit fixture and a mesh with an edge table (the writer folds edge classifications into
`class_entities`, so `class_columns` does too), and `tests/test_mesh.py` compares a real export.
The cell shape codes are the `.smsh` writer's (`CellShape::code`).

`Mesh` wraps the tables as read-only attributes with helpers: `points`, `cells()` (meshio-style
blocks; polyhedra give indices only), `cell_faces_split()`, `class_entity_ids(kind)`,
`Mesh.from_smsh(path)`.

## Errors

| Class | Code | Notes |
|---|---|---|
| `ParseError` | -32700 | |
| `InvalidRequestError` | -32600 | |
| `MethodNotFoundError` (`LookupError`) | -32601 | |
| `InvalidParamsError` (`ValueError`) | -32602 | also raised by Python-side validation |
| `InternalError` | -32603 | caught panics, poisoned lock |
| `ApplicationError` | -32000 | `.kind` is the op's contract code (`no-mesh`, `unknown-op`, ...) |
| `ScriptError(ApplicationError)` | -32000, kind `script-error` | `.result`, `.rendered`, `.error_code` |

`.kind` is passed through untouched. The class is chosen by the Rust side (`error_class`), the
codes are read from `sm-protocol` (`protocol_codes`); Python holds no table of its own.

Python-side validation (`prepare_params`) uses the catalog schema before any call: unknown
keyword (with a did-you-mean), missing required keyword, non-finite float, unparsable id,
wrong-kind id (`x-entity-kind`). A rejected call never adds a timeline node.

## Generated stubs

`tools/gen_stubs.py` reads the live catalog and writes `ops.pyi`: one keyword-only signature per
op (`Literal` for enums, `EntityId | str` for entity-kind parameters, `Sequence[...]` for lists,
output roles in the docstring) and one `Ops`/`Queries` aggregate. At run time the same names are
resolved lazily from the catalog, so ops added by any plugin work without touching this crate;
only the stub (a golden) is regenerated. `tests/test_ids_typing.py` fails when regeneration
differs. `mypy --strict` accepts `tests/typing_example.py` and rejects a misspelled keyword or op.

## GIL and fork

Native calls release the GIL while they run and while they wait for the lock. A rayon pool created
before `os.fork` is dead in the child: use `multiprocessing.get_context("spawn")` (smoke-tested).

## Packaging

`pyproject.toml` (maturin, mixed layout, `python-source = "python"`, features `["python"]`,
abi3). `cargo build/test/clippy` at the workspace root never needs Python (the `python` feature is
off). `ci/py.sh` does the Python side; per-platform wheels are a CI matrix over
`maturin build --release --features python` and are not built locally.

## Recorded, not gated: table snapshot on 10^6 hexes

`bench/tables.py 100` (release build, this machine, record only):

```
cells=1000000 vertices=1030301 faces=3030000
mesh_s=51.273 snapshot_s=0.8095 bytes_copied=263441076 smsh_export_s=10.022 smsh_open_s=0.04363
```

The snapshot copies 263 MB (22 tables) in about 0.8 s on a loaded shared machine (Apple silicon,
release build); `smsh.open` maps the same data in 44 ms because it copies nothing. This is
the cost of the no-borrowed-views ruling; the file path is the zero-copy route. Not a gate.
