# sm-scheme-ogrid

The O-grid surface scheme (W4 tasks HEX-OGRID, HEX-OGRID-K; see drafts/hexpin.md D1): a self-contained kernel with ogrid and polar modes on a disk, an annulus with a 4-sided loop, and a two-circle ring. It does not depend on `sm-decomp`. It is registered in `sm_server::standard_schemes`; `register` adds the `ogrid` scheme (HEX-OGRID-S, below). No auto list names it yet (W4-MESHER-LISTS), so use an explicit `mesh.scheme`.

## HEX-OGRID-K kernels (done)

Pure functions returning a `PlanarMesh` (nodes, CCW quads, polygons): `ogrid_disk` (central `a x b` block plus four collar blocks of `k` layers, corners at circle nodes `0, a, a+b, 2a+b`, central corners at `core` x the circle radius, optional Jacobi smoothing), `ogrid_annulus_quad` (four trapezoid blocks, square corners at 45 degrees + 90 degrees x e), (it returns `OgridError::Inverted` when unequal side counts twist the radial lines, i.e. any scaled Jacobian <= 0 or a non-finite node; balanced sides with `phase = 45 (mod 360)`, `ratio` in `1e-6..=1e6`, `|phase| <= 3600` and the circle strictly inside the square never fail; outside those ranges the inputs are rejected with `Param`, and other phases twist the radial lines and may return `Inverted`; `ogrid_disk`, `ring` and `polar_disk` run the same finite-node and Jacobian post-check), `ring` (periodic `n x k`) and `polar_disk` (central n-gon, `k` rings). Conventions: circle node `j` is at `phase + 360 j / n` degrees (for the disk, ring and polar kernels the caller picks a phase that is a multiple of `360 / n` to match a seam-aligned edge mesh; the annulus is safe only at phase 45, which needs `n = 4 mm` with equal sides `mm`, and 45 is a multiple of `360 / n` only when `n % 8 == 0`, so an annulus seam elsewhere needs a different square-side split or accepts `Inverted`); `ratio` is the outermost over innermost layer thickness (geometric); smoothing relaxes the grading, so use it only with `ratio == 1`. Node orders are documented on each function. `collar` is deferred.

## HEX-OGRID-S adapter (done)

`ogrid` (surface, score 70) in `src/scheme.rs`, recognition in `src/fit.rs`. Params (unknown keys rejected): `mode` (`"ogrid"` default, `"polar"`), `rings`, `ratio` (1e-6..1e6), `phase` (degrees, face frame: the global x axis projected on the face plane; first block corner of a disk, default 45; ignored on annuli). Caps: `QUAD | STRUCTURED | BLOCK_STRUCTURED` (ogrid), `QUAD | POLY` (polar). Applicable only to exact planar faces (tolerance 1e-9): a disk (one circular loop, any number of arcs), a circle in a centred square of four straight edges, and two concentric circles. `polar` has no square annulus. Intervals: `EvenSum` and `>= 4` on the disk circle (polar: `>= 3`), one `Linear Eq` row `n = m1 + m2 + m3 + m4` on the square annulus, `n_out = n_in` on the ring. Generation takes the boundary nodes from the earlier waves, checks that they are equally spaced (circle, in angle) and sit where the kernel puts them (1e-7 relative; else a `Quality` failure and the next scheme is tried), picks the circle node nearest the requested corner as kernel node 0 (annulus: nearest the square's first corner, which skews the radial lines by at most half a circle step), and emits the kernel mesh with the new nodes owned by the face (`Param::Surface`). The default `rings` follow the circle spacing. Tests: `tests/adapter.rs` runs the scheme through the server on a cylinder, the pin cell, the 3x3 lattice and a tube (volume `h (n/2) r^2 sin(2 pi / n)` to 1e-12, 0 validate violations).
