# EXPORT-OPTS: split_warped_faces through session.export (R11), Python Session.export options, visible export warning for the smrt region-name fallback (R10)

> Planning draft (W3c), corrected by the planning critique. Changes against the original draft are marked **Critique delta**. `docs/design/w3c/plan.md` wins over this file.

Depends: ACR-EXP1 and ACR-EXP2 merged on main (orchestrator, same commit) before A, B and C branch; worker A before the Python end-to-end tests of C (they need the server to emit the warning); none of the W3c items; no dependency on AUTO, CSG importers or the DAGMC benchmark.

## Goal
Three user-visible gaps in `session.export`, all small, all closed through the one protocol request:
1. **R11.** OpenFOAM `split_warped_faces` (library-only since W3b FOAM-WARP) becomes a `session.export` option, default off, like P5's `split_small_determinant`.
2. **Python.** `Session.export` can pass the per-format options (`graveyard`, `binary`, `polyhedra`) and the FOAM switches. The wheel row of the W3b milestone only compared default exports because of this (w3b-report D7, backlog "From W3b-INT acceptance").
3. **R10.** The `.smrt` fallback to volume-id region names is a visible warning in CLI stderr, CLI `--json`, the MCP result and Python. A fully blocked model exports with no note at all.

## Owner
Mixed, so split by crate. The orchestrator owns the two sm-protocol ACRs. Workers: A = `crates/sm-fem` and `crates/sm-server`; B = `crates/sm-cli` and `crates/sm-mcp`; C = `crates/sm-py`. A, B and C start from the ACR commit and are independent except that C's end-to-end warning test needs A.

**Critique delta.** Worker A also takes the `smrt_regions` duplicate-name test and invariant comment (from `drafts/cleanup.md` T1 item 3), since A rewrites that function. CLEANUP T1 item 4 (CLI/MCP note printing) is dropped there: workers B and A own it here.

## Findings (what is true today)

**R11 path**
- `FoamOptions::split_warped_faces` (default false) and `warp_tolerance` exist: `crates/sm-meshio/src/foam/mod.rs:243,317`, applied at `foam/build.rs:458`. It emits loss item `foam.warped_faces_split` (Degraded). `FOAM_FORMAT.md` section 12 records that the split turns checkMesh-clean warped hex meshes into failing ones (concave cells), which is why it is off by default.
- sm-fem never sets it: `crates/sm-fem/src/export.rs:50-117` (`ExportRequest` has only `split_small_determinant`, `empty_patches`, `wedge_patches`) and `export_files` at `export.rs:302-323` builds `FoamOptions` from those three only. `ExportRequest` is `#[non_exhaustive]`, so a new field is additive there.
- Protocol: `Request::Export` in `crates/sm-protocol/src/request.rs:214-244` has `split_small_determinant: Option<bool>` (line 237), `empty_patches`, `wedge_patches`. A new field on a struct variant breaks every construction and every exhaustive pattern. The P5 ACR had the same cost. Sites to touch mechanically (`split_warped_faces: false`): `crates/sm-server/src/server.rs:254` (pattern), `crates/sm-cli/src/lib.rs:636`, `crates/sm-server/tests/session.rs` (about 14 literals), `crates/sm-server/tests/export_wire.rs:60,207`, `crates/sm-server/tests/w3_wiring.rs` (`export` helper at line 44 and the P5 test around 355), `crates/sm-cli/tests/milestone_w3a.rs:190`, `crates/sm-cli/tests/commands.rs:641-690` (patterns; check for missing `..`), `crates/sm-protocol/tests/wire.rs` (5 sites). Tests that already use `..` (mcp.rs:581, mcp common) are unaffected.
- Server: `crates/sm-server/src/host.rs:49` (`ExportParams`), `host.rs:206-211` (the "foam only" guard, whose message lists the three P5 fields), `host.rs:235` (copies into `ExportRequest`), `server.rs:254-266` (copies request to params).
- `warp_tolerance` is not exposed anywhere above the library and R11 does not ask for it.

**Python path**
- `Session.export` is hand-written Python, `crates/sm-py/python/smartmesh/session.py:455-476`: only `format, mesh, provenance, inline`. No `options`, no FOAM fields. It sends JSON through `Transport.request("session.export", params)`, so no Rust change in sm-py is needed; the server already validates per-format options (`crates/sm-server/src/mesh_export.rs:39-94`: `gmsh {binary, polyhedra}`, `dagmc {graveyard}`).
- `ExportResult.notes` already parses notes (`python/smartmesh/results.py:193-229`) but has no severity.
- **Stub finding.** `ops.pyi` is generated from the op and query catalog (`crates/sm-py/tools/gen_stubs.py`, `DESIGN.md` "Generated stubs"). `Session.export` is not an op, so it is not in `ops.pyi` (the only `export` there is `model.export`, line 254). This task adds no op or query, so `ops.pyi` does not change, and `gen_stubs.py --check` (ci/py.sh:29) and `tests/test_ids_typing.py:73` must stay green without regeneration. `Session.export` is typed by its own signature and `mypy --strict` (ci/py.sh) checks it.

**R10 path**
- The fallback is `smrt_regions` in `crates/sm-server/src/mesh_export.rs:183-205`. It returns the string `smrt-region-names: regions are named by volume id (<why>)` in three cases: block lowering failed, the model has no blocks, or `covered != total` cells (some volume is in no block). The covering test counts cells in block sets, so "fully blocked" is exactly `covered == total`.
- Every exporter note travels as a plain `ExportNote { code, count, detail }` (`crates/sm-protocol/src/result.rs:105-128`), with `ExportNote::parse` of a `code: detail xN` string (host.rs:525). There is no severity. `LossSeverity` exists in sm-meshio but is dropped by `notes_of` (sm-fem `export.rs:155`, sm-server `mesh_export.rs:33`).
- Surfaces today:
  - **Protocol/JSON:** `ExportResult.notes` is serialised when non-empty, so `smesh export --json` and the MCP `structuredContent` already contain the note, as one entry among others, not flagged as a warning.
  - **CLI text:** `render::export` (`crates/sm-cli/src/render.rs`, fn `export`, about line 133) **ignores `r.notes` entirely**. Only `render::record` prints `note:` lines to stderr. So a text-mode user never sees any export note today (the backlog item "Export notes in smesh export --json" only covered JSON).
  - **MCP:** `tool_result` (`crates/sm-mcp/src/server.rs:309-323`) puts the whole JSON in one text block and leads with `summary` only when the result has one. Export has none.
  - **Python:** `ExportResult.notes` is data only.
- **MCP schema is stale (new finding, needed for R10 and R11 over MCP).** `Fixed::SessionExport` input schema (`crates/sm-mcp/src/tools.rs:210-222`) lists `format` as `smsh|vtu|exodus|openfoam` and has no `options`, `split_small_determinant`, `empty_patches`, `wedge_patches`, with `additionalProperties: false`. The server accepts `dagmc`, `gmsh`, `smrt` (the protocol parser does), but an MCP client that validates against the published schema cannot ask for them, so the R10 warning can never reach an MCP user through the tool as advertised. The description (tools.rs:143-148) also says "Formats: smsh, vtu, exodus, openfoam". Tests pinning it: `crates/sm-mcp/tests/mcp.rs:623` (property list) and `mcp.rs:744` (`export_schema_lists_four_formats`).
- Test today: `export_wire.rs:418` asserts the note exists for the no-blocks case only; nothing asserts the clean case has no note.

## Risks
- **Mechanical breakage across crates** from the new struct-variant field (about 25 literals). Mitigation: the orchestrator commits the ACR with all literals fixed, as for P5.
- **Warp fixture may have no warped faces.** The dual of a tet mesh of a brick could be planar enough. Acceptance 3 makes this a checked precondition and names the fallback (a curved map-meshed volume).
- **stderr output on text export is new behaviour** for notes that already existed (the OpenFOAM `foam.small_det_split` note is now printed). It is correct per the backlog and harmless for pipes, but any script that treats stderr as failure would notice. Printing only warnings in text mode is the narrower alternative.
- **Python `-W error`.** `tests/wheel_check.py` runs with `-W error`; an `ExportWarning` would fail it if the wheel row ever exports a model with volumes outside blocks. The milestone model is fully blocked, so no warning, and acceptance 8(d) pins it.
- **MCP golden regeneration** touches a pinned file; the allowed change is limited to the `session_export` entry and must be reviewed as a diff, not blindly blessed.
- **Count semantics.** The fallback note has count 1 (one model-level event), not a cell count; the cells in no block are in the detail text. Cheap to change if the user prefers a number.
