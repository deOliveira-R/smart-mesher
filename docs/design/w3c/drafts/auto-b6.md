## Findings (root cause confirmed by a prototype, not committed)

1. The notes say "respect triangle faces imposed by a neighbour". That is not the cause. The planner already sees both impositions on the shared face. I printed the needs at the failure: Volume#1 (hard `tetmesh`) imposes `Caps(TRI)` with firmness Hard; Volume#2 (auto `map`, `Selection::Auto{100}`) imposes `Caps(QUAD)` with firmness Hard and `Origin::Scheme`. No face scheme satisfies both, so the planner returns `NoApplicableScheme` with `imposed_by = [(Volume#2, map)]`, which is exactly the right thing to blame (`planner.rs` `blameable_imposers`, ~1550; `SchemeError::blame`, `sm-scheme-api/src/error.rs:350`).
   - **Critique delta:** `blameable_imposers` sorts by target, so `blame()` takes the lowest target id. Here that is the right imposer, but not in general: in the enclosed round pin (face 9 imposed by the cylinder's `sweep` and the moderator's `tetmesh`) the lowest id may be the wrong one. The loop must iterate `imposed_by` (see Scope).
2. The blame is never used, because the failure happens in the first `Driver::plan`. `scratch_plan` calls `driver.plan(&mi, intent)?` once (`crates/sm-mesher/src/auto.rs:189`; critique confirms `auto.rs:188`). Only `mesh_from_plan` (`auto.rs:205`) has the replan loop (`Driver::mesh_loop`, `sm-scheme-api/src/driver.rs`, around line 740), and it runs only on a plan that already succeeded. A plan-time error with a blame therefore returns straight out of `mesh.auto`. So the pinned test `b6_auto_next_to_a_hard_tet_neighbour_pinned_outcome` (`sm-server/tests/auto_select.rs:285-305`) fails for a reason that is entirely inside `sm-mesher`. No ACR is needed.
3. Prototype: in `scratch_plan`, replace `driver.plan` with a loop over the public `driver.plan_with(&mi, intent, &rej)`. On `Err(e)` with `e.blame() = Some((t, s))`, `s != copy`, not already rejected and within `driver.options.max_replans`, insert `Attempt::new(t, s, Phase::Resolve, FailureKind::NotApplicable, e.to_string())` into the `Rejections` and plan again. Otherwise return `e`. Result on `TWO_BRICKS_HARD_TET`: `mesh.auto` then `mesh.run` succeeds, volume 16.0 exactly, validator empty, cells `{"Tet":160,"Wedge":32}`.
4. The right volume does not end up as `tetmesh`. After `map` is rejected, `sweep` (score 60) beats `tetmesh` (10). The shared face becomes the sweep source, is meshed with triangles (imposed from the tet neighbour), and the volume is wedges, conformal to the tets. That mesh is valid and arguably better than an all-tet fill. It differs from plan.md acceptance B6 ("ends as `tetmesh`") and from the notes ("so the tet fallback is reached"). See Question 1.
5. Census: `census.rs:182` and `:207` call `scratch_plan`, so the census inherits the fix. Every repo script that fails at plan time with a blame and now succeeds shows as error to success. Nothing that succeeds today is affected, because the loop only runs after an `Err`.
6. `mesh.run` has the same plan-then-no-replan shape (`mesh_ops.rs:337`; `plan_query.rs:817` for `mesh.plan`). I leave both alone: they use the registry's strict lists (`standard_schemes`, `standard.rs:42-53`: `[map]`), so a replan could only change one error into another, and a change there is not hash-neutral in error text. Out of scope; noted in the report. **Critique delta:** confirmed as the plan's decision (replan in `scratch_plan` only).
7. B3 second half and B4 hex-only: both existing end-to-end tests (`b3_...` at `auto_select.rs:215`, `b4_...` at `:231`) cover only the default lists. The planner's `AutoPolicy` is read from `intent.defaults.auto` (`planner.rs` ~1410), which `DefaultStrategy::choose` overwrites from its own `lists` (`auto.rs:281-283`). `StrategyRegistry::default()` (`auto.rs:~344`) inserts only `DefaultStrategy::default()`, and `standard()` (`sm-server/src/standard.rs:182-191`) never adds another, so no list other than `default`'s is reachable through `mesh.auto`.

## Scope

All in `crates/sm-mesher/src/auto.rs` unless noted.

- **B6:** new `pub(crate) fn plan_with_blame(driver, input, intent, budget) -> Result<(Plan, Vec<Attempt>), SchemeError>` containing the loop of finding 3. `scratch_plan` calls it. The plan-time rejections go into the returned attempts, and `mesh_from_plan` receives them through `plan.rejections` (the planner stores `rej` in the plan, `planner.rs:455`). Both phases draw from one budget: `max_replans` minus the plan-time rejections used. The `mesh.auto_tet` reasons already read `attempts`, so the text includes "map: ..." for free. `mesh_ops.rs`, `plan_query.rs` and `census.rs` are not edited (census benefits unchanged).
  - **Critique delta (must-fix): iterate `imposed_by`.** On `NoApplicableScheme`, the candidate to reject is the first entry of `imposed_by` (in its sorted order) that is not hard, not `copy` and not already rejected. If the replan after that rejection fails again on the same face, the next entry is tried, instead of stopping at `.first()` (`blame()`). Each try counts against the shared budget.
- **Strategies:** **Critique delta:** stretch, only if the user answers plan C5 with yes; not part of MESHER-REPLAN.
  - Give `DefaultStrategy` a `name` and a `description` (today `name()` returns the const), plus a `warn_tet: bool` (when false, `tet_reasons` is not set).
  - Add two constructors:
    - `hex_only`: surface `[map, submap]`, volume `[map, sweep]`. No tet fallback, and no triangle sources, so no wedges.
    - `tet`: surface `[trimesh]`, volume `[tetmesh]`, `warn_tet = false` (the user asked for tets, so `mesh.auto_tet` would be noise).
  - Register both in `StrategyRegistry::default()` so every front end and stub session sees them. Names not registered in a given registry are dropped by `policy()`, as today.
  - `mesh.auto_strategies` lists three strategies. `crates/sm-mesher/tests/auto.rs:594` (`assert_eq!(rows.len(), 1)`) is updated to three, ascending by name: `default`, `hex_only`, `tet`.
- **Tests:** `crates/sm-mesher/tests/auto.rs` (stub) and `crates/sm-server/tests/auto_select.rs` (real schemes), as in Acceptance.
- **Docs:** `crates/sm-mesher/DESIGN.md` "Auto selection": plan-time blame, the strategy table, the B6 outcome.
- **Not touched:** `sm-scheme-api` (planner, driver), any scheme crate, `sm-server/src`, `mesh_ops.rs`, `plan_query.rs`, goldens (see Hash impact).

## Risks

- The wedge outcome for B6 (finding 4) departs from the written acceptance. If the user wants a pure tet fallback with the default strategy, the strategy would have to change a score or add a rule against sweeps with a tri source, which moves existing `mesh.auto` choices (only for tri-source cases that already succeed through pave, e.g. B3's prism), so I recommend against it.
- `hex_only`'s surface list `[map, submap]` relies on the planner not appending the remaining registered schemes to a face with no imposition. This is read from `planner.rs` ~1420-1440 (the append happens only when `needs` is non-empty) but must be confirmed by acceptance 8 and 9. If a sweep source face counts as imposed, `hex_only` could still yield a `pave` source and wedges, and the strategy would need an explicit `Forbid` or a documented caveat.
- The shared plan-time budget can change which error a pathological model returns (`ReplanLimit` instead of the planner's error) only for inputs that failed before.
- Stub schemes may not model TRI vs QUAD caps; acceptance 1 then needs the local test scheme.
- `mesh.run` and `mesh.plan` keep plan-then-no-replan (finding 6). Someone who runs `mesh.run` with an unassigned volume next to a tet neighbour, without `mesh.auto`, still sees the old error. This is documented rather than changed.
- **Critique delta (new):** blame order by target id (finding 1 delta); covered by the `imposed_by` iteration and acceptance 1's second-entry test.
