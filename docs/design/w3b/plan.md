# W3b plan: transport handover, delta and analytic tracking, auto meshing, exporters, Python, viewer

Base: `main` at `f9f6246` (the post-W3a contract batch 55a20a9 and the follow-ups foam2d, tet, server, cadio, poly are merged). Rulings: `docs/design/w3b/rulings.md` (Q1-Q14 binding; P1-P5 proposals awaiting the user's OK). Inputs, all committed next to this file: the per-task planning drafts `docs/design/w3b/drafts/<task>.md` and the deferred-item triage `docs/design/w3b/triage.md`; the three rt-api panel designs are git refs (`w3b-panel/rt-1` = fd4a235, tags `archive/w3b/rt-api/hierarchy-first` and `archive/w3b/rt-api/transport-first`). **Citation convention.** Paths are relative to `docs/design/w3b/`. "`drafts/<task>.md` acceptance N" is item N of that file's numbered **Acceptance** list; "Scope N" is item N of its **Scope** list; "`triage.md` GO n" / "WAIT n" / "R n" are the numbered items of the GO list, the WAIT list and the ACRs line of `triage.md`. The drafts and triage predate the rulings: where a ruling or this plan changes a cited item, the change is written next to the citation ("ruling delta"), and `plan.md` and `rulings.md` win over the drafts.

Milestone (§4): a pin-cell / small-lattice model is built with the new primitives and `model.copy`, auto meshed with the `default` strategy (the history holds explicit scheme assignments), surface-meshed and explained with `mesh.plan`, exported to DAGMC h5m and Gmsh msh4 (and the model to STEP through the read-only `model.export` command, O5 default), written as the tracking handover file by `session.export` in the new `smrt` format (O1 default) and opened by a C test program through `libsmrt` that runs surface and delta flights with its own cross sections, recorded as a script and replayed, driven from Python, and shown in the web viewer. CLI, MCP, in-process and Python give the same state hashes.

### 3.2 Consolidated frozen-contract changes

**RT-API (`sm-rt-api`; fd4a235 plus Q1 grafts, rewritten for Q2 and Q4).** These items are new since main, so fd4a235's own types may still change before the freeze.
- *Majorants (Q2).* Remove `EnergyBands`, `MajorantEntry`, `MajorantTable` (`from_fn`, `(set, band)` key, `efficiency`, `check`), `ModePolicy::Auto` and the table argument of `choose_mode`. The caller passes `majorants: &[f64]` indexed by `NodeId` (length `HierarchyView::node_count()`) on every segment call, inside `FlightInput` (below). Leaves use their own entry; internal nodes are not read. **Per-call validation is O(1) plus what is read**: each call checks only the slice lengths (`majorants.len() == node_count`, `block.len() <= node_count`, else `InvalidInput`) and checks the one majorant entry it reads (finite, ≥ 0, else `InvalidInput` naming the node); it never scans the slices. A one-time `FlightInput::validate(&self, view: &dyn HierarchyView) -> Result<()>` checks every entry and that `block` is sorted and deduplicated; callers run it once when they build the slices. **NodeIds index the prototype tree, not placed instances**: a node is a partition node of a prototype leaf, a lattice component or a universe/placement component of `WorldSpec`; all instances of one prototype (every element filled with the same universe, every copy of a placed leaf) share its NodeIds, and the instance is resolved through `levels` and index arithmetic. So the slice length is independent of the instance count and RT-WORLD's "no per-instance memory for uniform fills" holds. Consequence for transport callers: a per-instance majorant needs distinct prototypes (distinct universes or leaves), which is also what distinct materials need, since regions are prototypes. sm-rt holds no σ_t and keeps no copy of the slice. Whether a band axis survives is O2; the default is one slice per call, so the caller changes energy by passing another slice.
- *Per-call flight input.* `#[derive(Clone, Copy, Debug)] #[non_exhaustive] pub struct FlightInput<'a> { majorants: &'a [f64], block: &'a [NodeId] }` with `new(majorants)` and `with_block(block)`, taken by `next_segment`, `probe` and `stop_at`. `block` (blockdt: force surface in those nodes; the caller keeps it sorted and deduplicated, membership is a binary search, O(log n_block) per node entered; an unsorted `block` is not detected per call and gives deterministic but unspecified membership, never a panic; `validate` detects it) is passed per call like `majorants`, so the cursor never holds a borrowed slice and needs no heap copy. The slices may differ between calls; each segment uses the slices of the call that produced it.
- *Collision check (Q2).* `FlightCursor::check_collision(&self, sigma_t: f64) -> Result<()>` takes no slice: it compares against the majorant of the current segment's node, cached in the cursor by the last `next_segment` (`InvalidInput` before the first segment or after the end). `Err(RtError::MajorantViolated { node: NodeId, sigma_t: f64, majorant: f64, pos: Point3, cell: CellId })` when `sigma_t > majorant * (1 + 1e-12)`; code -12; never clamped; state not advanced. The variant (new in fd4a235, fields `set, band, sigma_t, majorant`) is redefined with these fields before freeze.
- *Opaque resumable cursor (Q1).* `pub struct FlightCursor` (private fields, no borrow, no heap at depth ≤ `LEVEL_INLINE`) replaces the lending `Flight<'a>` borrow: `MajorantTracker::begin(&self, st: &TrackState, o: &FlightOptions) -> Result<FlightCursor>`; `FlightCursor::{next_segment(&mut self, t: &dyn MajorantTracker, input: FlightInput<'_>, st: &mut TrackState, s: &mut Scratch) -> Result<Option<FlightSegment>>, probe(..., input: FlightInput<'_>, t: f64) -> Result<Located>, stop_at(..., input: FlightInput<'_>, t: f64) -> Result<Located>, set_policy(ModePolicy) -> Result<()>, check_collision(f64) -> Result<()>, safety_distance(...) -> Result<f64>, distance() -> f64, end() -> Option<&TraceEnd>}`. A thin borrowing `Flight` wrapper may stay for Rust callers. The safety cache lives in the cursor, not in `TrackState` (equality unchanged). The trait-level `SegmentQuery<'a>` loses `band` and `table` and gains `input: FlightInput<'a>` (`policy`, `scale`, `max_dist` stay).
- *fd4a235 types under Q2 and O2.* `FlightOptions` stays `#[derive(Clone, Copy, Debug, PartialEq)]` with no lifetime: fields `max_dist`, `max_steps`, `stop_at_deck`, `policy`, `scale`; **`band` is removed** (one slice per call; if O2 keeps a band axis, the band becomes a per-call field of `FlightInput`, not a flight option). `SegmentScale::{Cell, Region}` stays unchanged (σ-independent; `Region` needs `REGION_JUMP`). `FlightTally` stays: `score_track` uses lengths only and `score_collision(cell, weight, sigma_t)` takes the caller's σ_t, so it holds no cross section and is Q2-clean.
- *Material sets (Q1, Q2).* Sets deduplicated in CSR with `BTreeMap` ids (ascending first appearance); `HierarchyView::{set_regions(MaterialSetId), node(NodeId).set}` report the regions of each node; region names (`RegionInfo.name`) are the material names the caller pairs with its cross sections. `validate_partition` also checks containment (a node's set covers every region below it).
- *Modes (Q1).* `ModePolicy::{Surface, Delta}` plus `FlightInput::block` (above). Hybrid is caller-driven per segment through `set_policy` and `block` (O3). Surface segments: one cell; `sigma_m` is the node majorant as a bound only; the caller samples with its own σ_t(region). `FlightSegment.face_in/face_out` and `end` stay as in fd4a235.
- *Safety and region jump (Q1).* `MajorantTracker::safety_distance` (provided, `Ok(0.0)` valid) and `TrackerCaps::{MAJORANT = 128, REGION_JUMP = 256}` as in fd4a235. - *Counters.* `#[non_exhaustive] #[derive(Clone, Copy, Debug, Default, PartialEq, Eq)] pub struct WorkCounters { steps, locates, segments, surface_segments, delta_segments, node_visits, face_tests, surface_evals, locate_candidates, bvh_descents, lattice_index_locates, slow_locates, nudges, tentative, rejected, safety_skips, jumps: u64 }` with `add`; `Scratch.counters` (kept by `Scratch::clear`), `Scratch::clear_counters`.
