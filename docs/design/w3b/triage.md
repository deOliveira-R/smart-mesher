##### GO: take in W3b (ranked)

1. **RT prerequisites (S+S; sm-rt, sm-rt-capi).** The tracker cache cannot be loaded through the frozen contract (`smrt_open` always returns -5, W3_REPORT sm-rt-capi), and `smrt_dag_measure_area`, `get_angle(surface)` and region tags are stubbed. Sketch: stage-0 ACRs R1-R4 (below), then sm-rt exports `load_tracker(&CacheImage) -> Result<Box<dyn Tracker>, RtError>` without the input and sm-rt-capi wires `smrt_open`, `measure_area`, surface normal and tags (about 10 lines each behind `cfg(feature="sm-rt")`). Also `Tracker::mesh()` returns `Some` (MeshInput Arc), `LostCause::SenseMismatch` and `retries`. Reason: the honest DAGMC benchmark and the hierarchical backend cannot start from a cached tracker without it. Rank 1 because it blocks the flagship task.
2. **Allocation-free SoS entry in sm-math (S; sm-math, L0).** `orient3d_sos` allocates on exactly degenerate crossings, which breaks the zero-allocation tracker contract for lattice-aligned rays (the typical reactor case: rays through pin axes and mesh vertices). Sketch: `orient3d_sos_noalloc` with a fixed-size perturbation table; sm-rt switches to it; test against the allocating version over a degenerate-grid fixture. Additive in sm-math, not a frozen contract.
3. **Export notes through CLI and server, assert INT-8 (S; sm-cli, sm-server).** After the running `ExportResult.notes` contract lands: `smesh export --json` and the server reply carry the notes; the w3a milestone asserts the INT-8 split count against `smeshCellMap` (closes deviation 4 of the wave report). Also surfaces `FoamReport` / `LossReport` in the protocol (ruling E2). Directly serves "diagnostics actionable via MCP/CLI".
4. **OpenFOAM 2D case and warped dual faces (M; sm-meshio, sm-fem).** (a) `FoamOptions::split_low_face_cells: bool` (default true) plus a one-layer hex/wedge fixture and an `empty` patch path for dimension-2 and one-layer cases (both lines are in sm-meshio deferred). (b) Split warped dual faces into planar pieces in the exporter and record the INT-9 counts (1046 concave on polydual) before and after; report, do not tune the internal cells. Exporters own the quirks.
5. **Transport diagnostics and smooth suggestion (S+S; sm-quality, sm-diag).** Flag cells with two or more boundary faces (transport profile); `mesh.quality` suggests `smooth` for spread scaled-Jacobian warnings (wave-report deviation 1, make the milestone test use the real suggestion). Add `mesh.unflag_cells` and `grow`-aware set removal after ACR S1. Per-material profile is part of (c) only if the Transport thresholds are ratified (open question 1).
6. **Set-targeted smoothing (S; sm-smooth).** `mesh.smooth { set: <name> }` consuming the sets `mesh.flag_cells` stores (closes the quality to smooth loop; sm-smooth ruling M1 says "set naming decision"). Needs the naming ruling in open question 2. Includes `NodeSelect::Set`. Unit tests: nodes outside the set bit-identical.
7. **Boolean performance (M; sm-boolean).** Replace the O(F^2) `candidate_pairs` with a BVH over face boxes, index fragment classification, share the tool in `subtract` with N targets (Arc, not deep copy), and add a work-counter assertion (candidate tests <= c * F log F) instead of wall time. The per-op COW cost for 10^5-face models is bundled but gated on the bulk-commit contract; if that does not land, it stays recorded. Needed before the 1e5-face reactor assemblies the viewer and DAGMC benchmark will import.
8. **STEP fidelity cluster (M+M; sm-cadio, plus sm-topo-api ACR).** (a) Promote `PCURVE` / `DEFINITIONAL_REPRESENTATION` import and honour seam pcurves in `sample_face` (sm-cadio ACR 1 and 2); then delete `split.rs` and the `step.split_closed_face` workaround; unblocks submap and map on closed NURBS faces. (b) `model.import_step_attributes`: STEP names and colors to Model groups and colors (material names from CAD; this is how a nuclear user's assembly keeps its material identity). (c) Replace sm-cadio wall-clock tests with work counters (hygiene, S). Mirrored placements and `CARTESIAN_TRANSFORMATION_OPERATOR_3D` flattening is S and rides with (a).
9. **Pave corner rule and valence cleanup (M; sm-scheme-pave).** Acute / obtuse corner rule so triangles (32 of 150 random) stop failing the placement ladder, then diagonal collapse and valence-2 removal; quality gate recorded (min SJ 0.151 on the 5-lobed star improves). Auto selection scoring needs `pave` to be robust on three-corner regions, so this precedes the auto-selection task. Keep a private CDT (see WAIT 1).
10. **Submap periodic and seam faces (M; sm-scheme-submap).** Blend through pcurves via `GenCtx::loop_uvs` so cylinder lateral faces mesh with submap (surface-only `mesh.run` on cylinders is the first user-visible case); graded cut-line spacing for the L-shape stretch. Reversal corners and inner loops WAIT.
11. **Tet recovery robustness (M; sm-scheme-tet).** Fix `recover_facet` rounding (n=64 cliff, whole-build restart lottery, 28 s versus 5 s), replace the `RecoveryFailed.tri` placeholder, add the pass-level respace unit test and the O(n * hints) restart check; the located diagnostics go through `SchemeNote` once that contract lands (current W3_REPORT ACR). Gate on work counters (restarts == 0 on tiled n=64), not time.
12. **Server hygiene (S; sm-server, sm-mcp, sm-mesh).** `write_atomic` unique temp name (pid + counter); `Server::open` binding another builder's pending store; sm-mcp engine-backed `respelled_ids_feed_back_as_arguments`; drop the `contract_alloc` warm-up in sm-mesh; `cargo fmt` pass over sm-mcp and sm-scheme-api (last, to avoid conflicts); `smesh serve --ws` forwards to the sm-server `ws` feature (the viewer task needs it, so this is a viewer prerequisite, S).
13. **sm-poly typed error and partial dualization prerequisites (S; sm-poly).** Typed error for unrepaired cells (backlog); set `derived_from` in `ToPoly::apply` once the contract lands (one line); report the seam-edge and one-split-edge cases as typed errors. Partial dualization of mixed meshes WAITS (needs conformize).
14. **Verdict completeness for PARITY P1 (M; sm-quality).** `*_equiangle_skew`, `tet_mean_ratio`, `tet_inradius`, `tet_squish_index`, `quad_radius_ratio`, `hex_nodal_jacobian_ratio`, `wedge_max_stretch`, plus FV equiangle skewness and cell aspect ratio in the checkMesh definition. Each with an analytic fixture. Low risk, closes a PARITY row, no dependencies.

##### WAIT: not in W3b (with reason)

1. **Shared 2-D CDT crate (pave + tri).** Duplication is stable and documented; a new crate needs a ladder slot (L2, depends on sm-math only) and a graph node. Revisit only if items 9 or an off-center insertion change both copies.
2. **Pole / degenerate-edge faces, hemispheres, cone apex, solid-cylinder revolve and pole columns, 360 degree revolve.** All need a model-level partition and a topology decision on periodic revolve and linking faces in `TopologyView`. Raise as an open question for W4.
3. **Boundary Steiner points with coordinated surface re-meshing (tet).** Needs a driver retry hook (new contract). Not before sm-scheme-api is reopened for a second batch.
4. **sm-smooth: analytic gradients, 3-D Winslow, equipotential, untangle, randomize, parallel colouring, polyhedral / high-order.** Untangle is the only one with a user-visible gap (inverted tet input) but it is a new algorithm; propose it as the first W4 smooth item. Perf gates depend on bulk commit; record only.
5. **Higher-order cells (HEX20/27, TET10, edge-table elements), Exodus netCDF-4/HDF5, time steps and results, assemblies, edge/face/element sets, shell sides, Nemesis, reading third-party Exodus.** None serve the transport direction; wait for degree elevation. Note: HDF5 comes in with the DAGMC h5m writer; do not reuse it for Exodus in W3b.
6. **Mesh-level booleans, virtual topology, instanced and decomposed volumes, mixed-dimension unite, non-manifold inputs, NURBS SSI marching (M4), tangential contacts, extended NURBS webcut tool, sheet-tool imprint, tolerant healing above `linear_max`, partial-overlap merge of curved faces.** Large and independent; the DAGMC-style geometry the benchmark needs is quadric / planar, so M4 stays out. Instanced / decomposed volumes get a note: HIERARCHY rt (separate task) is the first consumer; coordinate there, do not duplicate.
7. **sm-sizing exact-regime limits (>512 classes), sm-tess constrained-Delaunay interior refinement.** Heuristic paths are verified feasible; viewer task can tolerate boundary-only faces and reports `boundary_only`.
8. **Remote file staging (`Request::Stage`), `.smsh` tracking chunk, `SmshMesh: MeshRead`, Fluent export, binary OpenFOAM, Fluent / h5m checklist.** Staging belongs with the remote backend, not W3b; the tracking chunk waits for the HIERARCHY cache format; Fluent waits for a licence by user ruling; `SmshMesh: MeshRead` is worth doing only with a file-to-file converter, add it then.
9. **Tri variants (`tripave`, `trimap`, `triprimitive`, `circle`, `hole`), anisotropic metrics, quad-dominant output, off-center insertion, parallel refinement.** Off-center insertion is the first remedy if the 20 degree bound fails; escalate then, do not schedule now.
10. **sm-rt: SIMD / packet traversal, mmap load, F32 traversal, non-matching PERIODIC, `rt.fire`, overlap detection, exact `closest` for curved faces.** Belong to the ANALYTIC / HIERARCHY / benchmark tasks (which decide if they matter); not triage items.
11. **sm-lang user functions, `where` predicates; typed-reference convention for scheme params that name entities (`IntentLayer::on_retired`).** The params convention is a contract question; ask in open question 3 before scheduling.
12. **Sequential meshing against meshed neighbours, partial `mesh.run` success, cancellation inside the driver, decomposition pieces in `mesh.run`.** Belong to the surface-only `mesh.run` task design, which decides what fails.
