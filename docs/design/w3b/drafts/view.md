### W3B-VIEW. `sm-view` (L3, new crate): render-buffer queries and the web viewer client

Stack decision (ARCHITECTURE §2/§7: "TypeScript + WebGPU", WebSocket JSON-RPC, binary render buffers):
- **Client:** TypeScript, raw WebGL2, no runtime dependencies (no three.js, no CDN). Dev dependencies only (typescript, esbuild, playwright), pinned by lockfile. WebGPU is NOT used in W3b: headless WebGPU is unreliable in CI, WebGL2 runs under SwiftShader, and the buffer contract below is renderer-neutral, so a WebGPU backend can be added later without touching Rust (open question 1).
- **Transport:** the existing sm-server `ws` feature (text JSON-RPC, tungstenite). Render buffers travel as base64 inside query replies, the pattern `view.tessellate` already uses. Binary frames are deferred; this task records the measured base64 overhead in `DESIGN.md` so the decision is data-based.
- **Where the client lives:** `crates/sm-view/web/` (TS source, `dist/` bundle, tests). One owned directory. The crate exposes the built bundle as `pub fn assets() -> &'static [Asset]` for sm-server to serve (sm-server wiring is the server task, see Deps).

- **Deps:** normal: sm-core, sm-op-api, sm-layer-api (`ModelLayer`, `MeshLayer`), sm-mesh-api (`MeshRead`), sm-topo-api, sm-quality (`compute`, `Metric`), serde, schemars, thiserror, rayon. Dev: sm-testkit, sm-mesh (stores the fixtures), sm-model-api. NOT sm-tess, sm-diag, sm-server, sm-engine or any other W3b crate (decision 12 peer rule). The client calls the existing `view.tessellate`, `mesh.validate`, `mesh.quality`, `mesh.info`, `model.list`, `timeline.*` itself; the server never joins them.
- **No stage-0 ACRs.** Everything needed (`MeshRead` facet sides and owners, `ModelLayer` colors, `Rev` on queries via `Request::Query.at`) exists. Notifications are transport-level (sm-server task), not a new `Request` variant.

#### Scope: Rust side (three read-only queries, `ViewPlugin`, id `"view"`)
All are `TypedQuery`; none mutates state; all take the mesh by id (default: the only mesh, else typed `ambiguous-mesh` listing ids, as `session.export` does). Because `Request::Query` has `at: Rev`, timeline scrubbing needs no new protocol.
1. `view.scene {}` -> `{ bbox:[[f64;3];2], bodies:[{id, volumes:[id], color:[u8;3]|null, name?}], meshes:[{id, name, dim:2|3, cells, facets, nodes, bbox, digest:Hash256, derived_from:[id]}] }`. Sorted by id. Colors come from `ModelLayer`. This is the client's cache key source: it refetches a buffer only when `digest` changes.
2. `view.mesh_skin {mesh?, volumes?:[id], clip?:{origin:[f64;3], normal:[f64;3]}, outline?:bool=true, max_tris?:u32=2_000_000}` -> `SkinReply { tri_count, vertex_count, positions:b64 f32x3, indices:b64 u32, tri_cell:b64 u32 (dense cell index of the visible side), tri_owner:b64 u32 (raw id of the topo entity owning the facet, 0 = none), outline_indices:b64 u32 (line list of polygon edges, empty when outline=false), bbox, clipped_cells:u32 }`.
   - Skin = facets with exactly one kept side, plus facets between different `volumes` owners (interfaces shown as double-sided). Surface-only meshes (`dim()==Two`) draw every polygon.
   - **Clip is cell-based, exact, with no geometric cutting:** a cell is removed when its centroid (`cell_volume_centroid`) has `dot(c - origin, normal) > 0`. Facets between a kept and a removed cell are the cut face and are tagged in `tri_owner` as the owner of the kept cell. So the cut shows real cells, matches what a solver sees, and is deterministic.
   - Polyhedral facets (n > 4) fan-triangulate from the facet centroid vertex appended after the mesh nodes (so non-convex dual faces stay watertight). Triangles are ordered by facet index, then fan order. Vertices are emitted in first-use order (no hash iteration).
   - Above `max_tris` the call fails with `ViewError::TooLarge { tris, max, hint }` ("clip, pass `volumes`, or raise max_tris"). It never decimates silently.
3. `view.mesh_scalar {mesh?, metric:"scaled_jacobian"|... (any sm_quality::Metric name), bad_below?:f64, bad_above?:f64}` -> `{ metric, count, values:b64 f32 per dense cell, min, max, mean, bad_cells:u32, worst:[{cell:EntityRef-like {id,index}, value, location:[f64;3]}] (N<=20) }`. Values are `sm_quality::compute` cast to f32 once, so the client colors `tri_cell -> values`. Unknown metric or a metric not defined for a cell type gives NaN in the buffer plus a count in `undefined_cells`; an unknown name is a typed error listing the valid names.
- Public library API (rustdoc on all): `ViewPlugin`, `SkinQuery/SkinReply`, `SceneQuery/SceneReply`, `ScalarQuery/ScalarReply`, `ViewError` (thiserror: `NoMesh`, `AmbiguousMesh(Vec<EntityId>)`, `UnknownMetric{name, valid}`, `TooLarge{..}`, `Mesh(String)`), `Asset{path:&'static str, mime:&'static str, bytes:&'static [u8]}`, `assets()`, and `pub fn skin(mesh:&dyn MeshRead, o:&SkinOptions) -> Result<Skin, ViewError>` (library form, no base64, used by tests and by a later native renderer).

#### Scope: client (`crates/sm-view/web/`)
What it shows in W3b (read-only; edits go through a one-line command console that sends `script.run`, so the human and an MCP agent share one session):
- **Model:** faces from `view.tessellate` (per-face ranges, `boundary_only` faces drawn with a hatch flag), edges as lines, body/volume colors from `view.scene`. Picking returns the topo entity id.
- **Mesh:** skin from `view.mesh_skin` with outline toggle, volume visibility checkboxes, and a clip plane (axis x/y/z + slider; sends `clip`).
- **Quality located on geometry:** a metric selector (`view.mesh_scalar`) colors skin triangles by cell value; `bad_below` marks cells in red. The findings panel lists `mesh.validate` and `mesh.quality` findings; each row has a location marker (sprite at `location`) and highlights its `owner` face/volume from the model tessellation ("bad cells cluster on face 12"). Clicking a marker or a worst-N row flies the camera to it and shows the suggested op text verbatim (copy button; no auto-run).
- **Timeline:** a node list from `timeline.log` with branches from `timeline.status`; selecting a node re-requests everything with `at=<rev>` (read-only time travel, HEAD untouched). A header shows state hash and mesh digest. When the server pushes a `state.changed` notification (sm-server task) the view refreshes; without it, the client polls `timeline.status` every 2 s.
- **Transports:** `ws://` (live) and `fixture://` (replays recorded reply JSON; used by tests and the offline demo `index.html?fixture=hexbox`). Same decode path for both.
- Modules (each unit-testable in node, no DOM): `codec.ts` (base64 -> typed arrays, endianness check, length checks that throw typed errors), `camera.ts` (orbit math, fit-to-bbox), `pick.ts` (CPU ray/triangle pick), `raster.ts` (CPU ID rasterizer for tests), `gl.ts` (WebGL2 renderer: flat-shaded skin, ID-buffer pass for picking, lines, point sprites), `app.ts`, `rpc.ts`.

#### Testing, headless
1. **Rust (gating, in `cargo test -p sm-view`):** library and query tests on sm-testkit meshes, determinism, and a `fixtures` test that regenerates `web/test/fixtures/*.json` and asserts they equal the committed files (golden; `SM_BLESS=1` rewrites).
2. **Node unit tests (`npm test`, `node --test`, no browser):** codec, camera, CPU pick and raster against the golden fixtures.
3. **Browser e2e (`SM_VIEWER_E2E=1 npm run e2e`, skipped with a printed reason when playwright/chromium is missing):** headless chromium (`--use-angle=swiftshader`), `fixture://` mode. Renders the **ID buffer** (not colors) and compares to `raster.ts` pixel by pixel with at most 0.5% mismatched pixels (edge rules differ). A color screenshot is saved as an artifact, never compared. Also: clicking a pixel returns the id `raster.ts` predicts; changing the clip slider changes the triangle count to the analytic value below; findings row click centers the camera on `location` within 1e-3 of bbox diagonal.
4. A live smoke against `smesh serve --ws` belongs to integration (needs the server task), not this crate.

#### Acceptance (analytic; numbered)
1. `view.mesh_skin` on the 4x2x2 unit-cell hex box (16 cells): 40 boundary quads -> 80 triangles, 40 skin facets, `tri_owner` nonzero on every triangle, sum of triangle areas = 2(8+8+4) = 40 within 1e-12.
2. Same mesh, clip `origin (2,0,0) normal (1,0,0)`: the 8 cells with centroid x < 2 stay (`clipped_cells` 8), skin is the 2x2x2 block: 24 quads -> 48 triangles, area 24, and the 4 cap quads (x = 2) are in `tri_cell`'s kept cells. A plane that removes everything gives zero triangles, not an error. A plane through a cell centroid (dot = 0) keeps that cell.
3. Two-volume mesh (webcut fixture, 16 hexes, shared cap): with both volumes the cap is shown (interface), with `volumes=[one]` it is a skin face with that volume's owner. Counts match the analytic cap area of 4.
4. Polyhedral mesh (poly dual of a tet box from sm-testkit or a hand-built 3-cell polyhedron): skin is watertight (every skin edge used exactly twice, checked with a local edge map sorted by key), area equals the sum of boundary facet areas within 1e-12, and the centroid-fan vertices are appended after node ids.
5. Surface-only mesh (dim 2, a 3x3 quad patch): skin = 9 quads -> 18 triangles, no clip effect on dimension (clip removes polygons by centroid).
6. `view.mesh_scalar scaled_jacobian` equals `sm_quality::compute` bitwise (after f32 cast) on a mesh with one node moved by 0.3: `worst[0].cell` is the cell touching that node, `bad_cells` equals the independent count of values below `bad_below`, min/max/mean match a recomputation. A hex box has all 1.0 (min = max = 1).
7. Typed errors: unknown metric lists valid names; `max_tris=10` on the box gives `TooLarge{tris:80,max:10}` with the hint; two meshes without `mesh` gives `AmbiguousMesh`; no mesh gives `NoMesh`. Messages name ids and a fix.
8. Determinism: every reply is byte-identical across two runs and `RAYON_NUM_THREADS=1` vs default (`sm_testkit::determinism::check`), including the base64 strings. `sm_testkit::strategies::config(n)` property test: for random clip planes on the box, kept-cell count plus `clipped_cells` equals 16 and each skin triangle's facet has exactly one kept side or is an interface.
9. Node unit tests: base64 round trip against Rust-written fixtures; a truncated buffer throws `CodecError`; fit-to-bbox puts all 8 bbox corners inside the frustum; CPU pick of the box fixture from three canonical views returns the analytic face (+x, +y, +z).
10. `assets()` lists `index.html`, `viewer.js`, `viewer.js.map` with correct mime types and non-empty bytes; a test hashes `web/dist/*` and compares with `web/dist.sha256` (stale bundle fails; the check that rebuilds with esbuild runs only if node exists and prints a skip otherwise).
11. Docs: `DESIGN.md` (buffer layouts with byte offsets, clip rule, polyhedron fan rule, cache keys, base64 overhead measured on a 10^5-cell skin, WebGL2 vs WebGPU rationale), `W3_REPORT.md`. Rustdoc on every public item; `cargo clippy -p sm-view -- -D warnings`; `tsc --noEmit --strict` clean.

#### Must NOT
- Edit any other crate, root `Cargo.toml`, CI, `tools/` or docs outside `crates/sm-view/`; touch sm-server (HTTP static serving, multi-connection, `state.changed` push are the server task).
- Add a runtime JS dependency, load anything from a CDN, or require network access to run the viewer or its tests; use WebGPU; add `unsafe`.
- Judge validity in the client: the viewer shows `mesh.validate` / `mesh.quality` output, it never recomputes verdicts. Quality values come from sm-quality only.
- Decimate or drop geometry silently; iterate a `HashMap` into output; use time-based or unseeded randomness; use `unwrap` on input paths (decode errors are typed in both languages); compare color pixels as a gate; add wall-clock assertions (record counts and base64 bytes instead).
- Mutate state, or auto-run a suggested op from the UI.

#### Deferred
Binary WebSocket frames and diffs, LOD and tiling beyond `max_tris`, WebGPU backend, field/overlay of ray-trace tracks, mesh editing by picking (select-and-apply), Tauri desktop wrapper, authentication for remote servers, screenshot-based regression gating.
