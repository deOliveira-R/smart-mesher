### W3b-RTBENCH. `sm-rt-bench` (L4, new, tool crate, `publish = false`): the honest tracking benchmark against DAGMC (MOAB, double-down/Embree) and XDG
- **Deps (tasks):** `rt-analytic` and `rt-hierarchy` (ANALYTIC/HIERARCHY backends in sm-rt) and `rt-delta` (delta-tracking mode), all merged; the W3a `sm-rt`, `sm-rt-capi` (read-only reference) and the stage-0 W3b contract batch. Soft dependency (stretch case B6): `export-dagmc` (DAGMC h5m exporter in sm-meshio). Crate deps: sm-core, sm-math, sm-geom-api, sm-model-api, sm-model, sm-tess, sm-rt-api, sm-rt, sm-testkit (dev: rayon, proptest via `sm_testkit::strategies::config`). It does NOT depend on sm-rt-capi (adapters call `Tracker` directly; the C-ABI overhead stays in `sm-rt-capi/bench`). Nothing depends on this crate.
- **Binding rulings.** Acceptance is reproducibility and fairness, not winning. Record-only: no wall-clock gate anywhere, tests assert work counters, hashes and analytic values. No speedup claim in code, docs or report text; the report states measured ratios with spread and CPU. Numbers are committed only if measured by the harness (never typed in). `sm-rt-capi/bench/` stays as the W3a record and is not edited; this crate supersedes it for new results and reads its C1-C3 data by path (`--legacy-data`).
- **Idea.** One deterministic case generator emits identical bytes to every competitor. One result schema (`smbench-result v1`) is written by the Rust runner and by the C++ drivers. A comparer checks that the trackers agree with each other and with analytic truth before any rate is shown. Rates are only reported for a (case, workload) pair whose agreement check passed.
- **Where it lives.** New crate `crates/sm-rt-bench/` (lib `sm_rt_bench`, bin `smrt-bench`, `docker/`, `drivers/`, `results/`, `DESIGN.md`, `REPORT_TEMPLATE.md`, `W3B_REPORT.md`). Reason: the cases need `sm-model`/`sm-tess` (L2) and `sm-rt` (L3), so it cannot sit inside sm-rt (L3, would invert L2 use) or sm-rt-capi's bench dir (owned by another task). Registers no ops, no plugin.
- **Scope (mandatory):**
  1. **Cases** (`cases::Case` enum, `pub fn build(case, scale) -> CaseData`). Every case is a `sm-model-api` Model (analytic faces, prototypes/lattices) plus a derived faceted twin from `sm_tess` at an explicit `sag` tolerance (recorded in the manifest). Vacuum outside (implicit complement), no graveyard, no reflective faces (DAGMC has none; reflective stays an sm-rt-only test).
     - **L1 legacy**: W3a C1/C2/C3 replayed from `--legacy-data` (facets only; sanity link to the W3a numbers).
     - **P1 pin cell**: fuel r 0.4096, clad r 0.475 (gap merged), square pitch 1.26, height 100; 3 regions plus complement. Facet twin at sag 1e-4 (cm).
     - **P2 17x17 assembly**: 264 pins + 25 guide tubes, one pin prototype instanced 289 times in the Model (HIERARCHY); the facet twin is flat (what DAGMC must hold). Reports `prototypes`, `copies`, `memory_bytes`.
     - **H1 large homogeneous region**: 200 cm water cube containing 8 small steel/fuel inclusions (spheres and boxes). Tet volume mesh from `sm-scheme-tet` at target edge 2 cm (about 1e6 tets, fixed seed) for the cell-walking modes and XDG; same mesh bytes for both.
     - **F1 fusion-like**: generated torus sector (R 600, 18 nested shells r 5..200 with 12 rectangular ports and a cut plane), tessellated at sag 0.05 (about 3e5 triangles) and 0.01 (about 3e6). It is synthetic on purpose (no licence issue); `--external-h5m PATH` runs DAGMC/XDG drivers and the facet path on a user-supplied real model (B5 stretch).
  2. **Rays and flights.** `smrays v1`/`smfacets v1` formats exactly as in `sm-rt-capi/bench/README.md` (little-endian, splitmix64 seeded from FNV-1a of the case name, start-region rejection rule for faceted vs analytic solids). New `smtets v1` (nodes f64x3, tets u32x4, region i32 per tet) for XDG, `smcase.json` manifest (regions, per-region `sigma_t`/`sigma_a` for the transport workload, tolerances, SHA-256 of every file). Generation is IEEE-exact and byte-identical on x86_64 and aarch64; `smrt-bench gen --check` compares with `expected_sha256.txt`.
  3. **Workloads** (every tracker implements the three through one `adapter` trait in Rust or the same JSON protocol in C++):
     - **W-track**: follow a ray to leakage; output the region sequence and the chord per region. Primary geometric workload; also gives segments per track.
     - **W-fire**: random interior points with known start region, one `ray_fire`-equivalent to the first boundary (DAGMC `ray_fire`, XDG `ray_fire`, sm-rt `fire` with `max_steps = 1` surface). Reported with and without point location (`find_volume`/`locate`) as separate rows, because DAGMC stock `find_volume` is a linear loop over volumes.
     - **W-flight**: seeded Monte Carlo histories (isotropic scatter, absorption, `sigma_t` per region from `smcase.json`, exponential flights from a per-history splitmix64 stream, collision/track-length tallies per region). DAGMC and XDG use surface tracking (one fire per flight). sm-rt runs surface mode, pure delta mode and the hybrid policy (`rt-delta` API); all three must produce tallies consistent with the surface-tracking tallies (4-sigma on per-region collision counts for 1e6 histories, fixed seed).
  4. **Competitors** (`docker/`, one image per row, base images pinned by digest, never `:latest`; the digest, package versions and source commits go into every result file):
     - `dagmc-moab`: W3a recipe (conda-forge dagmc `nodoubledown` + MOAB, OBB tree); driver extended from `sm-rt-capi/bench/dagmc/` (copied, not edited in place).
     - `dagmc-dd`: DAGMC with double-down/Embree. Try the conda-forge double-down variant first; if absent, build double-down at commit `437ad209eac5` and DAGMC against it from source with Embree from conda-forge. The Dockerfile fails the build if `dagmc_driver --version` does not report double-down.
     - `xdg`: build XDG at commit `83efb306e152` (MOAB mesh manager, Embree ray tracer; libMesh and GPRT off) from source; driver `xdg_driver.cpp` calls `ray_fire`, `find_volume` and the element `walk_elements` path on the `smtets` mesh (converted in-container by `smtets_to_moab.cpp`, tets keyed to volumes by region). If the build recipe cannot be completed, the image is reported `unavailable` with the failing command in the result file and the run continues; no numbers are invented.
     - All drivers: compiled `-O3` with the same toolchain flags, geometry loaded once, no I/O or allocation in the timed loop, a running checksum of outputs (anti dead-code), optional `--pin-cores`. Native architecture only (no qemu); x86_64 and aarch64 results are never merged into one table.
  5. **Measured, per (case, tracker, mode, threads in {1, N}):** `rays_per_s` (median, min, max of 7 reps after 3 warm-up), `segments_per_track` and `ns_per_segment` (derived from the same run), `fires_per_history` (W-flight), `build_s` split into `load_s` and `tree_s`, `structure_bytes` (sm-rt `TrackerInfo::memory_bytes`; competitors: peak RSS minus RSS after load of a stub-empty model, plus raw peak RSS for all), `lost` (with the W3a loss definition plus an audit sample), `geom_error` (below), `agreement` (below), `determinism` (below), `cpu_model`, `governor`, `ncpu`, `date_utc`, `git_sha`, `image_digest`.
  6. **Fairness rules** (written in `DESIGN.md`, each enforced by the runner or a test): (a) same bytes in: every tracker reads the same ray file and the same facet or tet file; (b) same session and machine: the runner interleaves trackers ABAB per rep and refuses to write a comparison table when `cpu_model` or `date_utc` day differ; (c) best effort for each side: DAGMC gets the start volume as OpenMC would hold it (hinted), sm-rt gets the same hint; point-location rows are separate; (d) precision is a column, not a footnote: double-down is mixed precision, sm-rt is f64 (`Precision`); (e) geometry fidelity is measured, not assumed: sm-rt-analytic is exact while DAGMC/XDG see the facet twin, so every tracker's chords are compared to the analytic reference (`geom_error` = max and mean abs chord error and region-sequence disagreement count per 1e5 tracks); a faster tracker with a worse `geom_error` is shown as such; (f) memory and build time are reported with the same weight as rates; (g) a W-flight comparison is shown only if the tally agreement test passes; (h) cell walking alone is not claimed novel (XDG does it); the report columns separate "walk on same tets" from "analytic/hierarchy" and lists what each row does not do (no reflective faces in DAGMC, no instancing in DAGMC, etc.).
  7. **Agreement checker** (`compare` module, pure functions, unit-tested with the stub `AnalyticWorld` standing in for a competitor): per track, region sequences are equal except where a chord is shorter than `5e-9 * bbox_diagonal` (grazing, counted and listed, not hidden); chords agree within `max(1e-9 * diag, facet sag bound)`; disagreements are written to `disagreements.jsonl` (first 1000 with ray index, both sequences) so a failing case is actionable.
  8. **Determinism section** (`determinism` module): sm-rt `trace_bundle` content hash for W-track and tallies for W-flight are equal for `RAYON_NUM_THREADS=1` and N, and across two runs (asserted); for DAGMC/XDG the same hashes are computed over their outputs ordered by ray index and recorded as observed (`stable: true|false`), never asserted. Result files carry `result_hash` over all non-timing fields so two runs can be compared by one string.
  9. **Runner** `smrt-bench`: subcommands `gen`, `run --cases P1,P2 --trackers smrt,dagmc-moab,dagmc-dd,xdg --threads N --reps 7`, `report --results DIR --out REPORT.md`, `self-test` (no Docker: generator checks, adapters on the stub, schema round trip), `docker-check` (builds each image, prints versions and digests). `run_bench.sh` is a thin wrapper. Result files `results/<case>-<tracker-set>-<UTC>-<pid>.json`, opened with `create_new` (never overwritten); a `bench-env.json` with toolchain versions and the machine id (no hostnames) beside them. `report` renders per-case tables (rows = tracker x mode, columns as in item 5) and a "what was not measured" list; it refuses mixed-machine input.
  10. **Docs.** `DESIGN.md`: fairness rules, protocol JSON, build recipes, how to add a competitor, known limitations. `W3B_REPORT.md`: commands run, machine, what built and what did not, and the measured tables copied from the harness output. Rustdoc on every public item.
- **Acceptance (all runnable without Docker unless marked D; D items report `status: partial` with the failing command if Docker is unavailable, never fabricated numbers):**
  1. `smrt-bench gen --check` matches the recorded SHA-256 of every file of P1, P2, H1, F1(sag 0.05, reduced to 1e4 rays) and the L1 legacy cases twice in a row, and across `RAYON_NUM_THREADS=1` and default; the P2 facet twin has exactly `289 * (facets of one pin) + shared plates` triangles by closed-form count.
  2. Analytic truth: on P1 and P2 the sm-rt ANALYTIC/HIERARCHY tracker's chord through each cylinder equals `2 sqrt(r^2 - b^2)` within 1e-11 relative for 1e4 seeded rays, and per-track chord sums equal the total path to the bbox boundary within 1e-10 (analytic, independent of any competitor).
  3. The facet twin respects its tolerance: for P1 the max radial deviation of the tessellation from the true cylinder is at most the recorded sag (measured from the triangle planes), and `geom_error` of an exact sm-rt run against the faceted-twin sm-rt run (VOLUME_MESH/facet input) is bounded by `sag * 4 / sqrt(1 - b^2/r^2 + eps)`-style analytic bound stated in DESIGN.md (the test computes the bound per ray).
  4. Agreement checker unit tests with a stub competitor: identical output gives zero disagreements; a one-facet perturbation larger than the tolerance is detected, located (ray index) and written to `disagreements.jsonl`; a grazing chord below the threshold is counted, not flagged.
  5. Work counters, not time: W-track on P2 reports `segments_per_track` for surface mode, and in HIERARCHY mode the number of prototype pins touched per track (<= the geometric count of pins the ray's cell-DDA passes through, computed independently by a 2D grid walk in the test); W-flight in delta mode reports `rejected_collisions` and `fires_per_history`, and in the homogeneous H1 interior (a ray that starts and ends inside the water with no inclusion on the path) delta mode reports 0 boundary tests per flight beyond the majorant node. (If the contract counters ACR is not merged, the test asserts the step count only and the report marks the other counters `n/a`.)
  6. W-flight unbiasedness: on a pure-absorber sphere (Sigma 0.3, R 5) the transmitted fraction for 1e6 seeded histories equals the exact `exp(-Sigma * chord)` average within 4 sigma for sm-rt surface, delta and hybrid modes; the three modes' per-region collision tallies agree within 4 sigma on P1.
  7. Determinism: item 8 hashes equal for 1 vs N threads and for two runs, for P1, P2, H1 (reduced) in sm-rt; `sm_testkit::determinism::check` passes on the W-track output bytes; the `result_hash` of two runs of `smrt-bench run --trackers smrt --reps 1` is equal.
  8. Fairness gates are code: a test builds two result files with different `cpu_model`, and `report` refuses to render a comparison; a file where `agreement.failed > 0` renders its rate cells as `n/c (disagrees)`; the rule (b) ABAB interleave order is asserted from a recorded trace of runner calls on the stub adapter.
  9. (D) `docker-check` builds `dagmc-moab`, `dagmc-dd` and `xdg` on this machine; each driver prints a version/commit line that equals the pinned one; `smrt-bench run --cases P1 --rays 20000` produces one result file per tracker; DAGMC-MOAB and DAGMC-dd agree on region sequences for every ray (they share the geometry; the DAGMC paper claims identical results) and both agree with sm-rt on the facet twin; XDG agrees on the P1 tet mesh walk (or the disagreement file explains it).
  10. (D) Full run P1, P2, H1, F1 at 1 and N threads on one machine produces committed result files and a rendered `REPORT.md`; the report includes memory, build time, `lost`, `geom_error` and determinism columns for every row, and the "what was not measured" list. No claim in the text that is not a table value.
  11. Lints and docs: `cargo clippy -p sm-rt-bench --all-targets -- -D warnings`, rustdoc clean, no `unsafe` (the crate forbids it), no `unwrap` on input paths (case files, JSON from drivers, CLI), typed `BenchError` with `thiserror`. `tools/ci.sh` passes with the crate in the workspace; `self-test` is run by `cargo test`.
- **Stretch:** (B5) `--external-h5m` on a user-supplied real fusion model; (B6) import the h5m written by the smart-mesh DAGMC exporter (`export-dagmc`) into the `dagmc-moab` driver and check its crossing sequences equal the `facets_to_h5m` path on P1 (cross-validates the exporter against DAGMC); (B7) OpenMC CSG row on P1/P2 (the 3-6x CSG gap in the research) through the OpenMC Python API in a fourth image; (B8) through-the-C-ABI row using `libsmrt` to show the Fortran/C++ call cost on W-flight.
- **Deferred:** GPU rows (XDG GPRT), libMesh backend, mesh-tally workloads (MOC/Sn segment lists, the segment-callback API), multi-node scaling, Serpent, any hosted CI that runs the Docker rows (the user decides where the benchmark machine is).
- **Must NOT:** edit `sm-rt`, `sm-rt-api`, `sm-rt-capi` or its bench dir (blocked_on_api with a request instead); claim a speedup or put a ratio in code, docs titles or test names; commit numbers not produced by the harness; gate any test on wall-clock or rates; use `:latest` images or unpinned sources; merge x86_64 and aarch64 numbers; drop a case, a tracker or a failed agreement from the report because it looks bad; use time- or thread-based seeds; iterate a HashMap into output order.
- **Registers:** binary `smrt-bench`; result schema `smbench-result v1`; case formats `smtets v1`, `smcase.json` (plus the W3a `smfacets v1`/`smrays v1` unchanged); Docker images `smrt-bench-dagmc-moab`, `-dagmc-dd`, `-xdg`.
