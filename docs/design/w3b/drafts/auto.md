### W3b-AUTO. `sm-mesher` (L3, exists): auto scheme selection as an explainable, overridable policy

- **Finding that shapes the task.** The score table of decision 12 is already implemented: each scheme returns its own score from `applicability` (map 100/50/10, submap 80/20, pave 40, trimesh/tridelaunay 30, triadvance 20, volume map 100, sweep 60, tetmesh 10, curve equal 50), and the planner already picks the best-scoring candidate (`resolve_pass`, ties go to the earlier name in the list). What makes auto "not real" today is the policy: `sm_server::standard_schemes` sets strict lists `curve [equal]`, `surface [map]`, `volume [map]`. A top-level face or volume that no parent imposes on therefore sees one candidate: map, or `NoApplicableScheme`. Sweep and tet are never auto-selected. Under a parent's imposition the whole registry is scored already (list, then the rest in name order). This task changes the policy, makes it user-overridable and replayable, and proves the consequences. It does not change any score or the planner.
- **Deps:** sm-core, sm-topo-api, sm-model-api, sm-mesh-api, sm-mesh, sm-scheme-api (`AutoPolicy::new`, `SchemeRegistry::{set_auto, auto, get, of_dim}`, `Selection`), sm-op-api, sm-layer-api, rayon, serde, schemars. Dev: sm-testkit, sm-scheme-api[stubs]. Do NOT depend on any scheme crate or sm-server (sm-mesher names schemes by string only, as the planner does for `"sweep"` and `"map"`).
- **Contract batch (running, do not re-request):** `Driver::mesh_from_plan` (mesh.run plans once; this task adopts it only if it has merged, else leaves `mesh.run` as is), `SchemeNote`/`Patch::notes`.
- **Before and after (ruling R1, see Open).**
  - Before (standard registry): unconstrained face: `map` or error. Unconstrained volume: `map` (six topological faces) or error. A face under a parent: full registry scored.
  - After: surface `[map, submap, pave, trimesh]`, volume `[map, sweep, tetmesh]`, curve `[equal]` (`tridelaunay`, `triadvance` stay reachable by name and under impositions). The list is the candidate set, its order is the tie-break.
  - Unchanged by construction: every target that has an intent scheme (the chain is tried first and wins, `Selection::Intent`), every decomposition piece with a `PieceShape` hint, and every face under an imposition (same candidate set, same scores).
  - Changes, exhaustively: (a) success to a different mesh: a face whose map score is 10 (a bend or reversal corner and no four-End layout) and some candidate scores above it: submap 80 when the corner sum is 4 (L, T shapes), else pave 40. Face map scores 100 and 50 are never beaten (submap is 80 or 20, pave 40). (b) error to success: faces with fewer than four corners, inner loops or embedded members; volumes that are not six-faced blocks; volumes whose map plan is infeasible and is rejected by the replan loop. (c) tie order: `trimesh` now beats `tridelaunay` (both 30, both `Method::Delaunay`) where the old implicit order picked `tridelaunay`; acceptance 9 asserts both give identical hashes. (d) `mesh.info.attempts` is nonzero for auto runs (outscored candidates are recorded as `Rejected`). Plans are not hashed (`MeshEntry::plan`), so state hashes are unaffected.
  - Explicit-scheme runs (W2 and W3a milestone, p0_rows, w3_wiring) are bit-identical. If the census (acceptance 8) moves any existing golden, STOP and escalate; do not edit the golden.
- **Scope (new file `src/auto.rs`; one registration line each in `lib.rs`; `mesh_ops.rs` limited to the two lines named below):**
  - `pub struct AutoTable { pub curve: &'static [&'static str], pub surface: &'static [&'static str], pub volume: &'static [&'static str] }` and `pub const STANDARD_AUTO: AutoTable` with the lists above.
  - `impl AutoTable { pub fn apply(&self, registry: &mut SchemeRegistry) -> Result<(), SchemeError> }` calls `set_auto` per dimension. Error `BadParams` names the missing scheme and dimension.
  - `pub fn replan_budget(n_targets: usize) -> usize = 16 + 2 * n_targets`. `mesh.run` passes it to `DriverOptions::with_max_replans`. Each volume that must fall back costs one replan (the driver reports the first failed job per replan), so the fixed 16 would make a 40-volume model fail. Only runs that previously failed can change.
  - Op `mesh.auto {curve?: [String], surface?: [String], volume?: [String], reset?: bool=false}` (`NO_OUTPUTS`): writes `intent.defaults.auto` via `AutoPolicy::new`, keeping dimensions not named. Each name must be registered for that dimension, not `copy`, no duplicates, list non-empty (`Invalid`, message says to use `reset`). `reset: true` clears the override of the named dimensions, or of all three when none is named. `["map","sweep"]` for `volume` is the hex-only policy (no tet fallback).
  - Query `mesh.auto_policy {} -> AutoPolicyInfo {curve, surface, volume: {names: [String], source: "intent"|"registry"|"all-registered"}}`: what the planner will consider, so an agent or the CLI can explain an outcome and choose a `mesh.auto` call.
  - Warning in `mesh.run` (existing `ctx.warn`): code `mesh.auto_tet`, for every volume whose plan row is `Selection::Auto` with scheme `tetmesh`, message lists the volume and the reasons of its earlier candidates from `plan.attempts` (e.g. "map: 5 faces; map needs exactly 6", "sweep: no pair of faces gives columns ...") and ends with `mesh.auto volume:["map","sweep"]` to forbid it. No warning when the winner is the first list entry.
- **Sweep source and target (companion C-SWEEP, owner `sm-scheme-sweep`, W3b micro task).** Auto uses exactly `find_columns`: the lowest-id valid pair (source is the lower face id). This is deliberate: an explicit `mesh.scheme sweep` without parameters uses the same function, and changing the pair would move explicit hashes (a box swept along x, y or z). A decomposition `PieceShape::Sweep` hint still outranks detection. C-SWEEP adds (1) a prefilter before `discover_columns` (equal vertex counts, no shared vertex) with identical results, (2) a work counter `SWEEP_DISCOVER_CALLS` (thread-local, test-only feature), (3) reason text `1-to-1 sweepable from {s} to {t} ({k} valid pairs)`, keeping the prefix `1-to-1 sweepable`. Fallback is the replan loop: a sweep whose linking faces cannot be mapped fails in requirements, is blamed and rejected, and the volume falls to `tetmesh` (or errors if the policy is hex-only).
- **Public API summary:** `AutoTable`, `STANDARD_AUTO`, `AutoTable::apply`, `replan_budget`, `MeshAuto`, `MeshAutoPolicy`, `AutoPolicyInfo`. All with rustdoc.
- **Acceptance A (this crate, stub registry; the stub scores differ from the real ones, so these test mechanics only):**
  1. `STANDARD_AUTO.apply` on a registry holding the real names is exercised in D-AUTO. Here: applying a table that names an unregistered scheme returns `BadParams` naming it, and leaves the registry's lists unchanged.
  2. `mesh.auto surface:["pave"]` on a stub brick makes `Selection::Auto` pick `pave` for an unconstrained face (stub pave 40 vs stub map 100 would have won before). `reset` restores the registry choice. The intent hash differs after `mesh.auto` and is equal after `reset` plus a replay from root. The state hash of an explicit-scheme run is identical before and after `mesh.auto` on other dimensions.
  3. `mesh.auto` rejects: unknown name, `copy`, duplicate, empty list (message mentions `reset`), a scheme of the wrong dimension (a surface name under `volume`). The state hash is unchanged after each failure.
  4. `mesh.auto_policy` reports `source` correctly in all three cases (intent override, registry list, no list).
  5. Order is the tie-break: two stub candidates with equal score win in list order, and swapping the list swaps the winner (counting stub that records `applicability` calls).
  6. Work counter: in one plan of one stub brick, `applicability` is called at most once per (target, candidate) in the resolve pass (counting stub).
  7. `replan_budget(0) == 16`, `replan_budget(40) == 96`; a stub model of 20 volumes whose first-choice scheme fails at generation meshes through the fallback within the budget (and fails with `ReplanLimit` at a fixed 16, as a negative control).
  8. `mesh.auto_tet` warning is emitted for a stub volume that falls to the tet stub and not for one that gets the first choice; its text contains the attempt reasons.
  9. Determinism (`sm_testkit::determinism::check`): `mesh.auto` then `mesh.run`, two runs, `RAYON_NUM_THREADS=1` vs default, identical state hashes and identical `Plan` (compared by serde JSON, since the plan is not hashed).
