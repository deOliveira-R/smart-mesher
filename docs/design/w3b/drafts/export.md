### W3B-EXPORT: DAGMC `.h5m` and Gmsh `.msh` 4.1 exporters (sm-meshio)

**Deps:** stage 0 (contract batch already running: `ExportResult.notes`, `SchemeNote`). Reads the existing frozen `sm-mesh-api` (`MeshRead`, `Classification`, `SetMembers`, `EdgeTable`) and, for one adapter, `sm-rt-api::FacetInput`. No other W3b task. Wiring into `sm_fem::ExportFormat`, `sm-server`, `sm-cli`, `sm-mcp` is W3-INT (see Deferred). Owns `crates/sm-meshio/` plus NEW files `tools/conformance/check_h5m.py`, `check_msh4.py`, `tools/conformance/dagmc/Dockerfile`, `tools/conformance/fixtures/ref/` (nothing else under tools/).

**Decisions (binding for this task)**
1. *HDF5 approach.* Pure-Rust minimal HDF5 writer, private module `sm-meshio/src/h5/` (`pub(crate)`, zero `sm-*` imports so it can be lifted into an `sm-hdf5` crate unchanged when VTKHDF or an ir-store profile needs it; same pattern as `sm-exodus/netcdf.rs`). NOT the `hdf5` crate: it links C libhdf5 (system or cmake build in CI), writes allocation-order and timestamp-dependent bytes unless carefully pinned, and breaks the repo's "no C dependency in the exporters" line. Licensing: our code is MIT, nothing vendored; HDF5 and MOAB formats are documented (MOAB LGPL source is read as a spec, never copied; cite file and line in `H5M_FORMAT.md`).
2. *Writer subset.* Superblock v2 (Jenkins lookup3 checksums), object headers v2 (`OHDR`), groups with compact link messages, contiguous datasets (layout v3), fixed-point, IEEE float, fixed-length string, opaque, enum and compound datatypes only as far as the reference file needs, scalar and 1-D attributes, committed datatypes if MOAB needs them. No chunking, no filters, no vlen, no timestamps (OHDR flag bit 5 clear), no creation order. Children sorted by name, addresses assigned in one deterministic layout pass. Anything else: `H5Error::Unsupported`.
3. *Crate placement.* h5m and msh4 are modules `dagmc` and `gmsh` of sm-meshio (matches ARCHITECTURE crate map). They consume `&dyn MeshRead` only, like vtu/foam. No new crate, no new contract.
4. *Reference first.* docs/research does not specify the h5m layout. Step 0 (blocking): obtain one real MOAB/DAGMC-written `.h5m` of a two-volume geometry with a graveyard (see open question), commit `h5dump -H` text plus the file under `tools/conformance/fixtures/ref/`, and write `crates/sm-meshio/H5M_FORMAT.md` from MOAB `WriteHDF5.cpp`/`mhdf.c`/`ReadHDF5.cpp`/`GeomTopoTool.cpp` and that dump (group tree under `/tstt`, node and element tables with `start_id`, set `list/contents/children/parents` encoding and flag bits, tag groups, handle width, the `NAME`/`CATEGORY` opaque size, history). If no reference file can be obtained, stop with status blocked on the user; do not guess the layout.

**Scope**
- `sm_meshio::h5` (private): `H5Writer::{new, group, dataset_*, attr_*, finish(&mut dyn Write)}`; `h5::read` (`#[cfg(any(test, feature = "testing"))]`) a minimal reader of exactly the subset written, for round-trip tests.
- `sm_meshio::dagmc`:
  - `pub struct DagmcModel { vertices: Vec<[f64;3]>, triangles: Vec<[u32;3]>, tri_surface: Vec<u32>, surfaces: Vec<DagmcSurface{id: u64, forward: Option<u32>, backward: Option<u32>}>, volumes: Vec<DagmcVolume{id: u64}>, groups: Vec<DagmcGroup{name: String, volumes: Vec<u32>}> }` (indices into the vectors; `forward` = volume the right-hand-rule normal points OUT of = IR `face_left` = rt-api `front`).
  - `pub fn model_from_mesh(mesh: &dyn MeshRead, o: &DagmcOptions) -> Result<(DagmcModel, LossReport), DagmcError>`: surfaces are faces with `face_class` = `TopoFace` that bound a cell; volumes are `cell_class` = `TopoVolume`; sense from `face_left`/`face_right` cell volumes (a skin face gives `backward = None`); interior faces inside one volume are skipped. Quad faces split on the shorter diagonal (ties: lowest vertex index); polygons of 5+ vertices fan from a new face-centroid vertex; every triangle keeps the face orientation. Groups: each cell set becomes `mat:<set name>` (option `material_prefix`, default `"mat:"`, `name_map: BTreeMap<String,String>` override); volumes in no set go to `mat:void`-free "unassigned" and are reported (`h5m.volume_without_material`).
  - `pub fn model_from_facets(f: &FacetInput, names: &BTreeMap<EntityId,String>, o: &DagmcOptions) -> Result<(DagmcModel, LossReport), DagmcError>`: same writer on sm-tess facets (the geometry the DAGMC benchmark traces, so both trackers see identical triangles). `front`/`back` map directly; `Region::NONE` becomes `None`.
  - `pub fn write_h5m(m: &DagmcModel, o: &DagmcOptions, w: &mut dyn Write) -> Result<DagmcReport, DagmcError>` and `export_h5m(mesh, o, w)` (= model_from_mesh + write). `DagmcOptions { material_prefix, name_map, graveyard: Option<Graveyard{ scale: f64 /*1.1*/, thickness_frac: f64 /*0.05*/, name: String /*"mat:Graveyard"*/ }>, faceting_tol: Option<f64>, include_curves: bool /*false: Curve/Vertex sets are stretch*/ }`, `#[non_exhaustive]`, serde `deny_unknown_fields`. Graveyard: two nested axis-aligned boxes around the mesh bbox, 12+12 triangles, own volume and surfaces, in its group; skipped if the model already has one (name match).
  - Tags and sets written per `H5M_FORMAT.md`: surface and volume entity sets with `GEOM_DIMENSION`, `GLOBAL_ID` (1-based dense by ascending model serial), `CATEGORY` ("Surface", "Volume", "Group"), `NAME` for groups (opaque 32 bytes: names longer than 31 bytes give `DagmcError::NameTooLong`, never truncation), parent/child links volume to surface, surface set contents = its Tri3 handles, `GEOM_SENSE_2` on surfaces ([forward, backward], 0 = none), optional `FACETING_TOL`. Handles ascend: nodes, then Tri3, then sets in (dim, id) order. `DagmcReport { triangles, surfaces, volumes, groups, bytes, hash: u64 }`.
  - `DagmcError` (thiserror, `#[non_exhaustive]`): `Io`, `Mesh(MeshError)`, `Unsupported(String)` (partition-classified entity, edge/vertex-only mesh, dimension-2 mesh, polyhedral face with fewer than 3 vertices), `Unclassified{ face }`, `NonManifoldSurface{ surface, edge }`, `OpenSurface{ volume, at }` (a volume's triangles do not close; reports the first open edge, no repair), `NameTooLong{ name }`, `H5(H5Error)`.
- `sm_meshio::gmsh`:
  - `pub fn write_msh4(mesh: &dyn MeshRead, o: &GmshOptions, w: &mut dyn Write) -> Result<GmshReport, GmshError>`; `GmshOptions { binary: bool /*false*/, polyhedra: PolyPolicy /*Error*/, boundary_elements: bool /*true*/, lines_and_points: bool /*true*/ }`; `PolyPolicy::{Error, Decompose, Drop}`; `GmshReport { nodes, elements_by_type: BTreeMap<u8,u64>, entities, physical_groups, loss: LossReport, bytes, hash }`.
  - Format: `$MeshFormat 4.1 {0|1} 8` (binary: little-endian, int 1 check word), `$PhysicalNames`, `$Entities` (bounding boxes from member nodes; volume-to-surface boundaries derived from face senses with signed tags; curve-to-point boundaries from vertex classification when present, otherwise empty plus `msh.entity_boundaries_partial`), `$Nodes`, `$Elements`; ASCII reals shortest round-trip, so bytes are deterministic. No `$Periodic`, `$NodeData`, `$PartitionedEntities`.
  - Entities and the msh4 quirk: physical tags attach to ENTITIES, not elements. Entity key = (classification entity, tuple of physical-set memberships); each distinct key is one Gmsh entity, tags ascending per dimension in (model id, signature) order. A cell set that cuts a `TopoVolume` therefore creates extra discrete volumes (`msh.entity_split`, Info). Node entity = `vertex_class` entity (each node exactly once).
  - Physical groups: cell sets to dim 3, face and side sets to dim 2 (side orientation dropped: `msh.side_orientation_dropped`), vertex and point sets to dim 0; tag = set label if present else next free per dimension; duplicate label in one dimension is `GmshError::BadLabel`. Names with `"` are `BadName`.
  - Types: Tet 4, Hex 5, Wedge 6, Pyramid 7, Tri 2, Quad 3, line 1, point 15; corner order is the `smartmesh.nodes.v1` = Gmsh order (decision 3); verified by acceptance 7, not assumed. High-order cells write their corner types plus `msh.high_order_dropped` (degree-2 emission is deferred). Polyhedra (docs/design/w3/gmsh-polyhedra.md: types 34/35 are dropped by msh4 and unreadable): `Error` returns `GmshError::PolyhedraUnsupported{ count, hint: "use openfoam, vtu or exodus" }`; `Decompose` splits each polyhedron into tets (one new node at the cell centroid, one at each polygonal face centroid, deterministic ids after the original nodes), allowed only when every neighbour across a polygonal face is also decomposed, else `NonconformingDecomposition{ face }`; `Drop` omits them with `msh.poly_dropped` severity Dropped. Loss codes `msh.*` and `h5m.*` are stable.
  - `pub fn parse_msh4(bytes:&[u8]) -> Result<Msh4Data, GmshError>` (ASCII and binary), internal for round-trip tests, documented as not a general reader.

**Acceptance (all analytic or against external readers)**
1. Fixture `tet_block_two_volumes([4,4,4],[0.25;3],split=2)` (two boxes, shared interface): `h5m` read back with `h5::read`: triangle count, vertex count, 2 volumes, surface count and each surface's area equal the analytic box faces to 1e-12 relative; interface surface has `[forward, backward]` = both volumes, outer surfaces `[vol, 0]`.
2. Sense: for every triangle, the point `centroid + 1e-6*normal` lies outside the forward volume's box and inside the backward volume's box (analytic box test); signed volume by the divergence theorem over a volume's surfaces with sense equals the box volume to 1e-12.
3. Closed volumes: `model_from_mesh` followed by an edge-use count gives every edge of every volume used exactly twice with opposite directions; a mesh with one deleted skin face gives `OpenSurface` naming that edge.
4. Quads and polygons: `hex_block_two_volumes` (new fixture) gives triangle count = 2 x quad count; the fan fixture (`hexagonal_prism`) gives total area exact to 1e-12 and still closed volumes.
5. Graveyard: with `graveyard` set, the bbox of the inner box equals mesh bbox x scale, group `mat:Graveyard` holds only the graveyard volume, volumes closed, no triangle overlaps the model.
6. `model_from_facets` on an sm-tess sphere-in-box facet set matches `model_from_mesh` semantics: closed volumes, senses from `front/back`.
7. msh4 round trip (`parse_msh4`, ASCII and binary identical content): node count, per-type element counts, per-entity counts, physical group names and tags; total volume by element Jacobians equals the analytic volume to 1e-12 for hex, tet, wedge and pyramid fixtures (`single_*`, `mixed_all_shapes`); all element signed volumes positive (this fixes the Gmsh node order). Cell set cutting a volume gives the documented split entities.
8. Polyhedra: default policy returns `PolyhedraUnsupported` on `dual_patch`; `Decompose` conserves volume to 1e-12 relative on planar-face polyhedra and returns `NonconformingDecomposition` on a hybrid poly/hex face; `Drop` reports the exact count.
9. Determinism: each exporter run twice and with `RAYON_NUM_THREADS=1` vs default gives byte-identical output (hash compared); h5 writer output has no timestamps, and `h5py` metadata of two runs differs in nothing.
10. Property tests (`sm_testkit::strategies::config(n)`) over random block sizes and splits: closed volumes, sum of surface areas, `parse_msh4` round trip.
11. Error paths: no `unwrap` on input paths, typed errors, rustdoc on all public items; `cargo clippy -p sm-meshio -- -D warnings`. A corrupted-input test for `h5::read` and `parse_msh4` never panics.
12. Conformance (not in ci.sh; `tools/conformance/check_h5m.py`, `check_msh4.py`, driven by `SM_CONFORMANCE=1 tools/conformance.sh --only dagmc|gmsh`; external tools judge exporters only, a fixture failing `smesh validate` is reported as OUR BUG and skips them):
   - Tier A (pip, always in the venv, add `h5py`, pin `gmsh==4.15.2` already noted): h5py opens the h5m (independent HDF5 library validates superblock, checksums, layout), tree and dataset shapes diffed against the reference dump; counts and sense table checked. Gmsh python: `gmsh.open`, `getNodes`, `getElements`, `getPhysicalGroups`, `getEntitiesForPhysicalGroup`, `getJacobians` (all determinants positive, sum equals analytic volume to 1e-10), and a Gmsh re-save as msh4 round trips counts. `meshio` reads the msh4 and agrees on cell blocks (hex/tet/wedge/pyramid).
   - Tier B (Docker, image `tools/conformance/dagmc/Dockerfile` from conda-forge `moab`, `dagmc`, `pydagmc`; same skip rules as OpenFOAM, exit 3 on missing unless `SM_CONFORMANCE_ALLOW_SKIP=1`): `mbconvert in.h5m out.vtk` succeeds; `pydagmc.Model` lists the volumes, material groups and surfaces with our counts; DAGMC `init_OBBTree` succeeds, `point_in_volume` for 1e3 seeded points matches the analytic box membership, `ray_fire` distances from seeded rays match analytic chord distances to 1e-9, graveyard hit terminates. Mandatory when the image is present.

**Must NOT**
- Edit any frozen contract, other crates, root Cargo.toml, CI, `tools/ci.sh` or `tools/conformance.sh` (the `--only dagmc|gmsh` hook is a W3-INT edit; this task ships the check scripts and a documented stub invocation).
- Add the `hdf5` crate, `libc`/`unsafe`, C dependencies, or a time/thread-dependent byte.
- Repair, snap, merge or weld geometry to make a volume closed: report `OpenSurface`. No tolerance constants in the exporters.
- Truncate a name, silently skip a polyhedron, or silently change an entity split.
- Wall-clock gates (bench `criterion`, record only: 10^6 tets to h5m and to msh4 ASCII/binary, bytes/s, in DESIGN.md).

**Deferred (one line each in DESIGN.md)**
Curve (Edge2) and Vertex entity sets in h5m (`include_curves`); h5m reader or import; CAD names/colors from STEP to groups; DAGMC metadata for `mat:` density or temperature tags; msh4 degree-2 elements, `$Periodic`, `$PartitionedEntities`, `$NodeData`; msh2.2 writer; MED and CGNS; `sm-hdf5` crate extraction when VTKHDF or an ir-store HDF5 profile needs it; mapping `Partition*` classification to parent `Topo*` entities (an sm-fem lowering step); pydagmc-based watertightness repair comparison (our meshes are watertight by construction, so there is nothing to compare except DAGMC's `make_watertight` on third-party files).
