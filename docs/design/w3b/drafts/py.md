### W3B-PY. `sm-py` (L6, new): Python bindings (`import smartmesh`), typed op execution, queries, numpy mesh tables

- **Deps.** Internal normal deps are sm-server (`Server`, `standard()`, `InputRef`), sm-protocol (`Request`, `Envelope`, `RpcError`, `Endpoint`), sm-core (`EntityId`, `Hash256`), sm-op-api (`State::layer`), sm-layer-api (`MeshLayer`), sm-mesh-api with feature `bytemuck` (`MeshRead`, `Coords`, `TopologyColumns`, `CellShape`), plus sm-engine types re-exported by sm-server. Do not depend on sm-mcp, sm-cli, sm-lang directly, sm-meshio or any L3 crate. External: pyo3 and numpy (rust-numpy), both optional behind feature `python`, serde_json, thiserror, bytemuck. Pins come from the orchestrator's skeleton `Cargo.toml` and `Cargo.lock`. Dev: sm-testkit, proptest. Python side: numpy only at run time. Tests use pytest, mypy and maturin.
- **Stage-0 items used by name (no ACR).** The sm-py skeleton and its workspace membership. The root `Cargo.toml` pins for pyo3 and numpy (abi3, no `extension-module` by default). The concepts.yaml edges below. A CI entry that calls `crates/sm-py/ci/py.sh` (the orchestrator wires it; this task ships the script).
- **Design rulings (binding).**
  1. **Sync API, thread-safe.** The protocol is a single-writer dispatcher and ops are deterministic and sequential, so there is no `async` API. `Session` wraps `Mutex<Server>`. Every native call releases the GIL for its duration (`Python::detach`, `allow_threads` in older pyo3; follow the pin). Concurrent callers serialize on the mutex. `await asyncio.to_thread(s.apply, ...)` is the documented async pattern. A poisoned mutex or a caught panic becomes `SmartMeshError(kind="internal")`, never pyo3's `PanicException` (it derives `BaseException` and would kill a notebook). All entry points go through one `guard()` wrapper that uses `catch_unwind`.
  2. **Thin typed layer over the JSON protocol, native code only where needed.** `core.rs` (pure Rust, no pyo3 types, tested by `cargo test`) owns `Host` and the mesh table snapshot. `py.rs` (`cfg(feature = "python")`) is the binding glue. The typed API, id handling, error classes and `.smsh` reader are pure Python on top of the `Transport` protocol (`request(method: str, params: Any) -> Any`). The native in-process transport is one implementation. A later WebSocket client (`smesh serve --ws`) is a second one with no change to the typed layer.
  3. **Cubit parity plus typed ops.** Cubit's Python API is read-only plus `cmd`. Ours has `Session.cmd(text)` (runs command-language text, returns `ScriptResult`) and typed op execution that goes through `Request::Apply`, so Python and the CLI/MCP share one code path and one state hash.
  4. **No `unsafe`, zero copy where it is safe.** In process, each mesh table is one `memcpy` of a `bytemuck::cast_slice` view into an owned `Vec` that numpy adopts without a second copy (`IntoPyArray`). The returned arrays are snapshots (read-only flag set), not views into the live store, so later ops cannot change them. The true zero-copy path is the file path: `smartmesh.smsh.open(path)` maps a `.smsh` with `mmap` and returns read-only `numpy.frombuffer` views. This is plain Python, so the layer needs no `unsafe`. Borrowing the store's memory (`PyArray::borrow_from_array`) would need `unsafe` outside sm-rt-capi, so it is not done (see open question 1).
- **Scope, mandatory.**
  1. `core.rs`: `Host { server: Mutex<Server> }` with `Host::memory() -> Result<Host, HostError>`, `Host::open(dir: &Path, create: Option<&str>) -> Result<Host, HostError>`, `Host::call(&self, method: &str, params: &serde_json::Value) -> Result<serde_json::Value, RpcError>` (builds the JSON-RPC text and goes through `Endpoint::handle_text`, exactly as `InProcess` does, so errors and hashes match remote clients), `Host::stage(&self, bytes: &[u8]) -> Result<InputRef, HostError>`, `Host::mesh_tables(&self, mesh: Option<EntityId>) -> Result<MeshTables, HostError>`. `None` means the only mesh; zero or several meshes give `HostError::NoMesh` / `AmbiguousMesh`, the same words as the export error. `MeshTables` is plain owned data using the `.smsh` array names, dtypes and meanings from `SMSH_FORMAT.md` §3.1: `x,y,z` f64; `vertex_ids,face_ids,cell_ids` u64; `face_offsets` u64; `face_vertices,face_left,face_right` u32 (right `0xFFFFFFFF` = none); `face_kind` u8; `cell_face_offsets` u64; `cell_faces` u32 (`face << 1 | side`); `cell_shape` u8 (codes 0 tet, 1 hex, 2 wedge, 3 pyramid, 4 polyhedron, 5 tri, 6 quad, 7 polygon); `cell_corner_offsets` u64; `cell_corners` u32; `cell_parent` u32; `cell_active` u8; `class_entities` u64; `vertex_class,face_class,cell_class` u32. Edges, sets, tags, high-order and parametric tables are Stretch. Table naming and dtype equal the file, so a session mesh and a file mesh are interchangeable.
  2. `errors.rs` and `errors.py`: `SmartMeshError(Exception)` with `.code: int`, `.kind: str` (the contract `RpcError.kind` string, passed through untouched), `.message`, `.data`. Subclasses by JSON-RPC code: `ParseError`, `InvalidRequestError`, `MethodNotFoundError(SmartMeshError, LookupError)`, `InvalidParamsError(SmartMeshError, ValueError)`, `InternalError`, `ApplicationError`. `ScriptError(ApplicationError)` for kind `script-error` carries `.result: ScriptResult`, `.rendered`, `.error_code`. Python-side validation failures (NaN or inf float, unknown id spelling, wrong type) raise `InvalidParamsError` before any call, never a bare `TypeError` from the middle of the layer.
  3. `ids.py`: frozen `EntityId` (`kind: str`, `serial: int`, `raw: int`, `__str__` canonical `Kind#serial`, `__hash__`, total order by `raw`, `EntityId.parse(str)` accepting the canonical and command-language spellings through the Rust parser, `from_raw`). Every API accepts `EntityId | str` wherever a param is an entity; serialization to op params always emits the canonical text.
  4. `session.py`: `Session.memory()`, `Session.open(path, create=False)`, `Session.create(path, name)`, `close()` and context manager; `apply(op, /, **params) -> ApplyResult`; `query(name, /, *, at=None, **input) -> Any`; `cmd(text) -> ScriptResult`; `run_script(text, *, path=None, includes=None) -> ScriptResult`; `batch()` context manager that collects typed calls and applies them as one `core.batch` node (params per the registry batch schema); `status() -> Status`; `hash(at=None) -> StateHash` (`state: str` hex, `layers: dict[str, str]`); `undo()`, `redo()`, `checkout(rev)`, `branch(name, at=None)`, `log(limit, from_=None)`; `save()`; `catalog() -> Catalog`; `stage_file(path) -> InputRef`; `import_step(path, **kw)` (stage, then `model.import_step {source: {sha256}}`); `export(path=None, *, format=None, mesh=None, provenance=False, inline=False) -> ExportResult` (bytes in `.data` when inline); `meshes() -> list[MeshInfo]` (via the `mesh.info` query); `mesh(id=None) -> Mesh`.
  5. Typed results are frozen dataclasses built from the protocol JSON: `ApplyResult{node, state, created, retired, outputs: dict[str, list[EntityId]], diagnostics, raw}`, `ScriptResult`, `Status`, `ExportResult` (with `files`, and `notes` once the contract batch lands), `Catalog`. Unknown JSON fields are kept in `.extra` (forward compatible with additive contract changes), never raise.
  6. Generated typing. `tools/gen_stubs.py` (this crate) reads the `catalog` JSON Schemas and writes `python/smartmesh/ops.pyi` (one typed keyword-only signature per op, with the op's `OUTPUTS` documented, `Literal` for enums, `EntityId | str` for entity-kind params). At run time `Session.__getattr__` exposes the same ops as `s.model.create_brick(...)`, built lazily from the live catalog, so ops added by any W3b plugin appear without touching this crate. Queries get `s.q.<name>(...)` the same way. The stub file is committed and a test fails if regeneration differs (drift check). Positional-argument ops (the `POSITIONAL` marker) are keyword-only in Python.
  7. `mesh.py`: `Mesh` with the tables above as read-only numpy attributes, plus pure-numpy helpers: `points` (N,3 f64, built from x,y,z), `n_cells`, `cells() -> dict[str, tuple[np.ndarray, np.ndarray]]` (shape name to `(cell_indices, corners[n,k])`, meshio-style blocks; polyhedra give only the indices), `cell_faces_split()` returning `(face_index, sign)` arrays, `class_entity_ids(kind: "vertex"|"face"|"cell") -> list[EntityId]`. `Mesh.from_smsh(path)` uses `smartmesh.smsh.open`.
  8. `smsh.py`: numpy reader for `.smsh` 1.x (mmap, header check per `SMSH_FORMAT.md` §1, CRC verification optional, read-only `frombuffer` views, refuses `nbytes != prod(shape) * sizeof(dtype)`). It is a second, independent reader (the existing one is `crates/sm-meshio/readers/smsh.py`, stdlib only) and doubles as a conformance check of the writer.
  9. Packaging. `pyproject.toml` for maturin (mixed layout, `module-name = "smartmesh._native"`, `python-source = "python"`, features `["extension-module"]`), abi3 for Python >= 3.10, numpy >= 1.23 and < 3, `py.typed`, `_native.pyi`. `Cargo.toml` has `crate-type = ["cdylib", "rlib"]` and feature `python = ["dep:pyo3", "dep:numpy"]`, so a plain `cargo build/test/clippy` at the workspace root never needs a Python. `ci/py.sh` creates a venv under `target/`, runs `maturin develop --features extension-module`, then pytest, mypy, `cargo clippy -p sm-py --features python -- -D warnings`, and builds one wheel per platform for the CI artifact (manylinux_2_28 x86_64/aarch64, macOS arm64/x86_64, Windows x86_64). Publishing to PyPI is not done.
  10. Docs in the crate: `DESIGN.md` (rulings 1-4, error table, GIL and fork policy, `.smsh` zero-copy story), `README.md` (quickstart, the ARCHITECTURE §8 slice in Python), `W3_REPORT.md`.
- **Acceptance** (Rust side by `cargo test -p sm-py`; Python side by `ci/py.sh`; analytic checks, no wall-clock gates).
  1. Slice parity: `brick 10 10 10`, `size 1`, `mesh`, `block 1 add volume 1` run (a) as one `cmd` per line, (b) as typed ops `s.model.create_brick(...)` etc., (c) as `run_script` give the same state hash, equal to the hash of the same script through `smesh run` and through the MCP tool path (`sm-cli` dev-style test in a Python subprocess against the built `smesh`). Undo, redo and `checkout` to a branch point restore equal hashes.
  2. Mesh tables, analytic: the 10-cube at size 1 gives 1331 vertices, 3300 faces, 1000 hex cells, `cells()["hex"]` shape (1000, 8), `bbox(points) = [0,10]^3` exactly, every `cell_shape == 1`, `cell_faces` has 6 entries per cell, and the Euler count `V - E + F - C = 1` with E computed in numpy from the face loops (3630). For each face, `face_left < face_right` where both exist (the ordering rule of `SMSH_FORMAT.md`).
  3. Session vs file: after `export(path, format="smsh")`, every always-present table of `session.mesh()` equals the table of `smsh.open(path)` byte for byte. The file arrays are `mmap`-backed and read-only (`np.shares_memory` with the mapped buffer, `flags.writeable` is False). Session arrays have `OWNDATA` or a bytes-owning base and are read-only. After a later `mesh.delete` the earlier `Mesh` object is unchanged (snapshot semantics).
  4. Polyhedra: `mesh.to_poly` on a tet block (testkit/`model.create_brick` + tetmesh as available on main) gives `cell_shape == 4` rows with empty `cell_corners` rows; the sign and face arrays reproduce each cell's volume by the divergence formula in numpy to 1e-12 relative (analytic: block volume).
  5. Errors: each of `RpcError::{parse, invalid_request, method_not_found, invalid_params, internal, application}` maps to its documented class and the `RpcError.kind` string reaches `.kind` unchanged. A failing script statement raises `ScriptError` whose `.result.state` is the hash of the partial state (ops before the failure stay applied). NaN, inf, an unknown id spelling and a wrong-kind id each raise `InvalidParamsError` without a timeline node being added (state hash unchanged). A forced Rust panic (test hook `smartmesh._native._panic()`, compiled under `cfg(test)` or feature `test-hooks`) raises `InternalError`, and the session stays usable.
  6. Ids and typing: `EntityId.parse` round-trips every kind of the `ENTITY_ID_PATTERN` sample set and both spellings; entities returned in `ApplyResult.outputs` can be passed back unchanged. `mypy --strict` passes on `tests/typing_example.py`, which calls `s.model.create_brick(width=..)`-style ops from the committed `ops.pyi`. The drift test (regenerate and diff) passes. Misspelled keywords in a typed call are type errors in mypy and `InvalidParamsError` at run time.
  7. Determinism (CLAUDE.md): two runs, and `RAYON_NUM_THREADS=1` against default (subprocess), give the same state hash and byte-identical table bytes (sha256 over all tables). A Python thread pool of 8 threads doing queries and one writer thread gives the same final hash as the serial run, with no deadlock and no data race (the GIL is released while waiting on the mutex).
  8. STEP: `s.import_step(sm_testkit w3a part)` (path from an env var set by `ci/py.sh`, from `crates/sm-testkit/data/step/w3a_part.step`) imports 3 bodies with volumes [1200, 200, 600] read through a query, state hash equal to the inline form and the sha256 form (`stage_file` + `{sha256}`).
  9. Rust side: `Host::call` returns the same JSON as `InProcess::send_text` for every method of `sm_protocol::METHODS`; `mesh_tables` on a testkit mesh equals the `MeshRead` it came from (all tables, proptest with `sm_testkit::strategies::config(n)` over lattice sizes). `NoMesh` and `AmbiguousMesh` are tested. `rg unsafe crates/sm-py/src` is empty (a test scans the source).
  10. Packaging: in a fresh venv, the wheel installs, `import smartmesh` works with only numpy present, `smartmesh.__version__` equals the crate version, `python -W error -c "import smartmesh"` is clean, and `pip install` then the acceptance 1 slice run from the installed wheel (not the source tree).
  11. Recorded, not gated: a `bench/tables.py` run on a 10^6-hex mesh records the table snapshot time, the bytes copied (sum of `nbytes`) and the `smsh.open` map time in `DESIGN.md`.
- **Stretch.** Edges, sets, tags, high-order and parametric tables on `Mesh` (names per `SMSH_FORMAT.md` §3.2); `Mesh.to_meshio()` and `Mesh.to_pyvista()` with optional imports; `Session.tracker(mesh)` exposing `sm-rt-api` `Tracker` queries as numpy batches (needs the W3b sm-rt tasks); `_repr_html_` summaries for notebooks.
- **Must NOT:** write `unsafe` (pyo3 macro expansion is the only exception, see open question 2); edit another crate, the root `Cargo.toml`, `Cargo.lock`, CI or docs outside `crates/sm-py/`; depend on sm-mcp, sm-cli or an L3 crate; keep global module state (two `Session`s must be independent); mutate state outside `Request::Apply` / `script.run`; read the clock, environment or cwd in a library path (paths come from arguments); iterate a `HashMap` into output; hand out arrays that alias live store memory; use `unwrap` on input paths; call a mesh-checking external tool; duplicate op schemas or error codes by hand (they come from the catalog and the contract `code()` strings); add a hard Python dependency besides numpy.
- **Deferred.** A remote `smartmesh.connect(url)` client (waits for `smesh serve --ws`); borrowed zero-copy views of the live store (needs the `unsafe` ruling); Ctrl-C cancellation of long ops (needs a cancel handle on `Server`, the engine has `Control` but the server does not expose it); meshes at an older revision (`at=`) without exporting; async-native API; positional op arguments; PyPI publishing and a release process; Python tracking API beyond Stretch; script record (`PARITY` A, its own W3b task; Python picks it up through the catalog).

#### registers
Python package `smartmesh` (distribution `smartmesh`, native module `smartmesh._native`): classes Session, Mesh, EntityId, ApplyResult, ScriptResult, Status, ExportResult, Catalog, StateHash, InputRef, MeshInfo; modules smartmesh.smsh, smartmesh.errors; generated ops.pyi. No ops, queries, layers or plugins.

#### ACRs
None. Everything needed is on main: `Server::call` / `workspace()` / `stage_input`, `State::layer::<MeshLayer>()`, `MeshRead::{coords, columns}`, the `bytemuck` feature of sm-mesh-api (decision 13), `ExportResult.inline`.

#### depends
[] (no hard dependency: new ops from other W3b tasks, `mesh.plan`, surface-only `mesh.run`, `ExportResult.notes`, appear through the catalog and `.extra`)

#### baseline
Conceptually the same as Cubit's Python API (`cubit.cmd` plus read-only getters) and Gmsh's Python API (in-process module driving a kernel, numpy arrays out). It differs in four ways. Ops are typed and executed (not only `cmd` strings), and their signatures and stubs are generated from the same JSON Schema the MCP tools use. Sessions are objects, so several can coexist, and they are replayable timelines with a state hash that equals the CLI's and MCP's. Mesh tables are polyhedral CSR tables with the `.smsh` names, identical in memory and in the file. Errors carry the contract codes. The advantage is that notebooks, the CLI and agents reproduce each other bit for bit, and the transport-code side gets `mmap` zero-copy reads with an independent reader.

#### risks
- pyo3 macros expand to `unsafe`, and the workspace rule allows `unsafe` only in sm-rt-capi. If `#![deny(unsafe_code)]` rejects the expansion, one `#[allow(unsafe_code)]` on the `#[pymodule]` item is needed, which is an orchestrator ruling.
- `Server` must be `Send` for `Mutex<Server>` to be `Sync` (pyo3 requires it for `#[pyclass]`). `Plugin` has no `Send` bound in the trait; the `Workspace` builder boxes plugins, so check at skeleton time. If it fails, the fix is in sm-server/sm-op-api (the task returns `blocked_on_api`), not `unsendable`, which would break threaded use.
- Linking: a cdylib with `extension-module` cannot be linked by `cargo test` on Linux, hence the `python` feature split and the logic in pure-Rust `core.rs`. The orchestrator must keep `--workspace` commands free of `--all-features`.
- Rayon plus `fork`: a pool created before `os.fork` is dead in the child. Documented: use `spawn`. Tested by a spawn-based `multiprocessing` smoke test only.
- Rust-numpy and pyo3 versions must move together, and numpy 2 ABI differs from 1.x; abi3 plus the `numpy` crate pin is verified in `ci/py.sh` against both numpy 1.26 and 2.x.
- The cell shape code table is duplicated from the `.smsh` writer (SMSH_FORMAT.md). Acceptance 3 catches drift against the real export; a future `MeshRead` code accessor would remove it.
- The generated stubs depend on `catalog` schemas being precise (`x-entity-kind`, enums). Ops with loose schemas get `Any` params, never a wrong type.

#### open
1. Allow a single audited `unsafe` module (`views.rs`, SAFETY comments, owner pyclass holding an `Arc` of the immutable state) for borrowed zero-copy in-process views? Recommendation: no for W3b. One memcpy per table is a few milliseconds per 10^6 cells, and the file path is already zero copy.
2. Accept pyo3 macro-expanded `unsafe` as outside the "unsafe only in sm-rt-capi" rule, with `#![deny(unsafe_code)]` plus one allow on the module item if the compiler needs it? Recommendation: yes, and add the sentence to CLAUDE.md.
3. Distribution and import name `smartmesh` (ARCHITECTURE §2) and minimum Python 3.10? Recommendation: yes to both; do not publish to PyPI until the user decides.
4. Should `Session` expose both `s.apply("model.create_brick", ...)` and `s.model.create_brick(...)`? Recommendation: both (the second is the typed one).

#### escalation
Open questions 1-2 need an orchestrator or user ruling before the worker starts. The `Send` check on `Server` and the `unsafe_code` lint result are skeleton-time facts the stage-0 orchestrator should verify with a compile-only `cargo check -p sm-py --features python`.
