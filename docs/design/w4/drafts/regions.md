# W4 REGIONS: one region per lattice position, times pin subdivision (ruling D9)

> Planning draft (W4), written by the W4 re-planner at `9cac369` after the user rulings (`../rulings.md` D9). Line numbers are against `9cac369` (code identical to `d2f4803`). Not critiqued by a second agent; the plan (`../plan.md` §4.1 W4-REGIONS-CUT, W4-REGIONS-SPLIT and §3 W4-0.3, W4-0.6) is the binding text.

## Goal

D9: a lattice element can be defined once ("all pins equal", one region per material) and the export asked to split it into one region per lattice position. Pins can also be subdivided into radial rings and azimuthal sectors for depletion, so a split lattice gives `positions x subdivisions` regions. The split is an export option over both. Region names are structured (material, lattice position, ring, sector), and the same split is written to `.smsh` cell sets (what the transport code reads first, D2) and to `.smrt` regions. Commercial depletion needs this at 17x17 and beyond, so the counts must scale (289 pins x 10 rings x 8 sectors = 23 120 fuel regions per assembly).

## Findings (what is true today, with file:line)

1. **`.smrt` regions are the blocks.** `smrt_regions` names regions after the block sets of the lowered mesh when every cell is in a block, else falls back to volume ids with the `smrt-region-names` warning (`crates/sm-server/src/mesh_export.rs:179-210`). The rule passed to sm-rt is `RegionRule::ByCellSets(names)` (`:209`).
2. **sm-rt already takes any list of cell sets as regions.** `ByCellSets` makes one region per named cell set, and an overlap or an uncovered cell is a fatal build issue (`crates/sm-rt/src/build.rs:112-133`). `RegionRule` is `#[non_exhaustive]` with two variants (`crates/sm-rt-api/src/input.rs:204-213`), and sm-rt's match has a wildcard arm that returns `Unsupported` (`build.rs:134`). So a new variant is additive.
3. **Regions can already carry integer tags, end to end.** `RegionInfo.tags: Vec<(String, i64)>` (`crates/sm-rt-api/src/state.rs:265-290`); the `.smrt` image writes a tags section only when some region has tags, "so tag-free images keep their bytes" (`crates/sm-rt/src/image.rs:20`, `:201-212`, read back at `:430`); the C ABI reads them with `smrt_region_n_tags` / `smrt_region_tag` (`crates/sm-rt-capi/include/smrt.h:252-256`). No producer sets tags today. The backlog entry "`RegionInfo.tags` not in cache images and hashed without a presence marker" (`docs/design/w3/backlog.md:98`) is at least partly stale (the image part is done); the hash part is checked by W4-0.3.
4. **The lowering makes the mesh sets.** `sm_fem::lower` adds block, sideset and deck-face sets (`SetOrigin`, `crates/sm-fem/src/lower.rs:20-27`) and returns them with the mesh (`Lowered`, `:46-56`). `.smsh` writes the mesh's cell sets and per-set element types (`crates/sm-meshio/src/smsh/format.rs:233-240`, `writer.rs:70-71`). A set name space is shared by all sets of a mesh (the invariant comment at `mesh_export.rs:184-187`).
5. **Export options are a free object validated per exporter.** `Request::Export.options: Option<Value>` (`crates/sm-protocol/src/request.rs:231-234`), checked by `options_map(name, options, allowed)` in sm-server (`mesh_export.rs:39-51`). The protocol doc says `smrt` "takes none" (`request.rs:27`, `:232`). A new option key needs no protocol type change.
6. **Nothing records which lattice position a volume came from.** `model.copy` is a deep copy and "a copy has no lineage link to its source beyond `Created`"; colors and groups are not copied (`crates/sm-model/src/copy.rs:1-10`, `MAX_COPIES = 4096` at `:25`). The CSG IR knows lattice indices (rectangular only: `Lattice { lower_left, pitch, dims, universes, outer }`, `crates/sm-csgio/src/ir.rs:188-200`), but the B-rep import does not exist yet (W4-CSG-CORE).
7. **The model API has the index types but no place for provenance.** `SlotIx` (`crates/sm-model-api/src/instancing.rs:43-70`, canonical order `(k, j, i)`), `HexOrient` (`:102-111`) and `Layout::{Cartesian, Hex}` with `offset` and `contains` (`:117-135`, `:199-222`) exist for real instancing, which no op creates and which sm-boolean refuses (`drafts/csgbrep.md` finding 8). The `Model` tables are fixed (`crates/sm-model-api/src/model.rs:50-63`); `canonical_visit` destructures `Model` exhaustively, so a new field is a compile error until it is hashed (`crates/sm-model-api/src/canonical.rs:212-216`). The precedent for adding a table without moving hashes is `ColorMap`: a later field is `skip_serializing_if` empty and "enters `canonical_visit` only when non-empty" (`instancing.rs:261-264`).
8. **Volume tables follow cuts.** `Model::apply_lineage` re-keys `volume_color` through a transitive `Resolver` (one old volume to all live children) and refuses volumes with an active decomposition (`model.rs:327-378`). A provenance table can reuse the same path, so cutting a tagged pin into rings keeps its lattice position.
9. **No ring or sector op exists.** Cylinder and plane webcuts exist (`model.webcut_cylinder` with any axis and centre, `crates/sm-boolean/src/ops.rs:566-600`; plane webcut in the same file). Rings and sectors are therefore ordinary webcuts; what is missing is an op that does them as a unit and records which piece is which.
10. **The backlog trigger has fired.** "Region granularity of the `.smrt` ... W4 trigger: the first request for it" (`docs/design/w3/backlog.md:102`); D9 is that request.

## Design

### R1. Where the indices live: one provenance table in the model (ACR-REGIONS, `sm-model-api`)
Two additive tables in `Model`, both `#[serde(default, skip_serializing_if = "BTreeMap::is_empty")]` and emitted by `canonical_visit` **only when non-empty**, after the decomposition table, under new tags 13 and 14 (the `ColorMap` precedent, finding 7). An empty model hashes and serializes exactly as before.
- `lattice_frames: BTreeMap<String, LatticeFrame>`. `LatticeFrame { layout: Layout, origin: Point3, parent: Option<String> }`, `#[non_exhaustive]` with a constructor. It reuses `Layout` (Cartesian or Hex with `HexOrient`) and `SlotIx` (finding 7); it is provenance only and is unrelated to instancing (no prototype, no flatten). Slot `(0,0,0)` is centred at `origin` (the `Layout::offset` convention). `parent` nests frames (core > assembly > pin); a cycle or an unknown parent is refused.
- `region_tags: BTreeMap<EntityId /* TopoVolume */, RegionTag>`. `RegionTag { slots: BTreeMap<String, SlotIx>, ring: Option<SubIndex>, sector: Option<SubIndex> }` with `SubIndex { index: u32, count: u32 }`, both `#[non_exhaustive]` with constructors.
- Methods: `define_lattice_frame(name, frame)`, `lattice_frame(name)`, `lattice_frames()`, `set_region_tag(volume, tag)`, `clear_region_tag(volume)`, `region_tag(volume)`, `region_tags()`, and the pure helper `LatticeFrame::locate(p) -> Option<SlotIx>` (Cartesian: nearest centre by rounding `(p - origin) / pitch`; Hex: nearest centre in axial coordinates with cube rounding; `None` outside `layout.contains`). Frame names match `[A-Za-z0-9_]+` (they appear in region names).
- `apply_lineage`: a tag follows its volume to every live child (the `volume_color` path). When a merge maps several old volumes with **different** tags onto one new volume, the new volume gets no tag (deterministic; the export then names it by material only). `check_integrity`: every slot names an existing frame and lies in its layout; `count > index`; tags key only `TopoVolume` ids.

Why a model table and not groups: groups are user-editable sets with free names, they do not follow the "one value per volume" shape, and parsing positions out of group names would be a second source of truth. Why not instancing: booleans refuse instanced volumes and nothing creates them (finding 7); the table is the provenance half of a lattice without the memory sharing, which stays W5.

### R2. Who writes the tags
- **`model.lattice_define {name, layout, origin, parent?}`** (sm-model): adds a frame.
- **`model.lattice_tag {lattice, volumes}`** (sm-model): sets each volume's slot in that frame from its centroid (`model.measure` centroid) with `LatticeFrame::locate`. A centroid outside the layout, or within `ModelTolerance::linear` of an element boundary, is a typed error naming the volume (option `outside: "error" | "skip"`, default `error`). It is geometric, so it works for any construction: `model.copy` lattices, STEP assemblies, imported decks. A full annulus has its centroid on its axis, which is its pin centre, so it lands in the right element.
- **`model.copy {..., lattice?: name}`** (sm-model): optional; after copying, runs the same tagging on the source and the copies. This is the "model.copy lattice provenance" of D9. Omitted from canonical params when absent, so existing copy histories hash as before.
- **`model.import_openmc`** (W4-CSG-CORE, sm-csgbrep): defines one frame per deck lattice (name `lat<id>`, nested by fill) and tags each placed element's volumes with the deck's own indices. The acceptance checks that these equal `model.lattice_tag` on the same volumes, and CSG-ORACLE checks them against OpenMC's lattice indices.
- **`model.subdivide_pin {volumes, axis, center, rings?, sectors?}`** (sm-boolean, new file): each selected volume must be a solid cylinder or a coaxial annulus about `axis` through `center`. `rings: {count, mode: "equal_area" | "equal_radius"} | {radii: [..]}` cuts with coaxial cylinders (equal area: `r_k = sqrt(r_in^2 + k (r_out^2 - r_in^2) / N)`); `sectors: {count, angle0_deg}` cuts with planes through the axis (`count` is 1 or even, since a plane webcut cuts both sides; odd counts are a typed error). The op knows which piece is which, so it writes `ring {index, count}` (0 innermost) and `sector {index, count}` (0 starting at `angle0`, counter-clockwise about `axis`), keeping the lattice slots the volume already had (R1 lineage). Sectors before rings or rings before sectors give the same pieces; the op fixes the order (rings, then sectors) so ids are deterministic.

### R3. The split is an export option (sm-fem lowering, sm-server)
- Option key on `smsh` and `smrt`: `"regions": {"split": [...]}` with any subset of `"lattice"`, `"ring"`, `"sector"`. Absent or `[]` is today's behaviour, byte for byte. (DAGMC and the other formats can take the same key later; not in W4.)
- Region key of a cell = (block name of its volume, then for `lattice` every slot of the volume's tag ordered outer frame to inner frame by `parent` depth, then ring, then sector), using only the requested parts. A volume with no tag in a requested part simply has no such part (the outer reflector water stays `water`).
- **Name grammar** (one function, `sm_fem::region::RegionName::{format, parse}`, round-trip tested): `<block>` then `@<frame>[i,j]` per frame (`[i,j,k]` when the layout has more than one layer), then `/r<ring>`, then `/s<sector>`. Example: `fuel@core[2,3]@asm[5,7]/r1/s2`. A block name containing `@`, `/`, `[`, `]` or `,` is refused with `region-name-reserved` when a split is requested.
- **`.smsh`**: the lowering adds one cell set per region, `SetOrigin::Region` (new variant in sm-fem), named `region/<name>` so it never collides with a block set (`fuel` the block and `fuel` the untagged remainder are different sets). Block sets and their element types stay as they are. `SMSH_FORMAT.md` gains a short section on the `region/` sets and the grammar.
- **`.smrt`**: one region per region set, named `<name>` (without the `region/` prefix), with integer tags `lat.<frame>.i`, `lat.<frame>.j`, `lat.<frame>.k` (k only for layered frames), `ring`, `ring_count`, `sector`, `sector_count`, for the requested parts only. This needs the additive rule `RegionRule::ByTaggedCellSets(Vec<RegionSet>)`, `RegionSet { set, name, tags }` (ACR in W4-0.3), because `ByCellSets` makes the region name equal to the set name and sets no tags (finding 2). The transport code then reads positions as integers through the C ABI (finding 3), not by parsing names.
- Errors: a split with blocks that do not cover the mesh is `regions-need-blocks` (no silent fallback to volume ids); region count above `u32::MAX` is impossible in practice and still checked.

### R4. Volumes and D4
Subdivided rings and sectors are B-rep volumes, so their analytic volumes are exact. With VOLFIT (D4; `mesh.preserve_volume`, W4-MESHER-LISTS), every circle moves to its own equal-area radius `r' = r sqrt((2 pi / n) / sin(2 pi / n))`, so each inscribed polygon has area `pi r^2`; an annulus between two such circles then has area `pi (r_2^2 - r_1^2)` exactly, and a sector with `n / S` intervals of each of its arcs has exactly `1 / S` of its ring. Hence every subdivided region's mesh volume is exact when `n % S == 0` on every circle. W4-REGIONS-SPLIT checks this once VOLFIT has merged (a3 or INT); before it, the check is against the polygon closed form.

### R5. Why this is better than the usual route
In the common Cubit and MOOSE workflows, per-pin and per-ring tally regions are made by hand (one block per pin) or by mesh-generator ids that are lost on export. Here one pin is defined once, the region granularity is a recorded export option, the indices are integers in the file the transport code reads, and the same split appears in `.smsh` and `.smrt`.

## Risks
1. **Merge after copying is O(F^2)** (backlog `:95`); a 17x17 subdivided lattice through `model.copy` + `merge` may be slow. Acceptance item 6 therefore tests scale at the lowering level; the full 17x17 B-rep build waits for the merge fix or CSG import.
2. **Sectors and the O-grid.** A sector-cut disk is no longer a disk, so `ogrid` does not apply to it; `hex_only` must still mesh quarter sectors (submap/pave). With `sectors.count = 4` aligned to the O-grid's quadrants a later task can map the O-grid blocks onto sectors; not in W4.
3. **Centroid ties.** A volume whose centroid lies on an element boundary (a moderator that spans elements) is refused by `lattice_tag` unless `outside: "skip"`; this is deliberate.
