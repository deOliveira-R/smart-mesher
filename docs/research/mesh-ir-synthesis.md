## 2. Is there an existing modern, versatile, well-specified format that meets our needs?

Short answer: no single format carries the requirement list (polyhedral cells first-class, mixed elements, high-order, non-conformal interfaces, material/region partitions, boundary sets, CAD association, parallel partitioning, fast large-mesh I/O). One format, CGNS, is good enough to adopt as the neutral primary interchange for the mesh layer. None is good enough as the native IR, and none reaches the neutron-transport consumers we care about.

### CGNS SIDS 4.5.2 — closest candidate; adopt as primary neutral interchange, not as IR

Has: a formal, versioned, committee-governed spec with a change process (https://cgns.org/current/CPEX.html); polyhedra as NGON_n (all faces) + NFACE_n (signed face lists) with CSR ElementStartOffset and optional ParentElements face->(cell,cell) (https://cgns.org/standard/SIDS/grid.html); declared interfaces (GridConnectivity_t with Abutting / Abutting1to1 / Overset and three donor levels) (https://cgns.org/standard/SIDS/multizone.html); Family_t indirection between mesh regions and properties/CAD; parallel HDF5 (cgp_*); broad CFD and ParaView support.

Lacks, against our requirements:
- Per-entity geometry association. GeometryReference_t under Family_t is a filename plus entity-name string (STEP-AP203/AP242 are now allowed values), surfaces only; there is no (dim, id) per mesh entity and no parametric coordinates (https://cgns.org/standard/SIDS/misc.html).
- Stable identity and ownership. Identity is positional; the SIDS has no owner-rank or ghost model.
- Interface data for polyhedral or high-order faces. InterpolantsDonor is defined only for BAR_2, TRI_3, QUAD_4, TETRA_4, PYRA_5, PENTA_6, HEXA_8; there are no overlap areas or weights; hanging nodes were rejected (CPEX0008), so a non-conformal interface on polyhedral zones carries at most CellListDonor.
- High-order beyond a closed Lagrange enum (quartic max, HEXA_125, with a SIDS/MLL inconsistency). CPEX0045 (accepted, awaiting implementation, target 5.0) adds interpolation metadata but explicitly excludes polyhedra and polygons (https://cgns.org/_downloads/01bf68322bab9d0fc99ee972efa32f34/CPEX0045_HighOrder_v3.pdf).
- A neutron-transport BC vocabulary (CFD-only BCType; BCGeneral/UserDefined escape hatch).
- Compression through the MLL (unverified; the docs say property lists are forced to defaults); a brittle history (3.4.0 shipped CPEX41 in 2019, 3.4.1 removed it, 4.0.0 reinstated it on 2020-02-17) (https://github.com/CGNS/CGNS/releases).
- Any neutronics user base; PETSc's reader explicitly rejects NGON_n/NFACE_n (https://petsc.org/main/src/dm/impls/plex/cgns/plexcgns2.c.html).

Worth tracking: CPEX0047 (quadrature), CPEX0049 (compatibility version control), and CPEX0050 (DofStorage SharedDofs/IndependentDofs, InterfaceContinuity Continuous/Discontinuous) are accepted and DG-relevant; none is in any release.

### Exodus II — mandatory export, not IR

Ubiquitous where our first consumer likely lives (Cubit, MOOSE/Griffin, Sierra, ParaView). Polyhedra are an add-on: NFACED needs NSIDED face blocks, faces are referenced by file-implicit ids spanning all face blocks (https://github.com/sandialabs/seacas/blob/master/packages/seacas/libraries/exodus/include/polyhedra.md), there is no orientation, and the library itself cannot resolve side sets on NFACED blocks (ex_int_get_block_param.c maps them to EX_EL_UNK; ex_get_side_set_node_list fails) — a first-order gap for boundary sets on a polyhedra-first mesh. No stored upward adjacency (downward element->face is writable but almost never written), no geometry link (Cubit exports names only), no non-conformal semantics (Sierra pairs sidesets in the input deck), implicit positional ids. It has more grouping machinery than usually credited: hierarchical assemblies (homogeneous members), edge/face blocks and sets, blobs, reduction variables, and now ex_basis/ex_field DoF descriptors (https://github.com/sandialabs/seacas/blob/master/packages/seacas/libraries/exodus/include/exodusII.h).

### MOAB / h5m — closest database precedent; export target

Entities + sets (with parent/child) + typed tags, including handle-valued tags that make relations first-class; CAD topology by convention (GEOM_DIMENSION, GLOBAL_ID, CATEGORY, GEOM_SENSE_2); the DAGMC pipeline into OpenMC and MCNP6 (https://bitbucket.org/fathomteam/moab; https://github.com/svalinn/DAGMC). Gaps: no formal spec and no file-version attribute (only an appended history dataset); no polyhedron face orientation (a shared face is referenced identically by both cells, so the outward side is undetermined); GLOBAL_ID header/code default conflict (0 vs -1); stringly-typed semantics ('mat:fuel'); ITAPS deprecated. OpenMC's MOAB backend accepts only linear tets (https://raw.githubusercontent.com/openmc-dev/openmc/develop/src/mesh.cpp).

### VTKHDF 2.8 — visualization export

Versioned HDF5 with a partition-concatenated layout and a polyhedral face table that is structurally close to our proposed core. But it is a visualization model: no faces for ordinary cells, no face->cell, face sharing and orientation unspecified (the owner/neighbour and signed-face proposals were considered and shelved, https://discourse.vtk.org/t/vtkhdf-add-support-for-polyhedron-cells/13089), no sets, no geometry, no interfaces, thin high-order. Implementation lags the spec: VTK 9.6 (2026-02) is the first reader for polyhedra; writer support is unstated (https://docs.vtk.org/en/latest/vtk_file_formats/vtkhdf_file_format/vtkhdf_status.html).

### Conduit Mesh Blueprint — in-situ export; design precedent

The de facto in-situ interchange (Ascent, VisIt, ParaView Catalyst2, MFEM). Gaps are policy: no winding/cascade convention, no face or edge entities, no named sets, no geometry, nestsets structured-only; Ascent's adapter rejects polyhedra (https://llnl-conduit.readthedocs.io/en/latest/blueprint_mesh.html).

### PETSc DMPlex HDF5 — design precedent

The best topology model in the survey (Hasse diagram) and it does have CAD classification (EGADS labels, TUV parametric, snap-to-model, https://petsc.org/release/manualpages/DMPlex/DMPlexCreateGeomFromFile/), but it is a library dump (default write version 1.0.0; parallel 3.0.0 opt-in) and polyhedra fail in every consumer (cell type UNKNOWN raises errors in DMPlexComputeCellTypes, DMPlexInterpolate rejects faces > 4 vertices, FV geometry has no face description for UNKNOWN).

### Gmsh MSH 4.2 — closest single file to the three-layer model, but unreleased

$Entities B-rep with signed boundaries, physical groups overlay, nodes/elements classified per entity with parametric coords, $Polytopes with sub-tetrahedralization whose extra nodes are the hanging nodes, $Edges/$Faces, $PartitionedEntities, $GhostElements, $Periodic (https://raw.githubusercontent.com/live-clones/gmsh/master/doc/texinfo/gmsh.texi). It exists only in the 5.0.0 work-in-progress branch; released Gmsh 4.15.2 (2026-03-24) writes MSH 4.1, which has no polyhedra and tag-only partitions. Track it; export 4.1 now.

### MED — export for the Salome/code_aster world

Polyhedra in two modes (nodal two-level CSR; MED_DESCENDING with faces as entities and signed references, sign convention not documented), MEDinterp arbitrary polynomial bases for fields, MEDCoupling remapper with an explicit sparse matrix. No B-rep in the file; MED 6.0.1 breaks backward compatibility (SALOME 9.16 notes). Pin the major version if exporting.

### Library-native formats (libMesh XDR/Checkpoint, MFEM, deal.II, PUMI SMB, STK via Ioss)

Serializations of a host library's in-memory model; none is a neutral IR. Two are instructive: libMesh's XDR cannot carry its own new C0Polyhedron (CheckpointIO had to add a "runtime topology" record in version 1.6), and MFEM's v1.x has two coordinate truths (ignored vertices vs the nodes field).

### What rolling our own costs, from the record

CGNS's layout break (3.4.0 -> 3.4.1 -> 4.0.0), MED 6.0.1's break, VTKHDF's reader lag of roughly two years behind its spec, Exodus polyhedra documented since v4.93 yet still partially supported by readers (ParaView issues 16062, 18360, 19915, 21318). A native IR therefore has to ship, on day one and together: a versioned machine-readable schema, a validator, and converters in both directions for the formats that matter. CGNS's own CPEX0049 is the committee drawing the same conclusion.

### Honest framing for the first consumer

If the transport code is ours, it reads the IR directly and "interchange" reduces to export targets. If it is Griffin/MOOSE, Exodus (with the NFACED side-set limit and libMesh 1.9-rc polyhedra) is the interchange; Serpent (https://serpent.vtt.fi/docs/user_guide/polymesh.html, unverified, 403) and OpenSn read OpenFOAM polyMesh (Serpent converts everything to tets and requires convex cells); OpenMC and MCNP6 read DAGMC h5m for geometry and tet h5m / Exodus / Abaqus .inp for overlay meshes (MCNP6 UM: 1st/2nd-order tet/penta/hex only). CGNS buys none of these. THOR is an AHOT-C tet code and Denovo is Cartesian, so neither is a polyhedral target; "Lupine" could not be identified — ask the user which code is meant.

## 3. The "database" framing: who already treats the mesh as a database

A mesh database, in the sense the user means, is: entity tables per kind, incidence relations with orientation, derived indexes (adjacency), sets as selections, tags/fields as columns, and a catalog. Five systems already do most of this; each teaches something specific.

**PETSc DMPlex (Hasse diagram as a relational store).** Every entity is an integer "point"; cone (what covers a point) and support (dual) are two inverse relations stored CSR-style with an orientation array; strata by depth/height are typed indexes; DMLabel is a secondary index (value -> point set); PetscSection is a column store keyed by point; closure, star, join and meet are graph queries; DMPlexSymmetrize/Stratify build derived indexes from the single cone relation (https://petsc.org/release/manual/dmplex/). HDF5 3.0.0 stores exactly strata/<depth>/{cone_sizes, cones, orientations} (https://gitlab.com/petsc/petsc/-/raw/release/src/dm/impls/plex/hdf5/plexhdf5.c). Orientation indexes the polytope's symmetry group, not just the dihedral group. Caveat already noted: polyhedra are storable but unusable downstream. Also: DMPlexSetAnchors + DMGetDefaultConstraints is a general "point dofs are a linear combination of other points' dofs" hook — exactly where mortar coupling would plug in. What we take: cones as single source of truth with supports and strata rebuildable; sections, labels and topology as independent layers joined only by ids; orientation as a column parallel to the incidence list.

**MOAB (entities + sets + typed tags).** Handle = 4 type bits + index, so type is a shift; contiguous sequences make a Range ([first,last] pairs) represent "all hexes in block 7" in O(1); sets contain entities and sets, with parent/child links separate from containment; tags are typed (int/double/handle/opaque/bit; dense per-sequence arrays or sparse maps); h5m has one global id space, CSR with end-offsets (poly_indices, set 'list' table with flags owner/unique/ordered/range-compressed), and optional stored adjacency (https://bitbucket.org/fathomteam/moab, src/io/mhdf). The convention layers (GEOM_DIMENSION, GEOM_SENSE_2, MATERIAL_SET, DAGMC group strings) show the core works without schema — and what that costs (header/code default conflicts; 'mat:' string parsing; no file-version attribute; no polyhedron orientation). What we take: typed id with kind; sets-of-sets with parent/child; range-compressed set contents; GEOM_SENSE_2 as the "surface -> (forward volume, reverse volume)" relation; replace conventions with schema-registered tags (name, type, unit, entity-kind domain, cardinality) and add a schema version.

**STK Mesh (schema/instance split, parts, selectors, buckets).** MetaData holds the schema (parts, fields, ranks); BulkData the instance. EntityKey = 8-bit rank + 56-bit id. Parts form a DAG with induced membership; Selector is a boolean algebra (|, &, −, !) over parts and fields, evaluated per bucket key, not per entity; impl::Partition is keyed by the sorted part-ordinal list and holds bounded-capacity Buckets, each with one topology (a clustered index and an SoA column store at once); FieldRestriction holds a Selector, so field layout is a predicate over parts. Materialized derived relations exist alongside: ElemElemGraph (face-adjacent element graph), explicit SideSet objects of (element, local ordinal) entries, upward connectivity as CSR-with-slack; modification_begin/end is a transaction (https://github.com/trilinos/Trilinos/tree/master/packages/stk/stk_mesh/stk_mesh/base). What we take: schema/instance separation; selector algebra over set signatures; buckets as a rebuildable physical index, never part of identity or the on-disk contract.

**Conduit Mesh Blueprint (path-addressed tables with foreign keys).** A tree of typed arrays where topology.coordset, field.topology, matset.topology and adjset.topology are name-based foreign keys; one ragged primitive (o2mrelation: sizes, offsets, optional indices) for every one-to-many; a Mesh Index acts as the catalog over multi-file datasets; several topologies can share one coordset (volume mesh, boundary mesh, interface mesh without duplicating points); Table Blueprint plus blueprint::mesh::flatten() literally converts a mesh into point/element tables; generate_faces/lines/centroids return s2dmap/d2smap source<->destination maps (https://llnl-conduit.readthedocs.io/en/latest/blueprint_mesh.html). What we take: one ragged primitive; a small catalog header readers can plan I/O from; flatten() as the existence proof that mesh = tables.

**PUMI / SCOREC (classification as the cross-layer key).** MDS stores per-type arrays with down[dim][type] / up[dim][type] adjacency, free lists, and ids interleaved as index*8 + type; the mds_apf wrapper adds model[type] (one model-entity pointer per mesh entity), param[2], parts, and three nets (remotes, ghosts, matches) (https://raw.githubusercontent.com/SCOREC/core/master/mds/mds_apf.h). GMI is a small C vtable (dim, tag, find, adjacent, eval, reparam, closest_point, normal, bbox, is_in_closure_of, periodic, ...) with Parasolid/ACIS (via Simmetrix), analytic and topology-only (.dmg) backends (https://raw.githubusercontent.com/SCOREC/core/master/gmi/gmi.h). The representation taxonomy in the PUMI User's Guide (full vs reduced × complete vs incomplete; one-level default) is ready vocabulary for "which adjacency tables are materialized". apf::verify enforces the closure rule: a downward entity's model dimension ≤ the entity's model dimension; an interior model face adjacent to >1 model regions needs 2 mesh regions. Measured cost: 241 B/tet for full one-level MDS vs 897 B/tet object-based (mds.tex). Two cautions: SCOREC's "partition model" (G/P/M hierarchy) means parallel part decomposition, not material grouping — name our material layer something else; and PUMI's entity sets are specified but unimplemented. What we take: classification + parametric coords as columns; a GMI-like trait for the geometry kernel; verify() as part of the spec.

Also database-like and worth copying in part: SGC (Rossignac–O'Connor: disjoint cells per dimension, an incidence graph with left/right/both tags, an active flag per cell so selections define point-sets over one complex, NAIL tables as explicit indexes; https://cgvr.cs.uni-bremen.de/teaching/cg_literatur/SIG96sgc.pdf); Omega_h (CSR Adj with orientation codes, ask_down/ask_up derived and cached per pair, class_sets); OpenFOAM polyMesh (faces + owner/neighbour is an edge-list relation, cells a derived view, upper-triangular order a clustered index yielding LDU layout, faceCompactIOList = CSR on disk); Fluent (typed zone tables with declared counts); Netgen Region<N> side tables (surfnr, domin, domout, bcprop, surfcolour).

The narrowed gap, per the corrections: CSR polyhedral layout (CGNS, VTKHDF, h5m, polyMesh, MED, Exodus), declared pairings (CGNS, OpenFOAM), persisted intersections (Fluent §61), classification (PUMI, Gmsh, Salome, DMPlex/EGADS), hierarchical sets (Exodus assemblies, STK Parts), and verify() functions (Conduit, apf::verify, checkMesh) each exist somewhere. What no system offers is the typed combination: one declared, versioned, machine-readable schema that carries a stated orientation convention, stable ids, classification as a foreign key, sets as typed tables, and an interface relation. That combination is the legitimate design target; a columnar CSR layout alone is not a differentiator.

## 4. Non-conformal interfaces

Six representations are in use. The task named four; the reports surfaced two more (E, F).

**A. Implicit unmerged faces + run-time geometric search (mesh stores two face sets; code finds the pairing).**
- Exodus/Sierra: two sidesets; the deck pairs them (Fuego "opposing sides", Aria contact with search tolerance) (https://github.com/sandialabs/seacas/blob/master/packages/seacas/libraries/exodus/include/exodusII.h and Sierra manuals).
- MOOSE/libMesh mortar: primary/secondary sidesets plus lower-dimensional blocks (LowerDBlockFromSidesetGenerator); AutomaticMortarGeneration does k-d tree screening, face linearization (Tri3/Tri6/Tri7/Quad4/Quad8/Quad9), projection, polygon clipping and triangulation into an in-memory mortar segment mesh; 3D after Puso (IJNME 59:315-336, 2004); tri secondaries lock, QUAD recommended (https://raw.githubusercontent.com/idaholab/moose/next/framework/src/constraints/AutomaticMortarGeneration.C). BreakMeshByBlockGenerator is the inverse operation that creates the unmerged state.
- ESI OpenFOAM cyclicAMI/ACMI: pair declared in the boundary file (neighbourPatch, transform, matchTolerance, lowWeightCorrection, requireMatch; Foundation v10 spelled the keyword transformType); srcAddress/srcWeights computed at run time; wghtSum stored as coverage fraction; not conservative (~0.1% error per https://cfd.direct/openfoam/free-software/non-conformal-coupling/) (https://api.openfoam.com/2506/classFoam_1_1AMIInterpolation.html).
- MFEM: ParMoonolith/ParMortarAssembler and Tribol at run time; never in the file. STK: stk_middle_mesh computes a middle grid with two-way classification; Nalu searches per integration point. SU2: config markers only.
- Detection in all of these is declaration plus geometric proximity (Fluent auto_create; Cubit Find Overlap / Find Near Coincident). No tool infers non-conformity from topology.

**B. Explicit declared pairs persisted in the mesh (no geometry data).**
- CGNS GridConnectivity_t: Abutting with donor levels minimal (zone name) / partial (+CellListDonor) / full (+InterpolantsDonor, linear donors only); stored twice, once per zone; Periodic_t and AverageInterface_t properties (https://cgns.org/standard/SIDS/multizone.html). Vendors (Cassiopee/elsA) put near-match details in UserDefinedData.
- OpenFOAM Foundation boundary file: nonConformalCyclic patch with zero faces, origPatchName, cyclicTransform, mandatory nonConformalError patch (https://cpp.openfoam.org/v11/classFoam_1_1nonConformalCyclicPolyPatch.html).
- Gmsh $Periodic (affine + node correspondences); PUMI matches (periodic copies); Netgen identifications; Cubit per-entity "Merge Off"; Simmetrix M_splitMatch duplicated faces on an interior model face (PHASTA "DG interface").

**C. AMR hanging-node trees (refinement history; constraints computed algebraically; no search).**
- MFEM NCMesh: ref_type bitmask, child ids, vertex_parents (two parents; scale only in NC mesh v1.1), masters/slaves with deduplicated point matrices; arbitrary irregularity (LimitNCLevel optional); variable p since 4.3 (https://raw.githubusercontent.com/mfem/mfem/master/mesh/ncmesh.hpp; https://arxiv.org/pdf/1905.04033).
- DMPlex tree (DMPlexSetTree, reference trees = 2:1 isotropic) over the anchors/constraints mechanism; DMForest/p4est.
- deal.II one-irregularity is an unconditional invariant; AffineConstraints; GridIn refuses hanging nodes on input.
- libMesh parent/child; Omega_h amr (hypercube, enforce_2to1_refine); Conduit nestsets (structured only); VTK HyperTreeGrid/OverlappingAMR; Fluent face tree §59 / cell tree §58 (parent cells moved to inactive zone type 32).
- CGNS rejected hierarchical elements (CPEX0008).

**D. Precomputed intersection / supermesh / materialized cut faces.**
- Fluent: child faces persisted in zones typed bc+1000 with §61 "Interface Face Parents" (skipped when read into meshing mode) (https://ansyshelp.ansys.com/public/Views/Secured/corp/v242/en/flu_ug/tgd_user_format_gridsect.html).
- OpenFOAM Foundation NCC (v10+, replaced AMI in v11): polyMesh untouched; fvMeshStitcher cuts intersection faces into the FV mesh at load and on motion; polyFacesBf maps each fv face to its parent poly face; conservation by construction; partial overlap lands on the error patch (https://cpp.openfoam.org/v10/fvMeshStitcher_8H_source.html).
- STAR-CCM+: Imprinted (adds vertices), Metrics-Based (faces as area + centroid, no vertices), Conformal (discards non-matching), Mapped Contact (proximity; Compact or Imprint stencils) (https://www.topcfd.cn/Ebook/STARCCMP/GUID-80A5E05B-0304-4955-B1A5-194547550FCB.html, third-party mirror).
- Code_Saturne: cs_join_add(fraction=0.1 of shortest edge, plane=25°) joins destructively in the solver and writes mesh_output.csm (https://code-saturne.org/doc/code_saturne-9.2/cs__join_8h.html).
- MEDCoupling remapper: sparse matrix rows per target cell; natures IntensiveMaximum vs ExtensiveConservation; Geometric2D handles quadratic edges; 3D surface intersection only tri/quad (https://docs.salome-platform.org/latest/dev/MEDCoupling/developer/intersec-specifics.html). libsupermesh (Farrell–Maddison). MOOSE's mortar segment mesh (in memory only).

**E. Degenerate to polyhedra (make the mesh conformal by giving the coarse face extra vertices).**
- PDT stitches hanging nodes into degenerate polygons; PWLD is designed for it (Bailey/Adams: "promising for ... grids that have local refinement") (https://www.kns.org/files/int_paper/paper/MC2017_2017_1/P017S01-02GhaddarT.pdf). OpenSn's PWLD on arbitrary polyhedra likewise.
- Conduit to_polygonal/polystar; MEDCoupling conformize3D (partition-like non-conformities only, polyhedra only); Gmsh 4.2 $Polytopes whose sub-tetrahedralization nodes are "the hanging or interior nodes"; CGNS NFACE_n can represent it (inference from the face-sharing rule) at the cost of losing the hierarchy.

**F. Overlay (no conformity between mesh and geometry is required).**
- OpenMC unstructured tally meshes over CSG/DAGMC geometry; material_volumes() ray-traced per element (0.15.1); AdaptiveLibMesh accepts hanging-node meshes; no unstructured surface tallies; libMesh path requires ReplicatedMesh (https://raw.githubusercontent.com/openmc-dev/openmc/develop/src/mesh.cpp).
- Denovo/Exnihilo ray-traces CAD onto a Cartesian grid; MCNP6 UM treats gaps as void and tolerates mild overlaps without correction.

### What the IR should store

Vocabulary first, since the user's term is "imprinting": an information-level imprint is a shared topology face carrying its two side regions, or an Interface record pairing two face sets, with the stored mesh left untouched (precedents: DAGMC/MOAB GEOM_SENSE_2, one surface set shared by two volumes; Foundation NCC's untouched polyMesh with polyFacesBf provenance). A physical conformize is a face-splitting operation that changes the mesh (Cubit imprint + merge, Code_Saturne join, Fluent child faces, MEDCoupling conformize3D). The IR keeps both as distinct operations and records which one produced a given interface.

1. **Interface record (declared level, one record, not two):** {id; side_A: face set; side_B: face set; kind ∈ {conformal-merged, imprinted-conformal, non-conformal-abutting, hierarchical/hanging, periodic, sliding, mapped-with-gap}; transform (none | translation vector | rotation axis+centre+angle); tolerance (fraction of local edge length, plus normal-angle cosine); required-match policy (full | partial-allowed | error-patch); provenance (user-declared | detected-coincident | derived-from-refinement); imprint status of the underlying topology face pair; field nature for transfer (intensive | extensive)}. Baseline to cite: CGNS GridConnectivity_t Abutting plus the OpenFOAM boundary entry; we differ by typed references, single record, provenance and tolerance-as-data.
2. **Overlap table (derived, cached, versioned by hash of both face sets + tolerance + algorithm id):** a sparse matrix stored in both directions (A->B and B->A, as OpenFOAM's src/tgt pairs) with per-entry {face_A, face_B, overlap polygon vertices, area, centroid, outward normal, parametric coordinates in each parent face's reference frame}; row sums give coverage (OpenFOAM wghtSum semantics); reciprocity check area(A,B) = area(B,A); optionally the sub-faces as entities with parent ids (the Fluent §61 / NCC polyFacesBf form) so a consumer can choose "materialized cut faces" or "weights only".
3. **Hierarchy (optional):** parent/child per entity plus a point matrix (slave vertices in master reference coordinates) in MFEM NCList form, so constraint matrices are derivable without search; the refinement tree itself is optional generative history.
4. **Detection as a validator query:** unmatched boundary faces; pairs of faces coincident within tolerance and coplanar within angle, not sharing topology; emitted as candidate Interface records with provenance = detected; coverage fraction per interface; fail or warn by policy. This is what Cubit (Find Overlap) and Fluent (auto_create) do interactively; here it is part of the file's validation.

### Lowering per consumer

- DG-SN transport (our code): sub-face polygons with area and outward normal; |Ω·n| per direction; a per-direction directed upwind graph over faces including interface sub-faces, with cycle detection and lagged edges (Haut et al. remove an edge set that "approximately minimizes" summed weight, https://arxiv.org/abs/1810.11080; OpenSn lags the faces with smallest |Ω·n|); flux reciprocity from the symmetric overlap table. CPEX0050's InterfaceContinuity/DofStorage is the matching vocabulary if a CGNS export of DG fields is ever wanted.
- PWLD/polyhedral codes (OpenSn, PDT): an "imprint to conformal polyhedra" export in which the hanging node becomes an extra polygon vertex; no interface object needed.
- Monte Carlo: DAGMC export needs imprinted and merged watertight surfaces (GEOM_SENSE_2 from topology sides); OpenMC's BCs accept only transmit/vacuum/reflective; overlay tally meshes need no conformity; an adjacency-through-interface view suffices for face crossing.
- MOOSE/Griffin: two sidesets plus lower-d blocks and the tolerance values written into the input deck; or the conformal imprint as plain Exodus.
- OpenFOAM Foundation: two zero-face nonConformalCyclic patches plus originals; ESI: cyclicAMI pair with its transform entry; Fluent: interface zones, or persisted children with §61.
- CGNS: Abutting GridConnectivity with CellListDonor (interpolants only for linear donor types).

Conservation nuance to carry in the record: weight-based projection (AMI) is not conservative; materialized cut faces (NCC, Fluent children, physical imprint) conserve by construction; MEDCoupling makes the field nature explicit because conservation and the maximum principle cannot both hold when coverage < 1.

## 5. Layer model

### How tools represent the layers and keep them coherent

- **Classification** (mesh entity -> lowest-dimensional containing model entity) is the universal cross-layer link: PUMI/Simmetrix model pointer + param (Beall & Shephard 1997, M^d classified on G^q with d ≤ q); Gmsh (entityDim, entityTag) blocks with parametric coords; Salome sub-shape association with parametric coords; Cubit "owner" geometry with sets that update on remesh; Omega_h class_dim/class_id; DMPlex EGADS labels + TUV; deal.II manifold_id (https://github.com/SCOREC/core/blob/master/apf/apfMesh.h; https://gmsh.info/doc/texinfo/gmsh.html; https://docs.salome-platform.org/latest/gui/SMESH/about_meshes.html).
- **Partition/material as selections over geometry**: Cubit blocks are geometry-bound (one block per volume, with Duplicate Block Elements as escape hatch; Default Block ON exports unblocked mesh keyed by owner id) (https://coreform.com/cubit_help/finite_element_model/exodus/block_specification.htm); Gmsh physical groups are integer tags in entities, many-to-many; Salome groups come in three lifetimes (on geometry / standalone / on filter); CGNS Family_t sits between Zone/BC and CAD; Exodus assemblies; STK Parts DAG; deal.II's material_id / boundary_id / subdomain_id / manifold_id is the cleanest four-way tag split; Netgen FaceDescriptor carries (surfnr, domin, domout, bcprop, surfcolour); MOAB GEOM_SENSE_2 carries (forward volume, reverse volume); SGC active selections; DAGMC group strings.
- **Topology distinct from shape**: Cubit Virtual Geometry (composite/partition without touching the ACIS model, fully reversible; mesh-based imprint creates it); SGC cells + incidence graph; MOAB stores topology without shape; PUMI's .dmg topology-only model; OCCT CompSolid sharing face TShapes; Gmsh BooleanFragments = OCCT General Fuse (https://occt3d.com/dev/doc/overview/html/occt_user_guides__modeling_data.html).
- **Conformality as topological identity**: Cubit imprint then merge (merge requires geometric and topological match; if meshed, topologically identical meshes; Merge Off persists intent) (https://coreform.com/cubit_help/geometry/imprint_merge/merging.htm); Gmsh Coherence; ANSYS shared topology; Fluent instead keeps a distinct face zone per cell zone and pairs at setup.
- **Discretization/field layer precedents**: Exodus ex_basis (per-DoF subcell dim/ordinal + parametric point) and ex_field; MED MEDinterp polynomial bases per geometry type; CGNS CPEX0045/0050; DMPlex PetscSection; MFEM nodes GridFunction in a named collection; vtkCellGrid function spaces (H(Grad)/H(Curl)/H(Div), CG/DG); XDMF FiniteElementFunction.
- **Sizing/meshing intent**: Salome hypotheses on sub-shapes with a documented priority order (edge, edge groups, wires, faces, face groups, shells, solids, solid groups, main shape); Simmetrix attribute "cases" (meshing case vs analysis case) on model entities and groups; Cubit intervals/schemes on geometry.
- **Distribution**: Gmsh $PartitionedEntities (partition entities as children of model entities) + $GhostElements; MED subdomain joints; PUMI remotes/ghosts/matches with residence sets; STK ghosting objects; Nemesis maps; OpenFOAM processor patches; DMPlex PetscSF; Fluent §40. SCOREC's name for this is the "partition model".

### Coherence invariants (what the validator enforces)

- Classification closure (apf::verify rule): for every mesh entity, model dim ≥ mesh dim, and the model entity of each downward entity lies in the closure of the entity's own model entity.
- A mesh face with one cell is classified on an L1 boundary face or on an L7 interface; a mesh face with two cells is interior or lies on a merged L1 face; an interior L1 face adjacent to two regions needs two mesh cells (PUMI rule) unless an Interface record covers it.
- Every L1 face has two side regions (Netgen domin/domout; GEOM_SENSE_2), one of which may be "exterior".
- Material regions partition the volumes exactly (Exodus: an entity in exactly one block); boundary sets may overlap (Exodus sets, Gmsh groups, Cubit sidesets).
- Geometric and topological closure of every cell (OpenFOAM checkMesh rules); one declared outward-normal/sign convention for cell->face; reciprocity of overlap areas.
- Interface coverage reported; required-match policy enforced; tolerances are data in the record.
- L9 residence/owner consistency (the residence-subset check in PUMI's apf::verify); L6 node ordering declared per shape; L8 dof layout consistent with L5 orientation permutations (DMPlex-style).
- Geometry-bound versus mesh-bound set lifetime recorded, so remeshing preserves intent (Cubit/Salome lesson).

## 6. Recommendation

### Positioning statement

Our IR is conceptually similar to CGNS SIDS (a typed, versioned schema with NGON/NFACE polyhedra, Family indirection and declared GridConnectivity interfaces) and to MOAB/DMPlex (the mesh as an entity–relation database with sets, tags and derived adjacency), with PUMI/Gmsh-style classification of every mesh entity to a B-rep, but differs in:

- (A) faces are first-class for every cell, with stored oriented cell->face and face->(left, right) relations, so polyhedra are the general case and tet/hex are derived shape tags — unlike VTKHDF, Conduit, Exodus and MOAB, where faces exist only for polyhedra and no orientation rule is specified, and unlike STK/PUMI, which have no polyhedra;
- (B) an explicit multi-layer model joined by typed foreign keys — classification (mesh -> topology), selection (region -> topology), pairing (interface -> faces), ownership (part -> entity) — rather than CGNS Family name strings, DMPlex/MOAB label conventions or Gmsh integer tags;
- (C) non-conformal interfaces as one first-class record with declared and derived levels, provenance, tolerance and imprint status, plus a cached symmetric overlap table valid for polyhedral and high-order faces — where CGNS stores two records with linear-only interpolants, OpenFOAM/MOOSE/Fluent recompute at run time, and MFEM/DMPlex cover only refinement-derived hanging nodes;
- (D) stable typed ids with owner, ghost and global-id columns in the schema — where CGNS and VTK are positional and Exodus is implicit;
- (E) high-order as (shape, degree, basis) with curved faces on polyhedra — where every surveyed format uses a closed enum and even CPEX0045 excludes polyhedra;
- (F) a machine-readable, versioned schema with a validator and converters shipped together from day one — only Gmsh and CGNS have formal specs, and none has a conformance suite;
- (G) a columnar physical layout (CSR offsets + flat indices, SoA coordinates, partition-contiguous datasets in HDF5/Arrow-compatible buffers) for zero-copy and partial parallel reads;

giving: (P) lossless polyhedral and DG-transport consumption — face adjacency, per-direction upwind graphs and interface weights come out of the schema instead of being re-detected; (Q) reproducible, inspectable non-conformity — detection, tolerances and pairings are data; (R) remeshing and adaptation that keep materials, BCs and CAD links through classification; (S) exports to every surveyed format as declared lossy projections with a loss report.

### DAG nodes this implies (one well-bounded concept each)

Shape kernel (L0) → Topology/cell complex (booleans, General-Fuse fragment, imprint, merge, virtual topology; L1) → Regions & attributes (L2/L3) → Sizing (L4) → Mesher(s) → Mesh database (L5/L6 tables, classification, validator) → Interface detect / face-intersect / overlap weights / imprint-to-conformal (L7) → Metrics → Partitioner & distribution (L9) → Discretization/fields (L8) → Exporters (one node per target, each emitting a loss report) → Provenance (L10). Edges are the typed relations named in section 5; the interfaces between nodes are those relations.
