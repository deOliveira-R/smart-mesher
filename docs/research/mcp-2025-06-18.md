# MCP 2025-06-18: server excerpt (stdio)

Offline reference for `sm-mcp` (T11). Fetched 2026-10-24 from modelcontextprotocol.io/specification/2025-06-18: basic, basic/lifecycle, basic/transports, basic/utilities/{ping,cancellation,progress}, server/tools, changelog; plus the 2025-03-26 changelog for the 2024-11-05 differences. Quoted text is verbatim from the spec. "Derived" marks inference, not spec text.

## 1. JSON-RPC message rules

Every message follows JSON-RPC 2.0 and is UTF-8.

- **Request:** `{jsonrpc:"2.0", id: string|number, method, params?: object}`. The id MUST NOT be `null` and MUST NOT be reused within a session.
- **Response:** `{jsonrpc:"2.0", id, result?: object, error?: {code:int, message, data?}}`. It has exactly one of `result` or `error`, and the same id as its request.
- **Notification:** `{jsonrpc:"2.0", method, params?}`. It has no id, and "The receiver MUST NOT send a response."
- **Batching** is removed in 2025-06-18 ("Remove support for JSON-RPC batching"). Do not send or expect JSON arrays.
- **`_meta`** is reserved for metadata. Do not assume anything about values under reserved keys. Of these, this excerpt uses only `progressToken`.

## 2. Lifecycle

The client sends `initialize` first:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{"roots":{"listChanged":true},"sampling":{},"elicitation":{}},"clientInfo":{"name":"ExampleClient","title":"Example Client Display Name","version":"1.0.0"}}}
```

The server responds:

```json
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"ExampleServer","title":"Example Server Display Name","version":"1.0.0"},"instructions":"Optional instructions for the client"}}
```

Then the client sends the notification `{"jsonrpc":"2.0","method":"notifications/initialized"}`. Before the server has answered `initialize`, the client sends only pings. Before `initialized` arrives, the server sends only pings and logging.

**Version negotiation.** "If the server supports the requested protocol version, it MUST respond with the same version. Otherwise, the server MUST respond with another protocol version it supports. This SHOULD be the latest version supported by the server." The client SHOULD disconnect if it cannot use the returned version. Both sides MUST respect the negotiated version and use only negotiated capabilities.

Example error for an unsupported version:

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32602,"message":"Unsupported protocol version","data":{"supported":["2024-11-05"],"requested":"1.0.0"}}}
```

**Server capabilities:** `prompts`, `resources`, `tools`, `logging`, `completions`, `experimental`. The `listChanged` sub-capability means the server emits list-changed notifications.

**Shutdown (stdio).** No message is defined. The client closes the server's stdin, then sends SIGTERM, then SIGKILL. The server MAY close stdout and exit. Derived: on stdin EOF, flush and exit 0.

## 3. Stdio framing

- "Messages are delimited by newlines, and MUST NOT contain embedded newlines."
- "The server MUST NOT write anything to its stdout that is not a valid MCP message." The server MAY log to stderr.
- Derived:
  - Write compact single-line JSON followed by `\n`, never pretty-printed, and flush after each message.
  - Ignore blank input lines.
  - Treat EOF as shutdown.

## 4. Ping

`{"jsonrpc":"2.0","id":"123","method":"ping"}` → `{"jsonrpc":"2.0","id":"123","result":{}}`. Answer a ping at any time, including before `initialize`.

## 5. Progress

The requester sets `params._meta.progressToken`, a string or integer that is unique among active requests. The server may then send:

```json
{"jsonrpc":"2.0","method":"notifications/progress","params":{"progressToken":"abc123","progress":50,"total":100,"message":"Reticulating splines..."}}
```

- `progress` MUST increase with each notification and may be a float.
- `total` is optional.
- Notifications stop when the request completes.
- Sending none at all is allowed.

## 6. Cancellation

```json
{"jsonrpc":"2.0","method":"notifications/cancelled","params":{"requestId":"123","reason":"User requested cancellation"}}
```

- On receiving it, the server SHOULD stop the work and "Not send a response for the cancelled request."
- Unknown, completed or invalid cancellations SHOULD be ignored, with no error reply.
- `initialize` cannot be cancelled.

## 7. Tools

**Capability:** `{"capabilities":{"tools":{"listChanged":true}}}`.

**tools/list** is paginated: the request carries `params.cursor` and the result carries `nextCursor`. Derived: returning every tool in one page with no `nextCursor` is valid.

```json
{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"cursor":"optional-cursor-value"}}
{"jsonrpc":"2.0","id":1,"result":{"tools":[{"name":"get_weather","title":"Weather Information Provider","description":"Get current weather information for a location","inputSchema":{"type":"object","properties":{"location":{"type":"string","description":"City name or zip code"}},"required":["location"]}}],"nextCursor":"next-page-cursor"}}
```

**Tool fields:**

| Field | Meaning |
|---|---|
| `name` | Unique identifier. The fetched page gives no character constraint; we use `OpInfo::tool_name`, with `.`→`__`. |
| `title` | Optional display name. |
| `description` | What the tool does. |
| `inputSchema` | JSON Schema with root `type: object`. |
| `outputSchema` | Optional. |
| `annotations` | Optional and untrusted. |

**tools/call:**

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_weather","arguments":{"location":"New York"}}}
{"jsonrpc":"2.0","id":2,"result":{"content":[{"type":"text","text":"Current weather in New York: ..."}],"isError":false}}
```

**Content types:**
- `text`: `{type, text}`
- `image`: `{type, data (base64), mimeType}`
- `audio`: `{type, data, mimeType}`
- `resource_link`: `{type, uri, name, description?, mimeType?}`
- `resource`: `{type, resource: {uri, mimeType, text|blob}}`

Each may carry optional `annotations` (`audience`, `priority`, `lastModified`).

**Structured output.**
- Structured output goes in `result.structuredContent`, which is a JSON object.
- "For backwards compatibility, a tool that returns structured content SHOULD also return the serialized JSON in a TextContent block."
- When `outputSchema` is set, "Servers MUST provide structured results that conform to this schema."

```json
{"jsonrpc":"2.0","id":5,"result":{"content":[{"type":"text","text":"{\"temperature\": 22.5, \"conditions\": \"Partly cloudy\", \"humidity\": 65}"}],"structuredContent":{"temperature":22.5,"conditions":"Partly cloudy","humidity":65}}}
```

**Errors.**
- Protocol errors use JSON-RPC errors. These cover unknown tools, invalid arguments and server errors:

  ```json
  {"jsonrpc":"2.0","id":3,"error":{"code":-32602,"message":"Unknown tool: invalid_tool_name"}}
  ```

- Tool execution errors, such as business logic failures, are a normal result with `isError: true`:

  ```json
  {"jsonrpc":"2.0","id":4,"result":{"content":[{"type":"text","text":"Failed to fetch weather data: API rate limit exceeded"}],"isError":true}}
  ```

**List changed:** `{"jsonrpc":"2.0","method":"notifications/tools/list_changed"}`. Send it only if `listChanged` was declared. The client then calls `tools/list` again.

**Security:** servers MUST validate all tool inputs and sanitize outputs.

## 8. Version differences

- **2025-06-18 added** (relative to 2025-03-26):
  - structured tool output (`structuredContent`, `outputSchema`)
  - `title` fields
  - `resource_link` content
  - elicitation
  - removal of batching
  - lifecycle SHOULD→MUST
  - the `MCP-Protocol-Version` header (HTTP only)
- **2025-03-26 added** (relative to 2024-11-05):
  - Streamable HTTP
  - batching
  - tool `annotations`
  - the progress `message` field
  - audio content
  - the `completions` capability
- **Derived server rule:** echo a requested version in {`2025-06-18`, `2025-03-26`, `2024-11-05`}, or else answer `2025-06-18`. When the negotiated version is older:
  - Below 2025-06-18, omit `structuredContent`, `outputSchema`, `title` and `resource_link`. Text content still carries the JSON.
  - For 2024-11-05, also omit tool `annotations` and audio content.

## 10. Stdio server checklist

1. Read one message per line, and write compact JSON plus `\n`, flushing after each. Logs go to stderr only.
2. Handle `initialize` first and negotiate the version as above. Declare `tools`.
3. Accept `notifications/initialized` with no reply. Answer `ping` with `{}`.
4. Implement `tools/list` (with an optional cursor) and `tools/call`.
5. Unknown tools and bad arguments get JSON-RPC -32602. Tool failures get `isError: true`.
6. With `outputSchema`, return `structuredContent` plus a text block holding the same JSON.
7. Never reply to a notification. Honour `notifications/cancelled`.
8. On EOF, exit cleanly.
