# smart-mesh mesh-IR synthesis: round-2 addendum

Basis: 6 fact-checked reports (2026-10-23) answering the critic's gaps in `docs/research/mesh-ir-critic.md`. Where a report's verification block corrects a claim, the corrected form is stated here with the verifier's source. Items the verifier could not fetch keep their marker: "(unverified)" or "[S]" (search snippet only). Layer names (L0–L10) and differentiators (A)–(H) are those of `mesh-ir-synthesis.md` §5–6 and `docs/design/ir.md`. Where this addendum changes a round-1 statement, it says "amends".

## 0. Amendments to round 1 at a glance

- **Positioning (synthesis §6, ir.md §2):** the integrated-store baseline is Cubit `.cub5`, Salome SMESH and ITAPS iRel; `.cub5` is itself HDF5 (section 2). "Like CGNS" becomes "like .cub5/Salome/iRel, but open, versioned, polyhedral-first, with a CGNS-grade schema".
- **Differentiator (A) precedent:** the face-first on-disk precedents are OpenFOAM `owner`/`neighbour` and CGNS `ParentElements`, not VTKHDF. VTKHDF is cell→faces→points with shared oriented faces and no face→cell array; its only relevant precedent is per-partition concatenation (section 1).
- **Differentiator (C) wording (ir.md §2):** PyFR is conforming-only and stores no pairing orientation; drop it from the claim. The defensible statement is: no surveyed format persists explicit sub-face overlap polygons with areas and normals; HOPR persists a coarse-side mortar type, MFEM NC and t8code persist refinement provenance, Nektar++/OpenFOAM/CGNS persist a declaration (section 4).
- **Conformize (ir.md §3 table, synthesis §4 pattern E):** in 3D, conformalizing a 2:1 interface means replacing the coarse face by the N fine faces (the polyhedron gains faces), not inserting hanging vertices into the coarse face loop. Teton requires exactly one opposite face per zone face and OpenSn matches faces by exact vertex set; the loop-insertion form fails both. In 2D the two forms coincide (section 6).
- **Differentiator (G):** the backend is now decided: abstract storage model with three physical profiles, Zarr v3 + mmap container day one, HDF5 as the HPC/interop profile, ADIOS2 not adopted (section 1).
- **Differentiator (D):** the id scheme is now designed (section 5); hash-derived ids are rejected on the birthday bound.
- **Layer model:** add Prototype/Instance/Lattice to L1/L2 and an instanced view of L5; add a coarse-mesh slot (independent mesh of the same L1 plus a fine→coarse map) (section 3).

## 1. Physical storage backends

### Findings

- **HDF5 2.x.** 2.0.0 (2025-11-11) introduced file-format 4.0 and dropped Autotools; the build option is still `HDF5_ENABLE_PARALLEL` (only the exported state variable became `HDF5_PROVIDES_PARALLEL`) (github.com/HDFGroup/hdf5/releases/tag/2.0.0; develop CMakeLists.txt). The default `H5Fset_libver_bounds` lower bound is now 1.8; nothing was found on 1.14 readers of 2.x-written files, so archives must pin libver bounds explicitly (same release page). Thread-safe and parallel builds are mutually exclusive ("Parallel and thread-safety options are not supported" unless `HDF5_ALLOW_UNSUPPORTED`); a thread-safe build is one global lock. The Rust crates' reentrant mutex is what makes a non-threadsafe libhdf5 usable from threads at all, so "use MPI ranks, not threads, on one file" holds in every language (develop CMakeLists.txt; github.com/metno/hdf5-rust).
- **HDF5 parallel compression** (support.hdfgroup.org `_par_compr.html`; hdfgroup.org 2022 blog): available since 1.10.2, collective only; ranks with no data still join the call; several ranks touching one chunk forces an owner-rank exchange; scaled poorly at about 8k ranks until collective metadata operations were enabled (`H5Pset_all_coll_metadata_ops`, `H5Pset_coll_metadata_write`); early space allocation is forced only for unfiltered parallel datasets, filtered ones default to incremental.
- **HDF5 filters** (`_h5_d__u_g.html`; forum thread 13747): built-ins are shuffle, Fletcher32, N-bit, scale-offset; gzip and szip are "optional built-in" and depend on zlib/szip at build time. The forum thread shows `h5repack -f GZIP=1` silently doing nothing on a 2.1.0 build without zlib: optional filters are skipped silently. The "ParaView cannot read zstd" line is one user's untested assertion. Lesson: check `H5Zfilter_avail` on both sides and mark filters mandatory. zstd still needs an external plugin.
- **HDF5 ROS3** predates 2.x (h5py gates its tests on 1.10.6); 2.0.0 rebuilt it on aws-c-s3 with S3 URIs, automatic tool switching, request splitting, a 64 MiB page-buffer and 8 MiB chunk-cache default; 2.2.0 added an I/O block cache. Still read-only (forum 13529; releases page).
- **Rust HDF5.** aldanor `hdf5` is dead (last release 0.8.1, 2021-11-21). `hdf5-metno` 0.15.0 (2026-09-18) supports HDF5 2.0.0 (0.12.0), 2.1.0 (0.12.4) and 2.2.0 (hdf5-sys 0.12.2); the MPI path is the `mpio` Cargo feature (mpi-sys ^0.2); `have-parallel`/`have-threadsafe` are cfg flags reflecting the linked library. Parallel builds broke and were fixed in 0.9.0 and again in 0.15.0, so the MPI path is exercised intermittently (crates.io; metno CHANGELOG; docs.rs features).
- **ADIOS2 BP5** (adios2.readthedocs.io engines, operators, setting_up; ornl.gov release note): new in 2.8, default since 2.9; a `name.bp/` directory with `data.0..M`, `md.0`, `md.idx`, `mmd.0`; TwoLevelShm aggregation default, MaxShmSize 4 GB, StripeSize 4096, OneLevelGatherRankLimit 6000; "memory consumption can get close to half of BP4 in some cases"; ORNL claims metadata at 1/3–1/4 of BP4 on E3SM. Operators: ZFP, SZ3, MGARD, Blosc2 (experimental), BZip2, PNG. The phrase "EveryoneWrites does not scale" could not be found on the cited page. crates.io has zero crates for `adios2` (checked 2026-10-23). Readers other than the ADIOS2 library are essentially nonexistent.
- **Zarr v3 core 3.1** (zarr-specs core; sharding-indexed): mandatory `zarr_format`, `node_type`, `shape`, `data_type`, `chunk_grid`, `chunk_key_encoding`, `fill_value`, `codecs`; exactly one array→bytes codec; `must_understand=false` is allowed for codecs and storage transformers, not for data type, chunk grid or key encoding, and it governs extension objects inside a node's metadata, not unknown sibling groups. Sharding: inner chunks plus an index of u64 (offset, nbytes) pairs, empty = 2^64−1, index at start or end, inner order unspecified, gaps allowed; crc32c on the index is recommended, not mandatory; a shard is one object, so writers must be shard-aligned. Variable chunking is ZEP 3, still Draft (created 2022-10-17).
- **Zarr codecs.** The registry holds 17 codecs (bitround, blosc, bytes, cast_value, conditional, crc32c, gzip, n5_default, packbits, reshape, scale_offset, sharding_indexed, transpose, vlen-bytes, vlen-utf8, zfp, zstd). There is no delta codec; standalone shuffle exists only as experimental `numcodecs.shuffle`; otherwise shuffle lives inside blosc (github.com/zarr-developers/zarr-extensions/tree/main/codecs). zarrs 0.23.14 (2026-08-14) implements no delta codec either; its `async` feature is "experimental" and slower than the sync API; stores: filesystem, `zarrs_object_store`, `zarrs_opendal`, `zarrs_icechunk` (docs.rs/zarrs).
- **Icechunk** (icechunk.io; crates.io): ACID transactions, immutable snapshots, tags, only modified chunks stored per commit; Rust core (`icechunk` 2.3.0, 2026-10-06; `zarrs_icechunk` 0.6.0). Parallel writes: cooperative (fork sessions, coordinator merges and commits; "it's the user's job to align the writing process with the Zarr chunks") or uncooperative (optimistic, `ConflictError`, rebase). An Icechunk repository is opened through the Icechunk library, not by a generic Zarr v3 store reader ("Right now, Icechunk only supports Zarr Python" besides the Rust crate).
- **Throughput evidence** is thin: Zarrista (on zarrs) reports 1.9–2.7× faster local-filesystem reads than zarr-python, beta quality; the Pangeo post (2025-11-25) saturates EC2–S3 with zarr-python + Icechunk/Obstore, sharding use unstated, optimal chunk 3–15 MB; an IPDPS 2020 Lustre study charges Zarr's file-per-chunk layout with MDS open costs (sharding mitigates). zarr-python 3.3 coalesces shard range reads within a 1 MiB gap up to 16 MiB. No MPI-scale mesh benchmark exists for any backend.
- **Arrow/Parquet** (arrow.apache.org Columnar; parquet.apache.org): `List` offsets are int32, `LargeList` int64 (needed at 1e9 cells); buffers padded to 8 bytes, 64 recommended; the IPC file footer gives random access and is relocatable, hence mmap-friendly; arrow-rs 60.0.0 (2026-09-15) supports little-endian only; no MPI-IO. Parquet page compression fights random access to a CSR slice. Fit: side tables, not mesh arrays.
- **safetensors** (github.com/huggingface/safetensors): 8-byte LE u64 header length, UTF-8 JSON header (100 MB cap) mapping name → dtype, shape, data_offsets, then one raw buffer, no holes or overlaps, LE row-major, no file-size limit; zero-copy mmap; no chunking, compression, checksums, hierarchy, versioning or parallel write protocol.
- **openPMD** (STANDARD.md 1.1.0, 2018-02-06; openPMD-validator): root attributes `openPMD`, `openPMDextension` (uint32 bitmask), `basePath`; only the ED-PIC extension exists; backends ADIOS2/HDF5/JSON; the validator is HDF5-only and "can not validate 100%". Lesson: validate the logical model, keep a serial JSON backend as the golden reference.
- **Face-first precedents** (amends synthesis §6 (A)): OpenFOAM polyMesh stores faces + `owner` + `neighbour`, internal faces first, boundary faces have no neighbour, normal points into the higher-labelled cell (doc.cfd.direct user-guide v12 mesh-description); CGNS `ParentElements` gives the two adjacent cells per face with the second parent 0 at a boundary, `ParentElementsPosition` the face's canonical position in each parent, NFACE_n signs encode outward (+) / inward (−) normals, `ElementStartOffset` required for MIXED/NGON_n/NFACE_n (cgns.org SIDS grid.html). VTKHDF 2.8 polyhedra (spec 2.5) are `FaceConnectivity`/`FaceOffsets`/`PolyhedronToFaces`/`PolyhedronOffsets` with shared oriented faces and no face→cell relation; its per-partition `NumberOfCells`/`NumberOfConnectivityIds` concatenation is the proven layout precedent.
- **Compression on connectivity**: no public ratios for Blosc/ZFP/zstd on CSR mesh arrays. Blosc's default is BloscLZ + shuffle (not zstd); its legacy "Delta" filter is XOR; Blosc2 ≥ 2.8 `bytedelta` after shuffle is what works on floats (aras-p.info 2023 Blosc post). ZFP is lossy-oriented for floats.
- **64-bit ids in exporters.** Exodus: `EX_ALL_INT64_DB` (on disk) and `EX_ALL_INT64_API` (in memory); compression only in netCDF-4 files, gzip level 1 "often sufficient" (seacas docs). Exodus size limits are per format mode: the legacy 64-bit-offset "large model" is capped (4 GiB per dataset, 2^29 nodes), netCDF-4 non-classic is "unlimited" with 64-bit integers (Exodus-Formats.md). CGNS `cgsize_t` is 32/64-bit per `CG_BUILD_64BIT` [S].

### Decisions

- **D1.1 Abstract storage model, three physical profiles, one golden backend.** The IR spec defines groups, named typed N-D arrays, attributes and per-array checksums, independent of bytes (openPMD pattern). Backends: (i) *solver-native* mmap container, one file per part; (ii) *archive/interchange* Zarr v3 on directory or object store via `zarrs`; (iii) *HPC/interop* HDF5 via `hdf5-metno` for MPI-IO collective writes and for the HDF5-based exporters (VTKHDF, h5m, HDF5 UM). Plus a JSON backend for golden test meshes. Day one: (i), (ii), JSON; (iii) enters with the first HDF5 exporter. ADIOS2 is not adopted (no Rust crate, single-library ecosystem, step-oriented); the model must stay clean enough to add it later.
- **D1.2 Layer ignorability is ours, not Zarr's.** Root attributes carry a format version triple, a per-layer schema version and an openPMD-style `required_layers`/`optional_layers` bitmask; unknown optional layers are skipped, unknown required layers fail loudly. Zarr `must_understand` is irrelevant to sibling groups.
- **D1.3 Part = unit of I/O and sharding.** One logical array per column, per-part count table (`n_cells`, `n_faces`, `n_cell_face_ids`, `n_face_vertex_ids`, ghosts) so each rank computes its slice; Zarr shard and HDF5 chunk boundaries coincide with part boundaries, so there is exactly one writer per shard/chunk (avoids HDF5's owner exchange and Zarr's read-modify-write). 1-D arrays with regular chunks; irregularity lives in our offset arrays, not in ZEP 3. Starting sizes: inner chunk 1–4 MiB, shard 64–256 MiB, to be tuned by D1.10.
- **D1.4 Id widths on disk.** u64 for all global ids and offsets; an optional part-local u32 index profile when a part's counts are < 2^32; width recorded in metadata; CSR offsets are always u64 (Arrow `List` int32 overflow, MOAB 32-bit `GLOBAL_ID`).
- **D1.5 Compression defaults.** Topology and geometry lossless. Zarr: `bytes → blosc(cname=zstd, shuffle)` or `zstd` plus `crc32c`; no delta codec (none registered; a custom one recreates the HDF5-plugin portability problem). The "delta" benefit comes from storing part-local indices (D1.4), not from a codec. HDF5: shuffle + deflate marked mandatory, zlib presence verified at build and `H5Zfilter_avail` at read; no plugin filters in the archive profile. Lossy (ZFP, quantization) only on L8 fields and only when the field's attribute says so. Ratios are measured on our meshes before defaults are frozen.
- **D1.6 Versioning without Icechunk in the archive profile.** Snapshots are immutable shards plus a manifest (array names, shard content hashes, layer versions); a new snapshot reuses unchanged shards. This keeps plain Zarr v3 readability, which Icechunk gives up. Icechunk may be offered later as an optional store through `zarrs_icechunk` for teams that want its transactions. HDF5 in-place mutation is never the history mechanism.
- **D1.7 HDF5 profile rules.** Collective, chunk-aligned writes; collective metadata operations on when filters are used; `H5Fset_libver_bounds` pinned explicitly for archives; one MPI rank per file region, no threads on one file; `hdf5-metno` pinned and its `mpio` path exercised in CI.
- **D1.8 mmap container.** safetensors layout plus what it lacks: magic number, format version, per-array crc32c, 64-byte alignment (Arrow's recommendation), little-endian, no holes, header size cap, a footer that allows append. `memmap2` with header validation before any slice is handed out. The container is an export of the archive profile, never the only copy.
- **D1.9 Arrow/Parquet** only for tabular side tables (provenance log, region membership, overlap tables, attribute tables), `LargeList`/int64 offsets.
- **D1.10 Benchmark before freezing.** A synthetic ~1e9-cell polyhedral mesh; read one part, write N parts from N ranks, cold S3 range reads; parallel HDF5 vs sharded `zarrs` vs mmap; compression ratios for connectivity with and without part-local indices. No public mesh benchmark exists, so this is a prerequisite, not an option.
- **D1.11 Validator** checks the logical model on every backend (names, dtypes, id widths, monotone offsets, left/right in range, orientation invariants, classification links); CLI plus Rust crate.

## 2. Integrated project stores

### Findings

- **Cubit legacy `.cub`** (MOAB `src/io/Tqdcfr.*`): custom offset-table binary with `FileTOC`, a model table (handle 1/type 1 = embedded ACIS SAT stream), per-FE-model headers with seven array descriptors (geom, node, element, group, block, nodeset, sideset), and per-geometry-entity `GeomHeader` records: mesh nodes and elements are stored *per owning geometry entity*. Association is geometry-side ACIS attributes (`UNIQUE_ID`, `ENTITY_ID`, `CUBIT_ID`, `COMPOSITE_ATTRIB`) joined to owner records; the mesh holds no pointer to the B-rep. Schema drift is visible: `data_version <= 1.0` shifts element-type enums; the `UNIQUE_ID`/`ENTITY_ID` attribute *string encoding* changed at Cubit 14 (Tqdcfr.cpp L2577–2600) — an encoding hazard, not a loss of identity across geometry edits; the values 52/55 are `blockElemType` sentinels ("infer from vertex count"), not record sizes. Legacy `.cub` has a 4 GB addressing limit (Coreform 2025.1 notes).
- **Modern Cubit is HDF5.** Coreform 2020.2: `.cub5` "contents and structure exactly the same as a .trelis file", and "Sandia Cubit does not support import and export of HDF5-based model files"; current Coreform help: "By default, the CUBIT file is written in an HDF5-based format that uses either the .cub or the .cub5 extension. The older binary format is supported for read-only backward compatibility"; `save as 'f' Journal` embeds the journal stream. Saving restores "exactly the same state ... element faces and edges are persistent, as well as mesh and geometry ids" (Sandia 16.06 saving_and_restoring). The schema is undocumented but h5dump-inspectable. MOAB's Tqdcfr reads only the legacy binary.
- **Cubit persistent attributes** (16.06 help): Color, Composite vg, Genesis entity, Id, Mesh container, Mesh scheme, Name, Partition vg, Smooth scheme, Unique Id, Vertex type, Virtual vg; written into the solid-model file, actuated after import; virtual geometry (composite, partition, collapse, simplify) is reversible and does not touch the ACIS model.
- **CGM**: own topology layer over any modeler, virtual entities between topology and true geometry, `CubitAttrib` subclasses with write/read/update/actuate hooks, unique-id attributes actuated before virtual-geometry ones (cgma-dev listings; Tautges 2001 [S] — mailing lists were unreachable this session).
- **iRel/Lasso** (MOAB `deprecated/itaps/irel/`): relation type per side `iRel_ENTITY | iRel_SET | iRel_BOTH`; status `iRel_ACTIVE | iRel_INACTIVE | iRel_NOTEXIST` (no PASSIVE); `iRel_inferArrArrRelations` joins geometry entities to mesh sets by (dim 0..3, gid) using `GEOM_DIMENSION` + `GLOBAL_ID`, but only when the caller invokes `iRel_infer*Relations`; nothing is restored automatically on load. Deprecated inside MOAB.
- **Salome SMESH persists per-entity classification** (smesh `SMESH_Gen_i.cxx` L5355–6010; `SMESHDS_Mesh.cxx` L138): per mesh "Ref on shape" (study entry), `meshPersistentId`, `shapeTick` (main-shape modification counter); "Node Submeshes"/"Element Submeshes" datasets holding every node's and element's sub-shape id (`TopExp::MapShapes` order); "Node Positions" with U on edges and U/V on faces. GEOM saves an OCAF BinOcaf document (`_GEOM.cbf`), not raw BREP streams. Copy-mesh onto modified geometry rebinds by sub-shape; unmatched objects turn red; a group on geometry degrades to a standalone id list and "can't be transformed back" (docs.salome-platform.org copy_mesh). This is the closest existing analogue to L5 classification plus staleness detection.
- **Simmetrix**: `.smd` model, `.sms` mesh, derived `.dmg` "needed to classify mesh points"; after "certain geometric transformations" `.smd` and native `_nat.x_t` "can have disagreeing model tags" (PHASTA wiki) [S]; binary layouts proprietary.
- **ESP/CAPS** (AIAA 2016-4007; ESP-help §5.12): `capsGroup` is "the major attribution entity required by CAPS"; `capsBound` is a cross-body data-transfer grouping, not a BC group; EGADS attributes "persistent when applied to topological objects and saved" in the native file. ESP auto-assigns `_faceID` (3-tuple), `_edgeID` (5-tuple), `_nodeID`, `_hist` ("list of Bodys that contained this Face"), `_body`/`_brch`, and `_newSeqnum` ("less susceptible to geometry changes") — ESP itself concedes sequence numbers drift. `capsMesh`/`capsConstraint`/`capsLoad`/`capsIgnore` (unverified).
- **libMeshb / MMG / refine** (LoicMarechal/libMeshb spec and source; nasa/refine `ref_gather.c`, `ref_import.c`): the `*OnGeometric*` keywords carry two incompatible semantics. INRIA/MMG: (entity, support-mesh entity, barycentric position, distance) — projection onto a faceted support mesh, no B-rep. NASA refine: the same keyword codes 40/41/42 hold (node, CAD edge/face id, t or (u,v), integer `gref` cast to double in the distance slot) and the EGADS model is embedded as `GmfByteFlow` (keyword 126). MMG internal tags: `MG_REF/GEO/REQ/NOM/CRN/BDY/NOSURF/OPNBDY/PARBDY/OVERLAP`; Bezier surface fit confirmed (PN-triangles), Hausdorff control (unverified).

### Decisions

- **D2.1 Positioning amended** (synthesis §6, ir.md §1–2): baseline = `.cub5` (HDF5), Salome study, iRel. Cubit abandoning its offset-table container for HDF5 is prior art for D1.1; a self-describing chunked container is the norm, not a novelty.
- **D2.2 Three association mechanisms, all stored.** (a) Authored intent by stable name/attribute on L1/L2 entities (CAPS `capsGroup`, Cubit Genesis/Id attributes). (b) Classification as a first-class L5→L1 table: (dim, L1 id) for every mesh entity, (u,v)/t and projection distance for boundary vertices (Salome Node Positions; refine CAD-parametric). (c) Lineage/provenance in L10. Relations are persisted and *verified* against a (dim, id) join on load (Lasso's recompute becomes a consistency check, not the source of truth).
- **D2.3 L1 entities get persistent ids plus a lineage map** (old id → new ids with split/merge/delete reason) in L10 (ESP `_hist`, `_newSeqnum` precedent). Each L1 entity carries a modification counter or content hash (Salome `shapeTick` generalized per entity) so L5 classification can be checked for staleness.
- **D2.4 Mesh is a derived, reproducible cache.** Each L5 snapshot records the hash of its inputs (L0 shape, L1 topology, L2/L3 attributes, L4 sizing); partial invalidation follows the lineage map (only entities whose lineage changed).
- **D2.5 Virtual topology (composite/partition) is a reversible overlay** in L1 with explicit records (kind, members, parametrization); classification points at the virtual entity with a pointer to the underlying true entities for projection (CGM/Cubit).
- **D2.6 Derived flag sets** (Corners, Ridges, Required, non-manifold, locked) are computed from L1 plus L4 intent at export (MMG tags), never primary.
- **D2.7 B-rep persistence**: opaque versioned kernel blob plus a neutral export (STEP/BREP); the operation log (L10) plays the role of Cubit's embedded journal.
- **D2.8 Adapters.** meshb export is consumer-specific (MMG barycentric vs refine CAD-parametric + GmfByteFlow); a Cubit importer dispatches on file signature (legacy binary vs HDF5), and no HDF5 `.cub` reader is planned while the schema is undocumented; DAGMC/MOAB-style `GEOM_DIMENSION` + `GLOBAL_ID` tagged sets export for MC.
- **D2.9 Named group → integer tag map persisted** (CAPS-style) so exported blocks/sidesets are stable across regeneration; orphaned or unmatched groups are flagged by the validator (Salome's red marker), never silently degraded to standalone lists.

## 3. CSG, universes/lattices, instancing, reactor hierarchies

### Findings

- **OpenMC** (docs.openmc.org geometry.xml; usersguide geometry; openmc `src/dagmc.cpp`, `src/geometry.cpp`, `tests/regression_tests/dagmc/universes`): surfaces with `boundary ∈ {transmission, vacuum, reflective, periodic}` and types up to torus and 10-coefficient quadric; cells with exactly one of `material` or `fill`, material and temperature may be per-instance *lists* (distributed), `rotation`/`translation` only on filled cells; regions are boolean expressions over signed surface ids; rectangular lattices (`dimension`, `lower_left`, `pitch`, row-major `universes`, `outer`) and hex lattices (`n_rings`, `n_axial`, `orientation x|y`, `center`, `pitch`, ring-ordered `universes`, `outer`); leaving a lattice without `outer` is an error. Lattice elements are references, not copies. `dagmc_universe` loads `.h5m`; its `<cell>` overrides may not carry `region`, `fill`, `universe`, `translation`, `rotation` (manual `volume` discouraged; `material_overrides` deprecated). A DAGMC universe is an ordinary fill: "DAGMC universes can also be used to fill CSG cells or lattice cells", and a regression test tiles one DAGMC pin cell in a 2×2 lattice with `CellInstanceFilter`; nested DAGMC universes via PR #4119; 0.15.1 added per-instance materials in DAGMC universes (#3056).
- **MCNP6.3** (LA-UR-22-30006 §5.5.5; Cox LA-UR-11-01654): `U`/`FILL`/`LAT`; a reused universe "always has the same configuration with respect to geometry, materials and densities"; every lattice cell needs `FILL`; a `FILL` entry equal to the lattice's own universe = homogeneous element; `0` at level 0 = element does not exist (sparse lattice); every `FILL` entry, including each array element, may carry its own `TR` (per-element transforms, which OpenMC lacks); up to 20 nesting levels; `LAT=1` hexahedra / `LAT=2` hexagonal prisms with index directions fixed by surface order on the LAT cell; "a lattice must be the only thing in its universe"; a particle leaving a limited lattice is killed.
- **Serpent**: `lat` card; root universe 0; lattice types seen 1, 2, 3, 14 (finite 2D), 11–13 (3D), 6–8 and 15–17 (infinite), 4 (circular cluster), 9 (vertical stack); total count unverified (serpent.vtt.fi blocked) [S].
- **MOOSE CSG and RGMB** (framework `syntax/CSG`, `csg/CSGBase.md`, `csg/CSGLattice.md`; reactor module generator docs): `CSGLattice` separates the 2D universe map from attributes (pitch etc.) via `getAttributes/isValidIndex/isValidUniverseMap/clone/setUniverses/compareAttributes`; Cartesian and x-oriented hex only (y via rotation), row-column (i,j) indexing with (0,0) top-left; `CSGBase` has TRANSLATION/ROTATION/SCALE, 2D lattices only, surfaces plane/sphere/axis-aligned cylinder, `outer ∈ {void, material, universe}`. The same `PinMeshGenerator`/`AssemblyMeshGenerator`/`CoreMeshGenerator` objects implement `generateCSG`: `--csg-only` emits a hierarchical CSG JSON (pins as universes, assemblies as lattices with background outer, core lattice with `empty_univ`, materials `rgmb_region_<id>`, core wrapped in a bounding cylinder). So MOOSE already has the dual flat/hierarchical view (amends the critic's "flattened only").
- **MOOSE Reactor flat mesh**: hierarchy survives as extra element integers `pin_type_id`/`pin_id`, `assembly_type_id`/`assembly_id`, `plane_id`, `region_id`, `depletion_id`; reporting-id policies `cell` (unique per tile), `pattern` (per prototype), `manual`, with `exclude_id`; boundary ids by magic offsets (20000 + pin type, 2000 + assembly type, 30500 interface offsets, even inward / odd outward); `CoreMeshGenerator` warns when stitching may produce hanging nodes, `flexible_assembly_stitching` for non-matching boundaries, no mixing of heterogeneous and homogenized assemblies.
- **Griffin CMFD**: `CoarseMeshExtraElementIDGenerator` (reactor module, hence the framework 404): each fine element gets the id of the coarse element containing its centroid; `enforce_mesh_embedding` optional; `subdomains` restriction. GCMR VTB chain verified: `SubdomainExtraElementIDGenerator` (`material_id`, `equivalence_id`) → `GeneratedMeshGenerator` 10×10×20 → `CoarseMeshExtraElementIDGenerator` → `coarse_element_id`; `cmfd_acceleration = true`. HPMR-H2 instead builds a separate CMFD mesh with the Reactor module (three meshes). INL/EXT-21-64272: the CMFD mesh must be nested in the transport mesh and use libMesh element types (section 6).
- **CAD→CSG**: GEOUNED (GEOUNED-org/GEOUNED dev) recognizes Plane, Cylinder, Cone, Sphere, Torus and builds general quadrics for oblique cylinders/cones; no B-spline; void generation via nested user "enclosures"/"envelopes"; universes/transforms via CAD name tags `_fXX_`/`_tXX_`; writers for MCNP, OpenMC, Serpent, PHITS. McCad/SuperMC decomposition [S]. `joss.07710` is CAD_to_OpenMC (Knudsen & Chierici 2025), not DAGMC.
- **DAGMC conventions** (svalinn.github.io): groups `mat:<id|name>` (+`/rho:<density>` for MCNP), `mat:Vacuum`, `boundary:Reflecting` (default transmission), `temp:<K>`, a graveyard volume, an implicit complement for uncovered space (`_comp` suffix); `make_watertight`/`check_watertight`; Cubit `export dagmc ... faceting_tolerance`. Facet volume mismatch is a known problem (OpenMC discourse 3638). MIT thesis (Du 2024, "CSG vs. DAGMC Performance Tradeoffs in OpenMC") reports "positively on DAGMC" without numbers in the abstract.
- **Volume meshes as CSG leaves in MC codes** (missed by round 1): MCNP6 `EMBED` takes an Abaqus `.inp` mesh, maps element sets to pseudo-cells, places it via a fill cell with optional `TR`, reusable in several fill cells; EGU-filled cells cannot carry a lattice; `mcnpum` cached format since 6.2 (LA-UR-11-01654, LA-UR-25-26170, LA-UR-23-28515). Serpent `solid 1/3` takes OpenFOAM polyMesh (points/faces/owner/neighbour + materials file) with a background universe, convex cells required (serpent wiki) [S].
- **Hex addressing differs per code**: OpenMC ring-ordered with `orientation x|y`; MOOSE row-column (i,j), x-oriented; MCNP (i,j,k) fixed by surface order; Serpent separate X-type/Y-type lattice types.
- **MeshKit RGG**: CoreGen builds the core by copy/move/merge → flat mesh like MOOSE; Kitware RGG GUI discontinued (sigma.mcs.anl.gov).

### Decisions

- **D3.1 Add Prototype, Instance and Lattice to L1/L2.** `Prototype` = self-contained sub-complex (B-rep or CSG fragment, local frame, named boundary ports). `Instance` = prototype ref + rigid/affine transform + attribute overrides, where material/temperature overrides may be per-instance lists (OpenMC distributed materials). `Lattice` = index→prototype map kept separate from geometric attributes (pitch, origin/lower_left, orientation, n_rings, n_axial), with `outer` fill, sparse slots (MCNP `0`), "homogeneous slot" (MCNP fill = own universe), optional per-slot transform (MCNP per-element `TR`), nesting to arbitrary depth (MCNP allows 20). Canonical hex slot address is an axial/cube coordinate pair plus orientation flag; lossless converters to OpenMC ring order, MOOSE row-column, MCNP ijk and Serpent X/Y types are part of the schema's conformance tests.
- **D3.2 Instanced view of L5.** One mesh per prototype plus an instance table; a deterministic `flatten(depth)` expands to one global mesh with a stored map instance-path → entity-id range; `detect_repeats` (content hashes of prototype meshes) is an optimization for imported flat meshes, never authoritative. An instance that must differ (deformation, per-instance refinement, flexible stitching) is unshared explicitly.
- **D3.3 Typed hierarchical ids.** `*_type_id` (prototype) and `*_id` (instance), `region_id`, `material_id`, `plane_id`, user namespaces (`depletion_id`, `equivalence_id`) are derived from the instance path in the instanced view and materialized as per-cell integer fields only on flatten/export (Exodus extra element integers for Griffin). The three MOOSE policies (`cell`, `pattern`, `manual`) plus `exclude` are supported as export options.
- **D3.4 Coarse mesh slot.** A coarse (CMFD) mesh is an independent L5 mesh of the same L1 plus a fine→coarse integer map on fine cells (centroid containment default, embedding check optional, Griffin semantics); a separate equivalence namespace; coarse cells definable by hierarchy level (pin, assembly, axial plane) or arbitrary grid; stored per instance path when meshes are shared.
- **D3.5 Instance interfaces.** Non-conformal stitching between instances is an L7 Interface record keyed by instance-port pairs (prototype declares `outer_*` ports), never a geometry rewrite (MOOSE `flexible_assembly_stitching` becomes data).
- **D3.6 Numeric boundary-id conventions stay out of the model**; named hierarchical boundary sets plus a stable allocator; MOOSE/Exodus magic offsets generated only on export.
- **D3.7 CSG front end for L0** beside the B-rep: regions as boolean expressions over signed quadric surfaces (planes, cylinders, spheres, cones, tori, general quadric), universes, lattices, boundary types (vacuum/reflective/periodic with paired surfaces); exact import/export with OpenMC geometry.xml, MCNP U/FILL/LAT, Serpent. L1 computes the void/complement so the cellular complex covers the whole domain with an explicit void region and outer boundary (GEOUNED's enclosures become a derived step).
- **D3.8 Three MC export modes.** (a) Exact CSG hierarchy when the geometry is analytic. (b) DAGMC `.h5m` with the Svalinn conventions, watertight check and a volume-conservation report (B-rep vs facets); DAGMC leaves may be instanced through enclosing lattices (test-verified in OpenMC) or through rotated/translated filled cells (supported by the generic code path, not seen exercised in a test); overrides inside a `dagmc_universe` carry no transforms. (c) Volume mesh as a CSG leaf: MCNP6 `EMBED` via Abaqus `.inp` or 6.3 HDF5 UM (parts = regions, per-part conformity), Serpent `solid` via polyMesh (convexity validated).
- **D3.9 Importers**: MOOSE Reactor Exodus (extra element integers and boundary names) and MOOSE `--csg-only` JSON as a hierarchical source; provenance on instances records the generating pattern and prototype hashes.

## 4. High-order/DG formats: persisted pairings, orientation, polyhedral geometry rules

### Findings

- **Taxonomy of persisted non-conformity.** (a) Explicit coarse-side mortar record: HOPR. (b) Refinement provenance only, pairs rebuilt on load: MFEM NC mesh v1.0/1.1 (`elements` with ref_type and node ids, `vertex_parents` "vert_id p1 p2", v1.1 per-vertex scale, `root_state`; masters/slaves not written, rebuilt by `BuildFaceList`/`Update`) (mfem `mesh/ncmesh.cpp`); t8code (coarse mesh + SFC state). (c) Declaration only, overlap at run time: Nektar++ MOVEMENT (`ZONES` FIXED + `INTERFACES` LEFT/RIGHT by zone and boundary composite, edges "geometrically identical but topologically disconnected", "only static non-conformal interfaces are supported") (doc.nektar.info user-guidese14); OpenFOAM v12 `nonConformalCyclicPolyPatch`/`nonConformalMappedWall` (patch pair + transform, intersection demand-driven, `write()` emits only the dictionary); CGNS Abutting. (d) In-memory only: DUNE `Intersection`, dune-grid-glue. No surveyed format persists explicit sub-face overlap polygons with areas and normals.
- **HOPR `.h5`** (hopr.readthedocs.io meshformat): 1-based; `ElemInfo(6, nElems)` = type, zone, side range, node range, elements in SFC order (decomposition for free); `SideInfo` has five defined columns (the doc is inconsistent between 5 and 6): SideType (last digit = corner count, negative = mortar slave), GlobalSideID (negative = slave), nbElemID (0 = none; negative = mortar type 1/2/3 on the *big* side), `10*nbLocSide + Flip` (flip 0–4, symmetric), BCID (0 inner; periodic type 1 and inner type 100 keep neighbour data). Mortars only on purely hexahedral meshes with one octree level jump (2 or 4 neighbours); small mortar masters are owned by the big element; master sides have flip 0. High-order nodes are in tensor-product (i,j,k) order, which "does not correspond to the CGNS corner node ordering for pyramids and hexahedra"; only side numbering follows CGNS. The child-order convention for types 1–3 lives in HOPR/FLEXI source, not the doc.
- **PyFR `.pyfrm` v1** (pyfr.readthedocs.io file_format): `/codec` string table, `/eles/<type>` compound (`nodes` I64, `curved`, `faces` as `(cidx, off)` symmetric pairs; boundary = `bc/<name>`, off −1), `/mesh-uuid`, `/partitionings/<n>` (eles ranges, neighbours), `/periodic` unused by the solver, `/nodes` carries a `valency` field. Conforming only; no flip stored.
- **Nektar++ XML/HDF5** (user-guidese6): VERTEX → EDGE → FACE → ELEMENT → CURVED (side table keyed by edge/face id with `TYPE`, `NUMPOINTS`, points) → COMPOSITE (homogeneous `T[0-862]`, optional NAME; doubles as region and boundary set) → DOMAIN; base64+zlib sections.
- **Nek5000** (`core/reader_re2.f`): `.re2` header `#v004 nelgt ndim nelgv nBC` (only v004 uses list-directed read with nBC); 8-byte words for v002–v004; per element group id then x(8), y(8), z(8); curved sides as 5 reals + 1 char; BC records with 'P' periodic storing the partner as an integer; no connectivity in `.re2`, the `.co2` (`#v002 nelgt nelgv nv`, per element id + global vertex ids) is a separately versioned derived file.
- **t8code** (JOSS 10.21105/joss.06887): vertices, lines, quads, tris, hexes, tets, prisms *and pyramids* supported; cmesh tree connectivity with per-face orientation; `t8_forest_leaf_face_neighbors` returns multiple neighbours and dual faces; fine adjacency not persisted; face-to-face connectivity only, "node-to-node connectivity and hanging nodes resolution" are future work.
- **DUNE `Intersection`** (dune-project.org doxygen): `inside()`, `outside()` (if `neighbor()`), `boundary()`, `conforming()` (true iff the intersection equals the facet on both sides), `geometryInInside/Outside` (sub-patch in each reference element), `indexInInside/Outside`, `integrationOuterNormal(local)` per quadrature point; periodic = `neighbor() && boundary()` with a transformed ghost; several intersections per facet when non-matching. dune-grid-glue: all three mergers (Overlapping 1d–3d, Contact, Conforming) are built on the Gander–Japhet advancing-front algorithm; no serialization.
- **DOLFINx** (docs.fenicsproject.org main): on-demand `create_entities`/`create_connectivity(d0,d1)`; `MeshTags(dim, sorted indices, values int8/int32/int64/float64)`; mixed topology via `Topology.entity_types` and (dim, type-index) tuples, one cell array per type; `create_cell_permutations` → one u32 per cell (edge reflections, face rotation+reflection); `create_entity_permutations` → u8 per (cell, local entity); `create_facet_orientations` is for tdim = 2 (surface) meshes, possibly embedded in 3D; no non-conforming.
- **Basix / Intrepid2 orientation** (arXiv 2102.11901; `Intrepid2_OrientationDef.hpp`): reference orientation is "low-to-high global vertex id"; for a face, rotate the lowest-global vertex to local 0 and reflect by comparing its two neighbours; a quad mesh needs 3 reference cells, a hex mesh would need 501, hence per-entity base transformations (one matrix per edge, rotation and reflection per face; permutation-only for Lagrange). Intrepid2 encodes triangle `ort = flip*3 + rotation` (0..5), quad `flip*4 + rotation` (0..7), 1 bit per edge (≤12), 3 bits per face (≤6), axes tables tri `{{1,2},{2,0},{0,1}}`, quad `{{1,3},{2,0},{3,1},{0,2}}`.
- **OpenFOAM face/cell geometry** (cpp.openfoam.org v12 `faceTemplates.C`, `primitiveMeshFaceCentresAndAreas.C`, `primitiveMeshCellCentresAndVols.C`, `checkGeometry.C`): `face::areaAndCentre`: apex pAvg = vertex mean; `a_i = (p_{i+1}−p_i) × (pAvg−p_i)`; area vector = ½ Σ a_i; centre = (1/3) Σ an_i c_i / Σ an_i with `an_i = a_i·unit(ΣA)`, `c_i = p_i + p_{i+1} + pAvg`, fallback pAvg. v12 also ships `areaAndCentreStabilised` (blends the centroid toward pAvg by a round-off ratio): two face-centre rules in one code. Cell: cEst = mean of face centres, `pyr3Vol = A_f·(Cf − cEst)`, V = Σ pyr3Vol / 3, centre pyramid-weighted. checkMesh thresholds: face angle 10° (not 5°), flatness 0.8, `planarCosAngle` 1e-6, `minPyrVol = −small`, closedness 1e-6, aspect 1000.
- **OpenSn** (`framework/mesh/mesh/cell.cc`, `unpartitioned_mesh.cc`, `piecewise_linear_polyhedron_mapping.cc`): face centroid and cell centroid = arithmetic vertex means; face area = Σ sub-triangle areas (not |vector area|); normal = Σ subarea·unit(subnormal), normalized; cell volume = signed sum of side-tets {v0, face centroid, v1, cell centroid}, which is the exact divergence-theorem volume of the fan-triangulated polyhedron, V = (1/3) Σ_f A_f·pAvg_f. OpenFOAM's V = (1/3) Σ_f A_f·Cf differs by (1/3) Σ_f A_f·(Cf − pAvg_f), zero for planar faces, generally nonzero for warped ones; it is not the volume of any triangulated polyhedron.
- **Serpent** converts to tets after read, cells must be convex [S, 403]. **Fluent/STAR-CCM+** centroid rules undocumented (unverified); the Fluent UDF doc says interior face normals point c0→c1.

### Decisions

- **D4.1 (C) amended.** Use the four-bucket taxonomy; the claim is "no surveyed format persists sub-face overlap polygons with areas and normals". L7's overlap table is therefore novel and gets its own conformance vectors: warped quad, warped pentagon, 2:1 hex mortar (types 1/2/3), tri/quad mixed interface, with reference areas, normals and reciprocity sums.
- **D4.2 L7 pairing record** modelled on DUNE `Intersection` + grid-glue's remote intersection: `(cell_in, local_face_in, cell_out, local_face_out, conforming, orientation_code, sub-polygon in each side's face reference frame, area vector per sub-face)`; sub-face area *vectors* must sum to the parent face's area vector within the file's declared tolerance (scalar areas do not add on warped parents; scalar coverage is reported separately); for octree meshes the HOPR-style provenance (mortar type, child order, tree id, `xiMinMax`) is stored alongside and a flag says which is authoritative. The declared level (Nektar++/OpenFOAM/CGNS) is the Interface record of synthesis §4.
- **D4.3 Orientation convention** (see §7.3 for the unified statement): canonical rule = low-to-high global vertex id; per-cell packed permutation word (u32, DOLFINx layout; Intrepid2 bit widths) as a derived, hash-bound cache; HOPR's symmetric explicit flip is produced only by the HOPR exporter. Stable global vertex ids are a hard prerequisite (section 5).
- **D4.4 Mixed cell types** keyed by (dim, type-index) as in DOLFINx, with homogeneous sorted per-type blocks as a derived permutation (PyFR partition regions); boundary, interior and periodic faces share one encoding — face→(left, right) with right = none plus the face's classification — so no codec table is needed.
- **D4.5 Face-geometry rule ids, versioned per code release.** The schema carries `face_geometry_rule` and `cell_geometry_rule` identifiers. Registered: `smartmesh.fan_vertex_mean.v1` (default), `openfoam.areaAndCentre.v12`, `openfoam.areaAndCentreStabilised.v12`, `opensn.sum_tri_area.vertex_mean.<commit>`, `explicit_triangulation`. Each rule defines separately: apex, area, normal, centre. Default: area vector A = ½ Σ p_i × p_{i+1} (apex-independent, exact flux through any surface spanning the loop), n = A/|A|, area = |A|, apex = vertex mean (persisted per face when non-planar beyond tolerance), face centre = area-weighted centroid of the fan triangles; cell volume V = (1/3) Σ_f A_f·pAvg_f (the fan-triangulated polyhedron, bit-compatible with OpenSn's side-tet sum), cell centroid = centroid of that polyhedron. Export notes: OpenSn's scalar area Σ|a_i|/2 ≥ |A| for warped faces; OpenFOAM's face centre weights the fan triangles by *projected* areas (`an_i`), so it differs from the true-area fan centroid on warped faces (coincides on planar ones), and its volume differs by the term above.
- **D4.6 Validator metrics and flags**: planarity (max vertex distance to best-fit plane / face diameter) against a tolerance declared in the file; flatness |A| / Σ|a_i| (warn < 0.8); concave face angle (warn > 10°); every side-tet (edge, face apex, cell apex) positive (PWLD requirement); closedness Σ_f A_f = 0 within 1e-6 relative; per-cell `convex` (Serpent) and `all_faces_planar_within_tol` flags; a conformance report (`geometry_valid`, worst planarity, worst concavity).
- **D4.7 Curvature** as a sparse L6 side table keyed by entity id: (type, point family such as equispaced/GLL, degree, points) (Nektar++ CURVED; PyFR curved flag with node count setting order); Nek5000's 5-real codes accepted only as import hints.
- **D4.8 Authoritative vs derived**: connectivity caches, permutation words and sweep graphs carry the content hash of their source (PyFR `mesh-uuid`, Nek5000 `.co2`); region/boundary tags stored as (dim, sorted indices, values) with dtype ∈ {int8, int32, int64, float64} and optional names (Nektar++ composites, DOLFINx MeshTags).
- **D4.9 AMR forests**: persist coarse mesh + refinement state + an explicit face-pair table (dual faces, neighbour class) so consumers without the library can read it; note t8code gives no vertex/edge hanging-node constraints, which CFEM consumers need.

## 5. Stable identity, canonical ordering, partitioning

### Findings

- **libMesh** (`dof_object.h`, `replicated_mesh.C`, `distributed_mesh.C`, `mesh_communication.C`, `mesh_refinement.C`, `libmesh_core_features.m4`): dense renumberable `id` plus `unique_id`, the latter off by default (`--enable-unique-id` or `--enable-everything`; MOOSE enables it). Unique ids are a never-reused creation counter; `DistributedMesh` strides them in groups of n_procs+1 (slot p for rank p, last slot unpartitioned), so values depend on P, are non-dense and waste 1/(P+1) of the space; provisional ghost ids are overwritten by the owner's in `make_node_unique_ids_parallel_consistent`; refinement children get fresh ids, coarsening defers deletion to `contract()`, so re-refinement yields new ids; stitching merges id spaces by `unique_id_offset`.
- **MOAB** (`Internals.hpp`, `ParallelComm.*`, `Core.cpp`): handle = 4 type bits + index (60-bit id space on 64-bit builds); cross-rank identity is the `GLOBAL_ID` tag, a 32-bit `MB_TYPE_INTEGER` dense tag assigned on demand — the real 2^31 limit.
- **STK** (`EntityKey.hpp`): one u64, 8-bit rank (`RANK_SHIFT = 56`) + 56-bit id, id > 0, `INVALID = ~0`; sorting keys sorts by rank then id.
- **Omega_h** (`Omega_h_modify.cpp`, `Omega_h_globals.cpp`): `modify_globals` recomputes *every* global after adaptation (owner counts → `rescan_globals` = offset scan + MPI exscan → new numbering for kept and produced entities). Survivors get new dense numbers; results depend on rank count.
- **p4est / t8code** (`p4est.h`; `t8_forest_general.h`): identity is (tree, Morton key, level); global quadrant index is positional and partition-dependent; `p4est_checksum` is "independent of partition and mpisize", `p4est_checksum_partition` is not; the `revision` counter bumps on every effective refine/coarsen/partition/balance but is deliberately *not* saved ("that would make files different that come from different revisions but store the same mesh") and is reset on copy/load; `p4est_partition(allow_for_coarsening, weight_fn)` keeps sibling families together, and "other constant weightings may result in different uniform partitionings" (the cut depends on weight scale). t8code: global element id = first-local-leaf offset + local index (positional); same family-preserving partition shift.
- **Exodus / Nemesis** (`exodusII.h`; `nem_slice/elb_inp.C`; Exodus-Formats.md): `ex_put_id_map(exoid, map_type, map)` writes the one id map per entity type; `ex_put_num_map(exoid, map_type, map_id, map)` writes auxiliary numbered maps (different thing). Nemesis is folded into Exodus (`ne_` → `ex_`); `nem_slice` offers nodal (`-n`) and elemental (`-e`) decompositions; load-balance params (internal/border/external nodes, internal/border elements); node comm maps are (node id, proc) pairs, element comm maps are (elem, side, proc) triples.
- **OpenFOAM decomposition** (doc.openfoam.com 2606; cpp.openfoam.org dev `domainDecomposition.H`): `decomposeParDict` methods `none, manual, simple, hierarchical, kahip, metis, scotch, structured, multiLevel`; constraints `preserveBaffles, preserveFaceZones, preservePatches, singleProcessorFaceSets, refinementHistory, geometric`; `processorN/constant/polyMesh` with `procBoundaryAtoB` patches; `faceProcAddressing` stores the complete-mesh face index with the turning sign ("if the sign of the index is negative, the processor face is the reverse of the original face"), all indices incremented by 1 so face 0 can carry a sign; `cellProcAddressing`/`pointProcAddressing` are plain 0-based.
- **MED joints**: `/JNT/<mesh>/<joint>` with `MEDsubdomainJointCr` and `MEDsubdomainCorrespondenceWr(... nentity, correspondence)`; correspondence array layout not documented on the page (unverified).
- **Partitioner determinism** (METIS `options.c`, `util.c`; Scotch 7.0.12 INSTALL.txt; KaHIP README; `Zoltan2_AlgParMETIS.hpp`): METIS is deterministic by default on a given build (`METIS_OPTION_SEED` −1 maps to fixed seed 4321); Scotch 7 has `SCOTCH_DETERMINISTIC = NONE | FIXED_SEED (default) | FULL`, where FULL is "fully deterministic with any number of threads and the same number of MPI processes" at some speed cost; KaHIP takes a seed and ParHIP promises identical results for identical seeds; Zoltan2/ParMETIS imbalance tolerance 1.1 (≤1.0 reset to 1.01), `ADAPTIVE_REPART` needs ≥2 processes. Graph partitioners are same-build deterministic; their results still differ across P and versions. Geometric/SFC partitions are spec-defined cuts of a linear order and hence reproducible across implementations.
- **Hash-derived ids fail the birthday bound** (computed, λ = n²/2^(bits+1)): 56 bits at 1e9 entities → ≈6.9 expected colliding pairs (P ≥ 1 ≈ 0.999), at 1e8 → 7%; 64 bits at 1e9 → 2.7%, at 1e10 → 93%; only 128 bits is negligible. A collision check with rehash is a global operation that makes ids order-dependent.

### Decisions

- **D5.1 Two id roles, both explicit.** (i) *Stable `EntityId`*: u64 packed STK-style, 8-bit kind (vertex, edge, face, cell, plus L1/L2 kinds), 56-bit serial, serial 0 invalid, never reused, never renumbered. (ii) *Dense index*: a derived per-snapshot column (0..N−1 in canonical order), rebuilt freely. Serials are allocated per operation by a *data-defined* canonical scan: the operation's products are ordered by (primary-parent stable id, template ordinal), sorted globally, and numbered from the operation's base (previous maximum + 1). The primary parent of a product is the lowest-dimensional pre-existing entity whose closure contains it (the classification rule applied to lineage), and the ordinal is the product's index in the operation's template; both are functions of the data, so every rank and thread derives the same key. Hence ids are identical for 1 vs N threads and 1 vs P ranks (CLAUDE.md determinism rule). The lineage triple (parents, op id, ordinal) is stored in L10. A sort-free variant is available where the sort cost matters: serial = op_base + (parent's prior dense index × K) + ordinal, with K the template's maximum products per parent; it leaves gaps but needs no global sort. Rejected: hash-derived ids (birthday bound), rank-strided counters (libMesh), post-adapt renumbering (Omega_h), random UUIDs. The 128-bit structured alternative is kept as the fallback if neither allocation variant is acceptable at scale (open question §8.1).
- **D5.2 Survivors keep ids.** Refinement does not delete the parent; it marks it inactive (SGC active flag, round-1 §3), so coarsening back reactivates the same stable id and children are retired. Repartitioning changes no id. Merging two meshes needs no offsets because ids are namespaced by kind and by origin object.
- **D5.3 Hierarchical key** for tree-refined regions: (root cell stable id, level, interleaved Morton bits) exposed as an additional derived key so ancestor tests and partition-independent hashing are computable (p4est/t8code); parent/child links in L10.
- **D5.4 Canonical order**: files are written sorted by (kind, stable id); face→vertex loops rotated to start at the smallest vertex id, direction fixed by the orientation rule (§7.3); `left` = lower stable cell id; cell→face lists sorted by face id with the sign column parallel. SFC/kd-tree locality orders are stored as separate permutations, never applied to identity.
- **D5.5 Checksums**: partition-independent (over sorted (id, connectivity ids, classification)) and partition-dependent (adds owner and halo tables), as in p4est; Merkle per layer and per kind-chunk so diffs and CI compare hashes; float coordinates go in a separate geometry hash with a declared quantization policy; the revision counter lives in L10 provenance, never in the identity-bearing payload (p4est's reason).
- **D5.6 L9 is a separate layer**: `entity_id → owner_part`, per-part ghost/halo lists, neighbour comm lists keyed by stable ids; provenance record {partitioner, version, seed or determinism mode, P, weight array hash (not only the rule, since scale matters), graph hash, imbalance tolerance}; the assignment array is always stored, never recomputed.
- **D5.7 Default partitioner**: weighted SFC/RCB with family preservation (cross-implementation reproducible); METIS/Scotch/KaHIP offered with fixed seed, `SCOTCH_DETERMINISTIC=FULL` for golden outputs. The dual graph comes from face→(left, right) with cell weights (groups × angles × DOFs, or MC particle density) and edge weights (face DOFs), *including L7 overlap edges*; keep-together constraints map from L2 (assemblies, instances, interfaces, baffles).
- **D5.8 Exporters**: Exodus via `ex_put_id_map` plus netCDF-4 non-classic with `EX_ALL_INT64_DB`; Nemesis elemental decomposition with (elem, side, proc) comm maps; OpenFOAM `processorN` with signed `faceProcAddressing`; MED joints. Round-trip tests compare the partition-independent checksum.
- **D5.9 Acceptance matrix**: identical ids and partition-independent checksum for 1, 2, 7 ranks and 1 vs N threads; refine then coarsen restores survivors' ids; repartition changes no id; merge needs no offsets.

## 6. Transport consumers: inputs and the minimal DG-SN/PWLD subset

### Findings

- **OpenSn** (Open-Sn/opensn: `cell.h`, `from_file_mesh_generator.cc`, `vtk_io.cc`, `unpartitioned_mesh.cc`, `aah.cc`, `cbc.cc`, `lbs_groupset.cc`): cell types SLAB…POLYHEDRON with PWLD on arbitrary polyhedra; readers `.obj`, `.msh` (2.2/4.1), `.e`, `.vtu/.pvtu`, `.case`, OpenFOAM; the unpartitioned mesh is vertices + per-cell (centroid, block id, vertex ids, faces as vertex loops). Face adjacency is derived by *exact vertex-set identity*; boundary ids are assigned by matching (d−1)-dimensional boundary cells (Exodus sidesets, or `.vtu` lower-dimensional cells carrying the id field) to volume faces by exact vertex set; interior faces that fail the match silently become boundary faces (count logged only at verbose level). Normals, areas, centroids and volumes are recomputed. Sweeps: per-direction SPDS, `mu = Ω·n` against `FACE_ORIENTATION_TOLERANCE`, edge weight `mu·area`, Boost graph, feedback arc set with lagged fluxes when `allow_cycles` (default **true**), topological sort then levelized order; inter-rank `location_successors/dependencies` per direction.
- **Teton / UMT** (LLNL/UMT `TetonBlueprint.cc`, `TetonConduitInterface.*`, `TetonInterface.hh`, `snac/*.F90`, `setOppositeFace.F90`): upstream corner balance; input is Conduit Blueprint with shapes tet/wedge/pyramid/hex/polyhedral/polygonal, topologies `main` and `boundary`, polyhedra via `o2mrelation`; Teton builds its own corner mesh (`main_corner`, `corner_adjset`) and calls `teton_setoppositeface`; BCs via `boundary_conditions/*` (`num_reflecting/vacuum/source/comm`, `corner_face_ids`, `neighbor_ids`) and a `boundary_attribute` field; zonal fields on `main`; partitions itself with ParMETIS. Cycles: Tarjan SCC (`sccSearchZone/Corner`) and `cycleBreakerZone/Corner` ("selecting a zone that will use some old (previous iterate) incident fluxes"), per-angle hyperplane levelization (`SweepUCBxyz`). AMR: `teton_setzone` says "Hanging nodes are treated as a zone defining node by Teton"; `setOppositeFace.F90` requires exactly one opposite zone/face per zone face (fatal "Inconsistent definition of opposite zone/face"), so a coarse zone next to N fine zones must be presented as N zone faces. AMR TODOs exist only for radiation-force `corner_to_vertex` and surface edits in the Conduit path.
- **Draco / Capsaicin** (lanl/Draco): RTT ASCII format (Header, Dims, Flags, NodeData, CellDefs with `sides`/`ordered_sides`, Cells, CellData, side/node flags); `Draco_Mesh` from cell→node lists; `CAMR_Mesh`/`CAMR_Layout` (2023) is a native 1-to-N fixed-ratio hanging-face layout ("cells may have up to N cell neighbors across a face") with a VTK writer; Draco is Capsaicin's support library (ChangeLog moved the parser package from Capsaicin); whether Capsaicin reads RTT/X3D or uses CAMR is inference. Tycho2 is tets only.
- **Attila / Attila4MC** (OSTI 426394; LA-UR-15-22871; LA-UR-23-28515; LA-UR-22-30643): tetrahedral SN with linear-discontinuous FE and DSA; Attila4MC meshes CAD with the Simmetrix mesher (first-order tets) and prepares both Attila and MCNP6 UM inputs from one model; Cubit is an alternative source for MCNP UM Abaqus files; no Cubit → Attila SN route found.
- **PROTEUS-SN**: continuous Galerkin, conformal, inputs ascii/nemesh/pntmesh/bgpmesh, Exodus from Cubit converted; element types unverified (OSTI and anl.gov blocked).
- **Griffin DFEM-SN** (INL/EXT-21-64272, OSTI 1822446; INL/RPT-22-69391): matrix-free sweeper that handles "re-entering element faces, cyclic dependencies among elements, reflecting boundaries" by lagging angular fluxes; parallel cycle detection is future work; test meshes mix HEX8 and PRISM6 blocks with first- or second-order Lagrange; the CMFD coarse mesh must be nested in the transport mesh and use libMesh element types (no 2D hexagon). Neither report mentions hanging nodes, AMR or polyhedra. (The "overlay a regular grid, assign by centroid" chain is verified only in the GCMR VTB example, section 3.)
- **PDT** (arXiv 1906.02950; Ghaddar M&C 2017): PWLD on semi-structured grids; a dependency-respecting sweep on a fully unstructured grid "would require a different angleset for each quadrature direction"; lagging "can increase iteration counts"; polygonal-prism grids with product quadratures share one ordering per azimuth; PDT's unstructured meshes are 2D Triangle meshes extruded in z with degenerate polygons at subset boundaries.
- **MCNP6 unstructured mesh** (LA-UR-22-30643, LA-UR-23-28515, LA-UR-21-26436, LA-UR-15-22871): C3D4/C3D6/C3D8 and quadratic C3D10/C3D15/C3D20 (+SC8), mixable; Abaqus `.inp` with `*Part/*Instance/*Assembly`, `*Elset` names encoding material and statistic set, pseudo-cells via `EMBED` (`MESHGEO`, `MGEOIN`, `BACKGROUND`, `MATCELL`); 6.3 adds an HDF5 UM format with Abaqus→HDF5 conversion; conformity is per part, MCNP tracks "through overlaps & gaps"; quadratic elements ~10× slower; `um_pre_op` checks twisted elements.
- **Shift**: GG (via Hyas) and ORANGE CSG plus DAGMC tessellated CAD (OSTI 1985383); Cartesian/hexagonal mesh tallies; no evidence of unstructured volume-mesh tracking.
- **Minimal information every verified SN consumer needs**: vertex coordinates; per cell an ordered face list, each face an ordered vertex loop (polyhedron definition); face adjacency derivable or explicit; a material/block id per cell; boundary-face tags with a name map; conformal faces (same vertex set on both sides); partition or the ability to partition. Everything else (normals, areas, centroids, volumes, sweep graphs, corners, ghosts) is recomputed by OpenSn and Teton.

### Decisions

- **D6.1 Transport profile = the minimal subset** (§7.7), exported as plain tables: coordinates, cell→face CSR with sign, face→vertex CSR, face→(left, right), material region per cell, named boundary sets over faces, BC type per set, plus the optional derived geometry cache and partition layer.
- **D6.2 Conformalize semantics (amends ir.md §3 and synthesis §4 E).** The "degenerate to polyhedra" export replaces each coarse face by the set of fine faces it abuts (the coarse polyhedron gains faces; each new face carries the fine cell's vertex set). In 2D this coincides with "the hanging node becomes a polygon vertex"; in 3D inserting hanging vertices into the coarse loop produces a single face that matches no fine face and is rejected by Teton's one-opposite-face rule and OpenSn's vertex-set matching. The PDT/PWLD-internal view (extra vertices on a polygon) is valid in 2D and, under extrusion, becomes face replacement automatically (each split edge extrudes to a separate quad face). The validator rule for OpenSn/Teton targets: every interior face must be matched by exact vertex set; the OpenSn exporter refuses or conformalizes non-conformal input instead of letting OpenSn mis-tag it as boundary.
- **D6.3 Precomputed face/cell geometry** is a derived cache under the rule id of D4.5; consumers that recompute (OpenSn, Teton) lose nothing, consumers that read it get bit-identical areas, normals and volumes on both sides of every face.
- **D6.4 Sweep graphs are derived, not primary**: cached per (mesh hash, quadrature hash, orientation tolerance) with upwind/downwind classification, `mu·area` weights, feedback arc set and levelized order; a per-direction cycle report; per-cell flags for cycle-prone geometry (warped or curved faces, nearly parallel faces). Both OpenSn and Teton lag cycle-breaking edges, so the cache format follows that pattern.
- **D6.5 Partition layer optional on export**; Teton partitions itself, OpenSn splits from an unpartitioned mesh. Locality reorderings (Teton kd-tree) are stored permutations (D5.4).
- **D6.6 Conduit Blueprint writer** is the Teton path: polyhedral topology with `o2mrelation`, a `boundary` topology with `boundary_attribute`, adjsets, zonal fields; Teton's corner mesh is its own business.
- **D6.7 Extruded/prismatic structure is first-class**: a mesh records (base 2D mesh id, layer index) when it is an extrusion, so PDT-style per-azimuth orderings, MOOSE `plane_id` and Griffin PRISM6 blocks are recoverable without detection.
- **D6.8 Exporters for transport**: Exodus (HEX8/PRISM6 for Griffin today; polyhedra are not a Griffin target until verified); `.vtu` VTK_POLYHEDRON, Gmsh 4.1 and OpenFOAM polyMesh for OpenSn; Abaqus `.inp` and MCNP 6.3 HDF5 UM with parts = regions and per-part conformity, linear elements by default; OpenFOAM polyMesh for Serpent `solid` with the convexity flag enforced; DAGMC `.h5m` for OpenMC/Shift surface geometry; meshb per consumer (D2.8).

## 7. Consolidated schema decisions

### 7.1 Physical backend
- Abstract storage model (groups, typed N-D arrays, attributes, checksums); profiles: mmap container (solver, per part), Zarr v3 via `zarrs` (archive/cloud, sharded, plain-Zarr readable, manifest-based snapshots), HDF5 via `hdf5-metno` (MPI-IO, interop, HDF5 exporters), JSON (golden tests). ADIOS2 deferred; Icechunk optional later.
- Part-aligned shards/chunks, one writer each; per-part count table; 1-D arrays, regular chunks; chunk 1–4 MiB, shard 64–256 MiB pending D1.10.
- Lossless topology/geometry: blosc(zstd, shuffle) or zstd + crc32c in Zarr; shuffle + deflate (mandatory, availability checked) in HDF5; no delta codec; part-local u32 indices as the compression lever; lossy only on fields by attribute.
- Root attributes: format version triple, per-layer schema version, required/optional layer bitmask; HDF5 libver bounds pinned.
- Self-run 1e9-cell benchmark before freezing codecs and chunk sizes.

### 7.2 Ids and canonical order
- `EntityId` u64 = 8-bit kind + 56-bit serial; never reused; dense index is a derived column; serials assigned per operation by a data-defined canonical sort of (primary parent, ordinal); lineage in L10; 128-bit structured ids are the fallback.
- Parents retained inactive on refinement; coarsening reactivates; repartition touches no id.
- On-disk ids u64; optional part-local u32 profile; CSR offsets u64.
- Canonical file order (kind, id); loops start at the smallest vertex id; locality orders are permutations.
- Two checksums (partition-independent / -dependent), Merkle per layer, geometry hash with quantization policy; revision only in L10.
- Partition layer separate; assignment array and partitioner provenance (incl. weight-array hash) stored; SFC/RCB default; graph partitioners with fixed seed / Scotch FULL.

### 7.3 Orientation (unified)
- Face→vertex loop winding defines the face normal (right-hand rule). `left` = the lower stable cell id; the normal points from `left` into `right`. Boundary face: `right` = none, normal outward, boundary set via the face's classification. This makes OpenFOAM `owner`/`neighbour` export a renumbering with no flips, matches CGNS `ParentElements` order, and gives the CGNS NFACE sign directly: cell→face sign is + for `left` (outward), − for `right`.
- FE orientation: canonical reference = low-to-high global vertex id (Basix/Intrepid2); a per-cell packed permutation word (u32, DOLFINx layout, Intrepid2 widths) is a hash-bound derived cache; explicit symmetric flips (HOPR) only in that exporter.
- Interface sub-faces carry their own area vector oriented from `left` to `right` and their parametric coordinates in both parent faces.

### 7.4 Instancing and hierarchy
- `Prototype`, `Instance` (transform + per-instance override lists), `Lattice` (index map separate from attributes; `outer`; sparse and homogeneous slots; per-slot transforms; unbounded nesting) in L1/L2; canonical axial hex coordinates with lossless converters to OpenMC/MOOSE/MCNP/Serpent addressing.
- L5 instanced view (one mesh per prototype + instance table) and deterministic `flatten(depth)` with instance-path → id-range map; type-id vs instance-id derived from the path, materialized only on export.
- Coarse-mesh slot: an independent L5 mesh of the same L1 with a fine→coarse map and an equivalence namespace.
- CSG front end in L0 (signed quadrics incl. torus/general quadric, universes, lattices, boundary types); L1 computes void coverage.
- Extrusion structure (base mesh, layer) first-class.

### 7.5 Polyhedral geometry rules
- `face_geometry_rule` / `cell_geometry_rule` ids, versioned per code release; default `smartmesh.fan_vertex_mean.v1`: A = ½ Σ p_i × p_{i+1}, n = A/|A|, area |A|, apex = vertex mean persisted for non-planar faces, centre = fan-triangle centroid; V = (1/3) Σ A_f·pAvg_f (equals OpenSn's side-tet sum), centroid of the fan polyhedron.
- Validator: planarity vs declared tolerance; flatness 0.8; concave angle 10°; positive side-tets; closedness 1e-6; per-cell `convex`, `all_faces_planar_within_tol`; conformance report.
- Conformalize = coarse face replaced by fine faces (3D); loop insertion only in 2D.
- Curvature as a sparse side table (type, point family, degree, points).

### 7.6 Non-conformal (amended C)
- Claim: no surveyed format persists sub-face overlap polygons with areas and normals; HOPR = coarse-side mortar type, MFEM NC/t8code = provenance, Nektar++/OpenFOAM NCC/CGNS = declaration, DUNE = in-memory.
- L7 record = DUNE-style (cell_in, face_in, cell_out, face_out, conforming, orientation code, sub-polygon in both frames, area vector) + optional mortar provenance + authoritative flag; sub-face sums checked; conformance vectors required.
- Instance interfaces keyed by instance-port pairs.

### 7.7 Transport-consumer minimal subset (what the in-house code reads first)
1. L6 coordinates (f64 SoA; units declared).
2. L5 `cell_to_face_offsets` (u64), `cell_to_face_ids` with sign, `face_to_vertex_offsets`, `face_to_vertex_ids`, `face_left`, `face_right` (none sentinel), optional cell shape tag.
3. L2 material region per cell (exact partition), named boundary sets over faces, Interface records if any.
4. L3 BC type per boundary set (vacuum, reflective, periodic + partner, incident source, albedo, white).
5. Geometry rule id, per-face apex for non-planar faces, per-cell `convex`/planar flags; derived cache (face area vector, centroid; cell volume, centroid) under the rule id.
6. Optional: L9 parts and ghost lists; L7 overlap tables; L10 content hashes (mesh, geometry, partition) that key the sweep-graph cache.
7. Extrusion record when applicable.
Sweep graphs, corners and locality permutations are derived caches, never required.

### 7.8 Export adapters implied this round
MOOSE Reactor Exodus importer and `--csg-only` JSON importer; Exodus writer with id maps and 64-bit mode; Nemesis elemental; OpenFOAM `processorN`; Conduit Blueprint polyhedral for Teton; `.vtu`/Gmsh 4.1/polyMesh for OpenSn; Abaqus `.inp` + HDF5 UM for MCNP6 `EMBED`; polyMesh for Serpent `solid`; DAGMC `.h5m` with Svalinn conventions; OpenMC geometry.xml / MCNP U-FILL-LAT exact CSG; HOPR with explicit flips; meshb per consumer; Cubit import by signature only.

## 8. Open questions

### 8.1 Decisions for the user
- Which transport code is the first consumer in practice: the in-house DG-SN/PWLD reading the IR, Griffin via Exodus (HEX8/PRISM6 only until polyhedra and hanging nodes are verified), or an MC code? "Lupine" still unidentified.
- MC path: DAGMC surface geometry, MCNP6 UM/`EMBED`, or Serpent `solid`? This fixes which export (surface vs volume mesh as CSG leaf) is built first.
- Day-one backend order: Zarr-first (pure Rust, cloud) as recommended, or HDF5-first because the consumer's tooling is HDF5/Exodus-centric?
- Is losing plain-Zarr readability acceptable in exchange for Icechunk's transactions (D1.6 says no)?
- Id scheme: accept the per-operation global canonical sort (64-bit serials), or prefer 128-bit structured ids with a dense side table to avoid the sort?
- Should the transport consumer read precomputed face/cell geometry and sweep-graph caches, or recompute (which decides whether the caches are shipped in the transport profile)?
- Canonical hex addressing: axial/cube coordinates as proposed, or one existing convention (OpenMC ring order) as the stored form?
- Is extruded/prismatic structure a first-class requirement (PDT-style sweeps, MOOSE `plane_id`), or a derived property?
